# src/pages — Routing Layer

## Intent
Every URL the EvoX Portal serves is defined here as an Astro page. Pages are
deliberately thin: they fetch content collections (`astro:content`), load
locale strings, and delegate markup to `src/layouts/Layout.astro` and
`src/components/pages/`. All routing logic (`getStaticPaths`, pagination,
locale selection) lives in this directory.

## Locale Routing Conventions (READ FIRST)
`astro.config.mjs` sets `i18n.defaultLocale = "en"` and
`prefixDefaultLocale: false`, which is why there are TWO mirrored trees:

- **Non-prefixed tree (top level):** serves English URLs with no prefix
  (`/docs/...`, `/news/...`). These pages hardcode
  `const locale: Locale = defaultLocale`.
- **`[locale]/` tree:** mirrors every page for the other 12 locales
  (`/ja/docs/...`, `/zh-cn/news/...`, ...). `getStaticPaths` always uses
  `locales.filter((l) => l !== defaultLocale)` — the default locale is NEVER
  generated under `[locale]/` (there is no `/en/...` URL).

The two trees are independent files: **any edit to a non-prefixed page must be
mirrored by hand in its `[locale]/` counterpart** (there the imports are
`../../../`, and the locale comes from `Astro.params.locale`).

Cross-links between pages must go through `getLocalizedUrl(path, locale)` from
`src/i18n/utils.ts` — it strips an existing locale prefix and re-adds the
target one (default locale → no prefix). `getLocaleFromUrl` parses the first
URL segment to detect the locale.

## API Surface (page groups)
| Route | File | Behavior |
|---|---|---|
| `/` | `index.astro` | Home; thin wrapper around `components/pages/HomeContent.astro` |
| `/{locale}/` | `[locale]/index.astro` | Home for each non-default locale; passes `locale` prop to HomeContent |
| `/404` | `404.astro` | Static 404; English-only, `noSEO`, `localePath="/"`, no locale mirror |
| `/docs` | `docs/index.astro` | Docs listing grouped by `data.section` (labels via `docs.section.<key>`), sorted by `data.order` |
| `/docs/<slug>` | `docs/[...slug].astro` | Doc article; paths via `getLocalizedArticles(allDocs, defaultLocale)` |
| `/news`, `/news/2`, ... | `news/[...page].astro` | Paginated news listing (10/page, pubDate desc). NO separate `index.astro` — paginate emits the base page itself |
| `/news/<slug>` | `news/[...slug].astro` | News article via `getLocalizedNews` |
| `/releases`, `/releases/2`, ... | `releases/[...page].astro` | Same pagination pattern (uses `getLocalizedArticles`) |
| `/releases/<slug>` | `releases/[...slug].astro` | Release article |
| `/tutorials` | `tutorials/index.astro` | Numbered tutorial listing, sorted by `data.order` |
| `/tutorials/<slug>` | `tutorials/[...slug].astro` | Tutorial article via `getLocalizedArticles` |
| `/community` | `community/index.astro` | Community page (self-contained, uses Layout) |
| `/runtime` | `runtime/index.astro` | Thin wrapper around `components/pages/RuntimeContent.astro` |
| `/libs` | `libs.astro` | Libs page. ⚠️ Top-level page is a FILE (`libs.astro`), not `libs/index.astro`; its mirror is `[locale]/libs/index.astro` |

All `[locale]/` pages mirror the above (except 404) using
`getStaticPaths()` → `{ params: { locale } }`, with `flatMap` over locales for
slug/paginated routes to generate per-locale combinations.

## Pagination Conventions
- `[...page].astro` routes use Astro's `paginate()` with `pageSize: 10`.
- Articles are sorted newest-first by `data.pubDate` before paginating.
- Page 1 is served at the base path (`/news`, `/ja/news`); later pages at
  `/news/2`, `/ja/news/2`, etc.
- Prev/next links use `page.url.prev` / `page.url.next` from `PaginatedPage`
  (`src/types/pagination.ts`).
- Do NOT add `news/index.astro` or `releases/index.astro` — it would collide
  with the base page generated by paginate.

## Known Gotchas
- **Duplicate-tree drift:** non-prefixed and `[locale]/` pages are copy-pasted
  twins. Any change (styling, copy, i18n keys) must be applied to both.
- Slug pages strip the leading `# H1` from the markdown body before `render()`
  (`bodyWithoutH1`) because the Layout already renders the title as `<h1>`.
- `news` uses `getLocalizedNews(...)`; `releases`/`docs`/`tutorials` use
  `getLocalizedArticles(...)`. Both return entries whose `slug` is already the
  locale-specific slug used in `params`.
- Locale is read from `Astro.params.locale` in `[locale]` pages (typed `Locale`);
  pages without a locale param hardcode `defaultLocale`.
- The site uses URLs with NO trailing slash (links built via `getLocalizedUrl`);
  don't add trailing slashes to new links.
- The 404 page is English-only with hardcoded copy — other locales fall back to it.

## Routing Table
- `[locale]/` → Localized mirror tree for all 12 non-default locales (see `../src-pages-locale/CONTEXT.md`)
- `../i18n/utils.ts` → Locale helpers (`getLocalizedUrl`, `getLocaleFromUrl`, `getLocalizedArticles`, `getLocalizedNews`, `loadTranslations`, `t`, `locales`, `defaultLocale`) — sibling, read-only, escalate writes to `../`
- `../content.config.ts` → Content collections (news, releases, tutorials, docs, libs) consumed by `getStaticPaths` — sibling, read-only
- `../types/pagination.ts` → `PaginateFunction` / `PaginatedPage` types — sibling, read-only
- `../layouts/Layout.astro` → Shared shell every page wraps (title, locale, SEO) — sibling, read-only
- `../components/pages/` → `HomeContent.astro`, `RuntimeContent.astro` (home/runtime pages are thin wrappers) — sibling, read-only, escalate writes to `../`
