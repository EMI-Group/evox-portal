智能体树描述谁正在工作，项目历史还需要解释工作结束后留下了什么。2026 年 9 月 26 日发布的 Genesis 0.13.4，继续完善 0.13.2 引入的提交历史视图，以及 0.13.3 加入的任务持久引用。这些变化将临时活动与可检查的软件版本连接起来。

![智能体活动保存在项目历史记录中](./durable-agent-history.webp)

## 从在线智能体到持久任务引用

任务级历史 API 解析持久引用与任务的基准提交，让时间视图保留已回收智能体产生的提交。此前的 API 可跨仓库查询提交范围与引用；任务层则补充持续跟踪某项开发工作所需的上下文。 [v0.13.2](https://github.com/EMI-Group/genesis/releases/tag/v0.13.2) · [v0.13.3](https://github.com/EMI-Group/genesis/releases/tag/v0.13.3)

当智能体委派模块工作并随后结束时，其贡献仍可能需要审查。Git 历史为变更提供持久身份，任务视图帮助用户在整体工作中找到它。一次智能体执行结束，不必抹去任务与成果代码之间的关联。

## 展示贡献之间的关系

0.13.4 按智能体泳道组织提交，让同一子树相邻，并显示委派与合并回流关系。没有归属的提交使用中性泳道。选择、悬停联动与键盘访问支持查看；部分仓库读取失败也不再导致整张图消失。 [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

历史达到 100 次提交的显示上限时，视图会标记截断。追查更早的修改时，可以用任务的基准与末端引用检查相应 Git 范围。

## 沿着贡献追踪到集成

从一个任务出发，找到基准提交，再沿智能体泳道追踪委派与合并回流。在决定保留哪些成果时，查看对应差异和测试结果。涉及多个代码库的修改，可以接着进入[多仓库审查](/zh-cn/news/genesis-multi-repository)完成集成。
