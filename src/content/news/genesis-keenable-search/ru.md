Исследовательская задача Agent может остановиться до первого запроса, если веб-поиск требует дополнительных учётных данных. PR #174 Genesis, включённый в `main` 19 ноября 2026 года, добавляет **Keenable** как выбираемого провайдера с публичным endpoint без настроенного API-ключа. Установки сохраняют прежнее поведение по умолчанию. [Принятый адаптер][pr]

![Открытый вход в библиотеку ведёт к документам с указанием источников](./cover.webp)

*Концептуальная иллюстрация: необязательный публичный путь к веб-исследованию.*

## Явно включить публичный путь

В `[tools.search]` задайте `enabled = true` и `provider = "keenable"`. Без ключа адаптер отправляет запрос и лимит результатов на публичный endpoint, добавляет `X-Keenable-Title: Genesis` и не передаёт `X-API-Key`. Добавление `KEENABLE_API_KEY` в хранилище учётных данных переключает на доступ с ключом. [Формирование запросов][adapter]

Реализация меняет оба необходимых условия: выбранный провайдер без обязательного ключа может включить поисковый инструмент Agent, а выполнение больше не отклоняет его только из-за отсутствия ключа. Провайдеры, которым нужны учётные данные, сохраняют прежние проверки.

## Читать результаты с учётом ограничений

При сборе документальных источников это убирает один шаг настройки. Адаптер переносит заголовки, URL и `snippet` в существующий формат результатов. Он учитывает `max_results`; аналога `search_depth` у Keenable нет, поэтому параметр игнорируется. [Преобразование ответа][adapter]

Публичный доступ ограничивается по IP. PR содержит тесты формирования запросов, разбора и включения инструмента, включая имитацию выполнения, но не сообщает о настоящем вызове API Keenable. После включения сделайте небольшой запрос с реального хоста выполнения и проверьте источники и ошибки службы, прежде чем опираться на него в большом исследовании. [Записанные проверки][pr]
