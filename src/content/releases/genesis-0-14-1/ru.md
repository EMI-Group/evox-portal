Выбирая модель, Вы также выбираете оплачивающий аккаунт, его учётные данные и параметры рассуждения для задачи. **Genesis 0.14.1 официально выпущен 8 ноября 2026 года** и согласованно передаёт эту идентичность через Settings, Projects, Assistant, планировщик и среду выполнения. Версия также объединяет удалённую работу на базе headless-сервера и расширяет контролируемую диагностику во время выполнения. [Полные примечания к выпуску][release]

## Настроить аккаунт, точно выбрать модель для задачи

Provider profile хранит авторизацию, endpoint, параллелизм и расписания. Вложенный список описывает доступные модели и индивидуальные настройки генерации и рассуждения. В задачу передаётся идентичность без секретов: ID профиля, ID модели и необязательный уровень рассуждения. Конкретный выбор закрепляет эту комбинацию для последующего выполнения; **Auto** оставляет выбор настроенным правилам.

Например, две модели рабочего аккаунта делят его слоты параллельного выполнения и задержки после ограничения запросов. Добавление модели не создаёт отдельный пул квоты. Личный аккаунт может иметь другие данные и расписание. Для разных API keys нужны не только разные ID профилей, но и разные имена учётных данных. [Настройка и правила выбора][profiles]

Каждой выбираемой модели нужна запись в `[[llm.providers.models]]`; одного `default_model` недостаточно. Уровень рассуждения по умолчанию задаётся отдельно от списка поддерживаемых уровней. Если список не пуст, но значение по умолчанию не определено, панель выбирает первый уровень; вызов внутреннего API без уровня может вообще не передавать параметр. После смены профиля проверьте модель и уровень.

Выпуск исправляет потерю явного выбора между задачей, агентом и системой, резервные пулы планировщика и неполные снимки настроек, вызывавшие `:model_spec_schema_unavailable`. Архивные настройки теперь безопасны для JSON, а секреты скрываются. Это важно и для новых задач, и для повторного использования сохранённых настроек.

## Вход по подписке следует настройкам аккаунта

Поддерживаемые профили получили OAuth/авторизацию по подписке и отдельный статус входа. Genesis импортирует файлы входа CLI поставщиков в управляемый файл для ReqLLM. `openai_codex` поддерживает только OAuth; профили подписки Anthropic используют `auth_mode = "oauth"`. Руководство для этой версии начинается с `codex login` или входа через Claude CLI на узле, где будет использоваться аккаунт. [Настройка подписки][oauth]

По умолчанию управляемый файл — `auth.json` рядом с `config.toml`. Свой `oauth_file` задаётся в provider profile; глобальный ключ `[llm] oauth_file` удалён. Новые файлы получают права `0600`, импорт выполняется атомарно. В файле одна запись на provider, поэтому разные ID профилей сами по себе не изолируют несколько входов по подписке.

Для удалённой работы проверяйте вход на удалённом узле. Если вход поставщика есть, но управляемое назначение доступно только для чтения, укажите в профиле закрытый путь с правом записи. Повторный вход не исправит права назначения. OAuth tokens, переданные только через окружение, автоматически не обновляются. Переработанные сообщения различают эти случаи.

## Один сервер для удалённой работы и панели

Отдельный дистрибутив `genesis_remote` упразднён. Удалённые команды и начальная настройка используют общий `genesis_server`: HTTP всегда доступен, а Erlang distribution переключается во время выполнения через файловый протокол, запускаемый SIGHUP. CLI предоставляет `genesis remote start`, `stop`, `status` и `logs`. [Сервер и установка][readme]

Если панель остаётся на ноутбуке, а задачи выполняются на SSH-хосте, меняется управление службой: проверьте скрипты с именем старого дистрибутива и управляйте общим сервером. Версия также поддерживает тесты удалённых проектов и возобновление тестов при вызове. Headless HTTP-сервер по умолчанию слушает localhost и не имеет встроенной авторизации; документированный удалённый доступ использует SSH-туннель.

## Проще восстанавливать взаимодействие при долгой работе

Многоуровневый посреднический вычислитель Elixir добавляет одобрение точного кода и восстанавливаемое одобрение в чате. Вывод обрезается по оставшемуся бюджету вместо ошибки из-за превышения. Также появились короткое окно восстановления после лимита ходов, финальные ответы без инструментов, короткие последовательные ID заданий и стабильные идентификаторы кэша промпта на запуск агента для GPT-вызовов OpenAI/Codex. Панель получила объединённый блок капсул и общие элементы выбора задачи и модели. [Подробные изменения][release]

## Обновлять, проверяя конфигурацию

1. Возьмите установщики или серверные архивы [v0.14.1][release] для нужной платформы. До изменения структуры аккаунтов сохраните конфигурацию. Старый `[[llm.models]]` остаётся совместимым вводом; канонические provider profiles имеют приоритет, а явное сохранение в Settings/config выполняет миграцию.
2. В **Settings → LLM → Provider profiles** проверьте авторизацию, вложенный список моделей, уровни по умолчанию и свой `oauth_file`. Учётные данные должны быть доступны процессу задачи, в том числе на удалённом сервере.
3. После перезапуска headless-сервера используйте `genesis status`, затем проверьте явный выбор профиля/модели/уровня, Auto и рабочее удалённое соединение. Перед повторным использованием проверьте старые скрипты демона. Эти проверки следуют из документированных изменений.
