Рабочее подключение модели требует не только имени: аутентификация, endpoint, поддерживаемые уровни рассуждения и общие ограничения аккаунта должны согласовываться. Изменения, включённые в Genesis `main` 19–20 ноября 2026 года, перестраивают Welcome и Settings вокруг аккаунтов провайдеров. PR #175 добавляет **Sign in with ChatGPT**, заменяя прежний импорт данных Codex для профилей подписки ChatGPT. [Интеграция][pr]

![Ключ аккаунта и компоненты выбранной модели размещены в одном упорядоченном футляре](./cover.webp)

*Концептуальная иллюстрация: аутентификация и выбор моделей относятся к одному настроенному аккаунту.*

## Сначала настроить аккаунт, затем модели

Welcome использует пошаговый мастер провайдера, а Settings обеспечивает дальнейшее управление аккаунтами. Автоматические имена и идентификаторы основаны на провайдере, а не выбранной модели. Один аккаунт может содержать несколько моделей и уровней рассуждения с общими учётными данными, параллелизмом и расписанием. При различии этих свойств подходят отдельные аккаунты. [Контракт профилей][profiles]

Например, команда с OpenAI-совместимым endpoint может один раз настроить базовый URL и учётные данные, добавить реально доступные модели и выбирать модель и уровень рассуждения для задачи. Интеграция делает доступным ввод API-ключа для пользовательских endpoint и направляет аккаунты пользовательских моделей через OpenAI Chat Completions. Каждая выбираемая модель должна быть в списке; одно имя модели по умолчанию её не регистрирует. Проверяйте выбранную модель, а не только заполненность поля учётных данных. [Интеграция и браузерные проверки][pr]

Мастер разделяет объявленные моделью уровни рассуждения и значение по умолчанию. Выбранное значение попадает в сохранённую запись модели и запрос проверки подключения. Каноническая шкала: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`; старое `max` читается как `xhigh` и при последующем сохранении записывается канонически. Специфичные написания провайдера преобразуются на границе запроса. Поддержка зависит от реальной модели: отображение шкалы не означает, что каждый endpoint принимает все уровни. [Правила рассуждения][profiles]

## Авторизовать ChatGPT через Genesis

Выберите **ChatGPT Subscription** в Welcome или **Settings → LLM → Provider accounts**. Версионированное руководство приводит `genesis chatgpt login`, `genesis chatgpt status` и `genesis chatgpt models` для входа и проверки. Из исходного checkout используется `mix genesis.chatgpt login`. Откройте показанный URL в браузере и разрешите доступ Genesis. [Руководство по подписке][oauth]

После входа используйте **Check connection**, выберите регистрацию и одну из доступных этому аккаунту моделей. В Settings сначала сохраните аккаунт, затем выполните **Connection Test**; Welcome проверяет модель до завершения настройки. Для совместимости сохраняется `provider = "openai_codex"`, используется `auth_mode = "oauth"`, а `siwc_account` определяет регистрацию Genesis.

Существующие профили подписки требуют повторной авторизации через Genesis: это подключение не использует старые учётные данные, импортированные из Codex. Если прежней модели нет в новом обнаруженном списке, выберите доступную. Аккаунты OpenAI с API-ключом остаются отдельным вариантом. Для нескольких регистраций используйте явный псевдоним, например `genesis chatgpt login --account work`, и выберите его в профиле. [Миграция и псевдонимы][oauth]

## Сохранять подключение на хосте выполнения

Учётные данные выбранного аккаунта разрешаются и обновляются на узле выполнения. Изменения сериализуются между CLI входа и работающим сервером. Так видимая в браузере регистрация не смешивается с подключением на другом удалённом хосте. [Хранилище аккаунтов][store]

Для собственного хостинга руководство описывает SSH-перенаправление loopback-порта входа и выполнение входа с тем же пользователем и каталогом конфигурации, что у службы Genesis. Также описаны защищённый перенос учётных данных и `GENESIS_SIWC_HTTPS_PROXY` для хостов, которым нужен HTTP CONNECT proxy. До проверки инференса выполните инструкции именно для нужного хоста: вход на ноутбуке не настраивает отдельный сервер.

Проверки обновления и потокового вывода ChatGPT в PR использовали фикстуры; новая браузерная авторизация настоящего аккаунта ChatGPT оставалась непроверенной в том обзоре. Для своей установки практическим подтверждением служит реальный ответ модели на нужном хосте. [Область проверки][pr]

## Явно задать расписания аккаунта

Та же модель аккаунта содержит параллелизм в пиковые и непиковые часы, часовой пояс и политику расписания. Новые пресеты могут заполнить поддерживаемые расписания провайдеров, но число слотов — изменяемые значения Genesis, а не гарантия мощности провайдера или экономии. Все модели аккаунта делят слоты; добавление модели не создаёт отдельную квоту. [Реализация пресетов][presets]

`off_peak_holidays = "CN"` добавляет поставляемый китайский календарь, включая компенсирующие рабочие дни. Данные статические, охватывают 2025–2027 годы и не обновляются автоматически. Проверьте часовой пояс, правила выходных и допущения пресетов. Нулевой пиковый параллелизм ставит новые запросы в очередь; уменьшение ёмкости не вытесняет уже выполняемую работу. [Семантика расписания][profiles]

После перехода на сборку с этими изменениями перепроверьте список моделей, рассуждение по умолчанию и хост каждого аккаунта. Повторно авторизуйте ChatGPT и выполните тест подключения. Для аккаунтов с расписанием проверьте сохранённые правила и следующее ожидаемое переключение. Это проверка идентичностей и ограничений, которые фактически будут использовать будущие задачи.

## Обновление списка моделей после сохранения

Изменения в `main` от 23 ноября 2026 года связывают сохранение регистраций ChatGPT с обновлением конфигурации. На том же узле выполнения изменение настроек перезагружает список моделей проекта; закрытие окна настроек рабочей области также запрашивает перезагрузку. Отброшенные результаты теперь вызывают ошибку с возможностью повтора вместо бесконечной загрузки. Перед повтором дождитесь готовности удалённого соединения. [GitHub](https://github.com/EMI-Group/genesis/commit/ffb0926723a4f2b695b1562a27954041be0cabd6)

Незавершённая настройка учётной записи больше не вызывает цикл сбоев планировщика. Он записывает в журнал невозможность определить модель по умолчанию; заполните список моделей учётной записи и выберите допустимую модель, прежде чем использовать этот вариант по умолчанию. [GitHub](https://github.com/EMI-Group/genesis/commit/868842557371daff7bcf68ce5ad59199b897d807)
