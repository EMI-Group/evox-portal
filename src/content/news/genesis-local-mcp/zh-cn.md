编码智能体往往已经掌握开发目标和项目路径。交给另一个引擎执行时，调用方需要在同一段对话中发起工作、追踪进度并取回结果。2026 年 11 月 11 日，Genesis 将本地模型上下文协议（MCP）端点合入 `main`。兼容的编码智能体可以通过一条连接调用 Genesis 现有的任务 API。[合并记录][pr]

## 连接负责执行任务的 Genesis 进程

Streamable HTTP 端点 `/mcp` 挂载在正在运行的 Genesis 服务器上。服务器验证请求的身份和参数，再调用现有的任务或调度器 API。HTTP 请求结束后，任务仍由服务器执行。连接是无状态的，后续查询靠任务 ID。

Genesis 接受来自回环地址的连接，并校验 Host 和 Origin。请求所需的 bearer 凭据来自运行实例的 `mcp-token` 文件。编码智能体的宿主需要支持 Streamable HTTP，并能持久保存授权请求头。Genesis 和可写的项目目录需在同一台机器上。[连接指南][guide]介绍了如何配置包含这项改动的源码构建。已发布版本的服务器配置可见 [Genesis 0.14.1][related]。

## 给任务带上足够的上下文

假设编码智能体已定位一个解析器缺陷，你要它委派回归测试。调用方可以先用 `genesis_check` 检查本地配置，再通过 `genesis_start_task` 提交主检出目录的绝对路径，以及说明出错输入、预期行为和验证方式的目标。Genesis 使用自己配置的模型，因此需要把调用方对话中的相关上下文写进目标。

九项工具覆盖就绪检查、配置重载、模型查询、任务提交、列表、状态、结果、消息和取消。已有 Git 仓库需要至少一个初始提交。此入口要求主检出目录包含 `.git` 目录，因此不接受关联工作树或子模块根目录。[任务与仓库要求][guide]

## 重连后用任务 ID 找回进度

保存提交返回的 ID。客户端重连后，可以用该 ID 调用 `genesis_get_task`，也可以先查询项目近期任务，再决定是否重发。状态接口从调度器和已保存的任务状态中提取有限的进度信息。轮询时可以省略完整结果，使用返回的变更令牌等待一段有限时间。

消息响应表示请求已进入队列。取消响应给出已接受的请求和已保存的状态。要确认执行结果，应查看最终任务状态，用 `genesis_get_result` 取回已保存的结果，并核对报告中给出的提交和测试证据。[任务观察与控制][guide]

## 先验证连接，再委派任务

从包含这项改动的源码版本构建 Genesis，在实际执行任务的实例上配置模型供应商。按指南创建私有凭据，并在客户端登记实例的实际回环地址。接着打开新的客户端会话并调用 `genesis_check`，分别检查 MCP 连通性和模型就绪状态，确认后再提交任务。[配置与连接检查][guide]
