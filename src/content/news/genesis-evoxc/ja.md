テンソルグラフ・コンパイラを構築するということは、同じ計算の複数の実装間で整合性を保つことを意味します。グラフ変換によってテンソルのレイアウトが変わることもあれば、アダプターが演算を拒否することもあり、デバイス・コールが計算の完了前に戻ってくることもあります。Genesis による EvoX Compiler の事例は、これらの境界を個別に検証する際に有用なものとなります。

![回帰テストに対してチェックされるコンパイラ・グラフ](./compiler-contract-layers.webp)

[10月28日の Evidence スナップショット](https://genesis.evox.group/evidence/evoxc/)では、6,789 件のテスト合格と、約 50 米ドルのモデルトークン費用が記録されています。これらの数字の背後にあるエンジニアリングを調査するため、本記事では公開されている v0.1.0 のソースコードも参照します。スナップショットとリリース版ではテストの総数が異なります。以下の実装例は、それぞれのバージョンによって特定されています。

## 目的をテスト可能なインターフェースに変換する

EvoX Compiler は、テンソル言語、EvoXIR グラフ、およびステージング・インターフェースを管轄します。外部コンパイラは、エクスポートされた表現を受け取り、最適化、スケジューリング、およびコード生成を処理します。その[パッケージ・コントラクト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/CONTEXT.md)には、依存関係の方向が文書化されています。値の型と IR がトレーシングと演算の基礎となり、変換とアダプターがそれらのレイヤーの上に構築されます。独立した `evoxc_hf` パッケージは公開コンパイラ API を利用しますが、コンパイラ側がモデル統合をインポートすることはありません。

この分割により、ローカルの開発作業に具体的な境界が与えられます。例えば、変換処理は、各バックエンドに Python の `vmap` を理解させることを要求するのではなく、別の通常のグラフを生成します。バックエンドの欠落は、実行パスを黙って変更するのではなく、明示的なエラーにする必要があります。パッケージレベルのコンテキスト・ドキュメントには、別の開発タスクが維持すべき API と制約が記録されています。

公開パイプラインは `trace → lower → compile → load → run` です。各ステージは個別のオブジェクトを返します。[仕様テスト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/tests/test_spec_compliance.py)では、誤ったステージの入力をチェックし、グラフ定義への直接的な eager execution コールを拒否し、便利な関数が文書化されたパイプライン通りに展開されることを検証します。また、作成者が明示的に埋め込まない限り、クロージャから具体的なテンソルをキャプチャすることも拒否します。これによる実用上の利点は、一見便利なショートカットが、知らないうちに別のセマンティクスを持ち込んでしまうのを防げることです。

Evidence の記録によると、開発はレイヤーごとに進められ、次のレイヤーに進む前に pytest によるチェックが義務付けられていました。リポジトリには、その手法のための検査可能なコントラクトとテストが用意されています。エージェントの意思決定の完全なアーカイブ・シーケンスは提供されていません。

## 2つのリファレンスに対してチェックされるポピュレーション変換

要求の厳しい機能の1つに `batch_functions` があります。これは、一致する入出力シグネチャを持つ複数のプログラムを単一のグラフに結合するものです。そのコントラクトは「結合されたグラフが動作する」ことよりも強力で、「出力の行 i は、プログラム i の結果と等しくなければならない」というものです。

[v0.1.0 の統合テスト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/tests/transforms/test_batch_functions_integration.py)では、読みやすい小規模な例を実行しています。同じグラフ位置で、3つのプログラムが `x + 1`、`x * 2`、`x - 3` を実行します。`switch_ops=True` の場合、マージされたグラフは行ごとの選択を通じて異なる演算を表現します。テストでは、このグラフを IREE の CPU パスでコンパイルし、その出力を、マージされたグラフの NumPy 実行結果、および元の関数の NumPy 結果をスタックしたものと比較します（`rtol=atol=1e-5`）。

コンパイラを介さないチェックでは、StableHLO の出力を検査し、期待通りの選択演算が行われているかを確認します。別のチェックでは、同一のプログラムをマージし、選択が不要な `vmap` と結果を比較します。これらのテストを組み合わせることで、単にコンパイルが成功したことを合格条件とするのではなく、プログラムの保存、エクスポート、およびバックエンド統合を精査しています。

## デバイス配置は正確性の一部である

GPU 上で動作する実行ファイルは、ホスト・データがすでにデバイス上に存在するかのように装って受け入れるべきではありません。[テンソルおよび配置の仕様テスト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/tests/test_spec_compliance.py)では、データが物理デバイスを持っていること、転送が `Tensor.to(device)` を通じて明示的であること、および無効な配置が `DeviceError` を発生させることをチェックします。

これはパフォーマンス測定においても重要です。すべての呼び出しでモデルの重みを再転送してしまうと、レイテンシの数値は、重みを常駐させている場合とは異なるワークロードを測定することになります。[v0.1.0 のモデル統合ドキュメント](https://github.com/EMI-Group/evoxc/blob/v0.1.0/evoxc_hf/CONTEXT.md)では、チェックポイントのロード、順方向計算、および実行ファイルのステージングを分離しています。パラメータは明示的なグラフ入力として残り、その配置が可視化されます。

## 返されたコールは必ずしも完了した作業ではない

XLA のデバイス常駐パスは、作業をキューに入れ、完了前に戻ってくることがあります。したがって、`run` の時間だけを計測すると、実行時間が過小評価されます。[同期テスト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/tests/backends/test_xla_synchronize.py)では、イベントのライフサイクルをチェックします。実行によって完了ハンドルが蓄積され、`synchronize()` がそれらを待機して破棄し、2回目の同期では追加のプラグイン作業が発生しないことを確認します。

エラーケースも同様に具体的です。待機が失敗した場合でも、残りのハンドルは処理され、最初のエラーが発生しなければなりません。完了イベントを提供しないプラグインは、虚偽の完了を主張するのではなく、明示的なエラーを発生させる必要があります。

これらのテストでは、数値計算を行わない小規模なフェイク PJRT プラグインを使用しています。これらは GPU のスループットや数値精度ではなく、同期のセマンティクスとクリーンアップを検証します。この区別により、テストの証拠（Evidence）と主張を一致させています。

ソース：[Evidence 検証](https://genesis.evox.group/evidence/evoxc/#verification) および [バージョン別リリースステータス](https://github.com/EMI-Group/evoxc/blob/v0.1.0/README.md#status--deferrals)。これらはプロジェクトによって報告された実行結果です。依存関係やハードウェアによるガードが、実行されなかったパスの理由です。CPU テストの合格は、すべてのアクセラレータの検証を意味するものではありません。

Evidence スナップショットの 285,659 行の追跡テキストには、テスト、ドキュメント、ベンチマーク資料が含まれています。約 50 米ドルの費用はモデルトークンをカバーしており、ハードウェア費用は含まれません。モデル、エピソード数、およびアクティブな実行時間は報告されていません。リポジトリのカレンダー期間は、連続した自律的な実行時間ではありません。

リポジトリは、コード、テスト、およびドキュメントの生成を Genesis の成果としています。具体的な成果物は、個別に検査可能なステージ・コントラクト、グラフ保存テスト、およびデバイス完了セマンティクスを備えたコンパイラです。これらの境界を越えて1つの機能を追跡するには、[ポピュレーション統合テスト](https://github.com/EMI-Group/evoxc/blob/v0.1.0/tests/transforms/test_batch_functions_integration.py)から始めてください。[EvoX Compiler の概要](/news/evox-compiler)では、ユーザー向けのパイプラインについて説明しています。
