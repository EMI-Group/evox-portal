Переход от разговора к задаче разработки и изменениям Git не должен требовать каждый раз восстанавливать контекст проекта. PR #175 Genesis, включённый в `main` 20 ноября 2026 года, добавляет рабочую среду LiveView с навигацией по проектам, вкладками, историей задач и разговоров, панелью Git и встроенными настройками. Связанные изменения пространств VCT и области черновиков позволяют переносить идентичность проекта между этими представлениями. [Объединённые изменения][pr]

*Концептуальная иллюстрация: каждый проект сохраняет собственный рабочий контекст.*

## Проверять проект в одном месте

Рабочая среда соединяет навигацию и рабочие представления. Можно вернуться к проекту, просмотреть задачи или разговоры и проверить изменения Git, не начиная заново в каждом разделе. Интеграция сохраняет выбор пространств, настройку учётных записей, паузу и возобновление задач. После переподключения восстанавливается и контекст согласования. Это развитие [предыдущего процесса работы Assistant с задачами][previous]; разрешённое действие по-прежнему определяется структурированным подтверждением. [Интеграция][pr]

Представьте разработчика, переключающегося между библиотекой и использующим её приложением. Черновик требований к библиотеке должен остаться с ней при открытии вкладки приложения. Операция Git должна выполняться на сервере и в репозитории выбранного проекта. Изменения проверяют принадлежность проекта перед операциями Git и сохраняют выбранный узел при недоступном соединении, не перенаправляя действие на хост панели управления.

## Идентичность черновика — это больше, чем путь

Общий модуль `DraftScope` определяет черновик браузера парой `{node, token}`. Проект, уже подключённый к Virtual Context Tree, использует точку `vct:///projects/<name>`; иначе применяется абсолютный путь операционной системы. Если доступны оба, точка имеет приоритет. Разные варианты записи пути одного подключённого проекта обращаются к одному черновику, а разные точки VCT над одним путём остаются разделёнными. [Реализация][scope]

Ключ хранения браузера объединяет узел и токен. Последующее исправление подхватывает черновик, привязанный к пути, когда становится доступна точка VCT, охватывая переход от выбора каталога к регистрации проекта. Это непрерывность браузерного черновика, отдельная от сохранности задач и от гарантии долговременного восстановления разговоров после перезапуска сервера. [Подхват черновика][adopt]

Для удалённого проекта важно сохранять путь буквально: панель не должна нормализовать его по правилам файловой системы хоста браузера. Перед отправкой восстановленного черновика проверьте узел, репозиторий и модель, особенно после переключения между локальными и удалёнными проектами.

## Пространства группируют проекты; задачам нужен каталог

VCT теперь имеет уровень группировки `vct:///workspaces/<name>`. Пространство содержит упорядоченный список участников и необязательное описание. Участники ссылаются на точки подключения проектов или пути ОС; вложенные пространства не поддерживаются. Палитра Projects и выбор проекта в Assistant могут показывать группы, а API только для чтения позволяют просматривать участников. [Интерфейс оператора][workspace]

У группы нет собственного каталога выполнения. Поэтому `DraftScope.path/1` не возвращает путь, если выбрано только пространство, а приём задач отклоняет точки VCT в качестве путей. В примере объедините библиотеку и приложение для совместной навигации, затем выберите конкретного участника для задачи разработки. Пространство не делает всех участников неявными целями записи.

В исходном checkout команды `mix vct.workspace list` и `mix vct.workspace show <name>` позволяют проверять группы. Документированная команда `create` принимает повторяющиеся `--member` и необязательный `--data-dir`; укажите каталог данных нужного экземпляра Genesis. Отсутствующие участники отмечаются, а не пропускаются молча. Перед изменением группы изучите контракт команды по ссылке.

## Проверять переходы между представлениями

В PR записаны браузерные проверки создания и завершения задачи, отправки с клавиатуры и потокового вывода Assistant, а также экрана настройки аккаунтов. Там же отмечен тайм-аут запроса Assistant о задачах конкретного проекта. Для долгой работы важно отличать принятие запроса от наблюдения его результата. [Запись проверок][pr]

В сборке с этими изменениями попробуйте два проекта с разными черновиками, переподключите выбранный узел и откройте Git-панель нужного проекта. Убедитесь, что черновик вернулся в правильный проект, а подтверждение по-прежнему указывает реальную цель выполнения. Затем следите за записанным состоянием задачи: восстановленная вкладка не доказывает завершение фоновой работы.
