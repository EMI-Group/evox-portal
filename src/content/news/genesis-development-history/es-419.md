El árbol de agentes muestra quién trabaja ahora. La historia del proyecto también debe explicar qué queda después. Genesis 0.13.4, publicado el 26 de septiembre de 2026, amplía la vista de commits de 0.13.2 y las referencias persistentes de tareas de 0.13.3, conectando actividad temporal con versiones inspeccionables.

## De agentes activos a referencias persistentes

La API de historial por tarea resuelve referencias persistentes y el commit base. La vista temporal conserva así commits de agentes ya reciclados. La API anterior consulta intervalos y referencias entre repositorios; la capa de tarea aporta el contexto para seguir un trabajo específico.

Cuando un agente delega un módulo y termina, su contribución puede seguir necesitando revisión. Git da al cambio una identidad duradera y la vista de tarea ayuda a localizarlo. El fin de una ejecución no tiene por qué borrar la relación entre tarea y código resultante.

## Mostrar las relaciones entre contribuciones

La versión 0.13.4 organiza commits por carriles de agentes, agrupa subárboles y muestra relaciones de delegación y fusión de retorno. Los commits sin propietario tienen un carril neutro. La selección, la sincronización al pasar el cursor y el teclado facilitan la inspección; los fallos parciales de lectura no vacían todo el gráfico.

La vista señala el recorte al alcanzar el límite de 100 commits. Permite navegar por el desarrollo, pero no es un archivo ilimitado ni una explicación completa de cada decisión.

## La trazabilidad apoya la selección

El gráfico muestra el origen y la integración de un cambio en una rama, pero no demuestra su corrección. Siguen haciendo falta diferencias, pruebas y revisión. Para la evolución del software de EvoX, hace más visible la relación entre contribuciones propuestas y versiones conservadas, ayudando a decidir qué continuar.
