오래 실행되는 개발 작업에는 재시작 버튼 이상의 것이 필요합니다. 어떤 에이전트가 작업했고 무엇을 파악했으며 어떤 파일 상태를 복구할 수 있는지 남아 있어야 합니다. 2026년 11월 19일 출시된 [Genesis 0.14.3][release]은 작업 단위 일시 중지와 재개, 영구 에이전트 상태, 명확한 실시간 활동 표시와 설정·승인·배포 개선을 제공합니다.

![분기된 기계 나무가 각각 고정된 받침에 다시 연결되는 모습](./whole-tree-resume.webp)

*개념 삽화: 작업 복구는 각 가지를 자신의 저장 상태에 다시 연결하는 과정입니다.*

## 취소하지 않고 작업 하나를 멈추기
실행 중인 작업은 `pausing`을 거쳐 `paused` 상태로 전환됩니다. 에이전트는 진행 중인 도구 배치를 마치고 대화를 체크포인트에 저장하며 작업 트리를 커밋한 뒤 멈춥니다. 일시 중지된 작업은 계속 표시되고 재개할 수 있으며 완료나 취소로 처리되지 않습니다. 재개할 때도 같은 작업 ID를 사용합니다.

여러 에이전트의 구현 작업을 다음 작업 시간으로 넘길 때 유용합니다. 에이전트 상태 저장을 활성화한 상태에서 일시 중지를 요청하고, 중지 상태가 될 때까지 저장이 끝났다고 판단하지 마세요. 영구 저장은 기본으로 켜져 있고 `genesis_start_task`의 `persistent_state`로도 제어합니다. 대화형 세션은 일시 중지할 수 없고, 저장을 끈 작업은 재개할 수 없습니다. [해당 버전 구현][pause]은 루트 에이전트의 영구 기록도 요구합니다. 자식 기록만으로 목표를 다시 시작할 수는 없습니다.
## 파일 복구 범위를 명확히 하며 트리 복원하기
별도 SQLite 저장소가 에이전트별 대화, 실행 ID, 도구 및 하위 에이전트 배치 진행 상황을 보존합니다. 트리 전체를 재개하면 완료된 자식은 저장된 결과를 제공하고, 실행 중이던 자식은 자신의 체크포인트와 작업 트리 기준점에서 이어갑니다. 안정적인 에이전트 ID가 연결 관계를 유지하며, ID가 이미 사용 중이면 경고와 함께 대체 처리를 합니다.

`refs/genesis/agent-state` 아래 Git 참조는 작업 브랜치가 회수되어도 체크포인트 커밋에 접근할 수 있게 합니다. 정상적인 일시 중지는 기록된 중지 커밋에서 작업 트리를 재생성합니다. 예기치 않은 중단 후 [재개 안내][notice]는 보장되는 체크포인트를 명시합니다. 종료된 실행의 커밋되지 않은 변경은 보존이 보장되지 않습니다. 체크포인트가 없으면 작업 기준점으로 돌아간 사실을 안내합니다.

파일을 편집하고 작업을 실행하던 태스크를 재개했다면, 작업을 반복하기 전에 안내된 커밋과 `git status`, `job_list`를 확인하세요. 중단된 도구 호출에는 가상의 성공 결과 대신 복구 정보가 제공됩니다. 이 버전은 하위 에이전트 중복 생성, 대화형 세션이 비정상 일시 중지 작업으로 복원되는 문제도 수정하고 턴 제한에서의 복구를 개선합니다.
## 유휴 상태처럼 보이던 작업 확인하기
검사기와 Assistant는 실시간 활동과 원자적 감시 스냅샷을 사용합니다. 컨텍스트 압축과 다음 턴 준비는 전용 실행 단계를 가지며 유휴 상태로 표시되지 않습니다. Context Memory는 실시간 호출을 마지막 행에 표시하고 이전 추론은 정적으로 유지합니다. 조용한 대기 구간을 해석하고 압축과 멈춘 요청을 구별하기 쉬워집니다.

스케줄러 소유 도구 허가는 동시 호출을 제한하며 백그라운드 인계 동안 소유권을 유지합니다. 포기된 실행 요청은 거부되고 시간 초과 격리 정리는 도구 태스크가 멈추기 전에 끝납니다. 백그라운드 완료 알림과 OS 상태 조회는 레지스트리를 막는 경로에서 분리되며, 세션 종료도 동기 저장 장벽을 피합니다. 체크포인트 쓰기는 대기 작업을 합치고 적체량과 페이로드 크기를 제한해 저장 부하가 모든 에이전트를 멈추지 않게 합니다.
## 더 명확해진 설정과 승인
스키마 기반 설정 API는 부분 업데이트를 지원하고 Assistant는 설정 탐색과 읽기 전용 프로젝트 조회를 수행합니다. 승인 대화상자와 알림은 요청자 ID, 권한, 실행 상태를 보여줍니다. 알림 범위, 포커스 처리, 권한 요청과 모션 감소 동작도 개선됩니다.

프로젝트를 인식하는 Assistant 세션은 분리된 대화, 업로드, 작업 추적을 이번 릴리스에 포함합니다. [프로젝트 워크플로 기사][workflow]에서 자세히 설명합니다. 명시적인 로컬 스킬 목록 명령은 도구 권한 검사를 생략할 수 있고, 에이전트가 커밋을 빠뜨리거나 실패하면 자동 커밋 대체 경로가 처리합니다.
## 업그레이드 후 복구 결과 점검하기
기존 헤드리스 서버 설치에서는 [해당 버전 업데이트 안내][update]의 명령을 사용합니다.
```bash
genesis update --check
genesis update
```
업데이트가 있으면 확인 명령은 종료 코드 10을 반환합니다. 업그레이드 전에 진행 중인 작업을 마치세요. 업데이트 도구는 서버 활동을 확인하고 새 버전을 준비한 뒤 재시작과 상태 검증을 수행합니다. 새 버전에서 일시 중지 중인 작업은 업데이트를 막지만, 중지된 작업은 재개 가능한 채로 업데이트를 막지 않습니다. Release에는 Linux x64, Linux ARM64, macOS ARM64 신규 설치 패키지가 있습니다.

데이터베이스 업그레이드는 별도 과거 기록 조정 단계 대신 일반 마이그레이션을 사용합니다. 이전 ID 충돌은 추가적으로 조정하며 잔여 또는 불완전 마이그레이션 상태는 거부합니다. SQLite 복구 경로는 개발 전용입니다. 사용하지 않는 재개 도우미와 완료 별칭이 공개 API에서 제거되어 사용자 정의 연동은 확인해야 합니다.

의존성에는 multipart 길이 제한 보안 수정이 포함된 Plug 1.20.4와 ReqLLM 1.31.0이 들어가며 Nix 의존성 해시와 사전 검사도 갱신됩니다. 업데이트 뒤 서버 버전과 정상 상태를 확인하고 작은 영구 작업으로 중지, 체크포인트 확인, 동일 작업 재개를 시험하며 자식 결과와 활동 표시를 살펴보세요. 배포별 마이그레이션 진단은 [전체 릴리스 노트][release]와 함께 확인할 수 있습니다.
