Длительной разработке нужна не только кнопка перезапуска: необходимо сохранить сведения о работающих агентах, накопленном контексте и состоянии файлов, которое действительно можно восстановить. [Genesis 0.14.3][release], выпущенный 19 ноября 2026 года, объединяет приостановку и возобновление задач, постоянное состояние агентов, более понятную текущую активность и изменения конфигурации, согласований и развёртывания.

![Разветвлённое механическое дерево снова соединяется с отдельно закреплёнными основаниями](./whole-tree-resume.webp)

*Концептуальная иллюстрация: восстановление задачи означает подключение ветвей к их собственному сохранённому состоянию.*

## Приостановить задачу, не отменяя её
Выполняемая задача переходит через `pausing` в `paused`. Агенты заканчивают текущие пакеты инструментов, сохраняют диалоги и фиксируют рабочие деревья коммитами перед остановкой. Приостановленные задачи остаются видимыми и допускают продолжение; они не становятся завершёнными или отменёнными. Возобновление сохраняет тот же ID задачи.

Это полезно, когда реализацию силами нескольких агентов нужно прервать между рабочими сессиями. Оставьте сохранение состояния включённым, запросите паузу и дождитесь состояния остановки. По умолчанию сохранение включено; его также задаёт `persistent_state` в `genesis_start_task`. Интерактивные сессии нельзя приостанавливать, а отключение сохранения исключает возобновление задачи. [Реализация этой версии][pause] требует постоянной записи корневого агента: одних записей дочерних агентов недостаточно.
## Восстановить дерево с явной границей состояния файлов
Отдельное хранилище SQLite сохраняет диалоги, идентификаторы запусков и прогресс пакетов инструментов и дочерних агентов. При восстановлении всего дерева завершённые дочерние агенты предоставляют сохранённые результаты; работавшие продолжают со своих контрольных точек и основ рабочих деревьев. Стабильные ID сохраняют связи; занятая идентичность вызывает предупреждение и резервный вариант.

Ссылки Git в `refs/genesis/agent-state` сохраняют достижимость коммитов после очистки рабочих ветвей. Штатная пауза позволяет пересоздать рабочее дерево из записанного коммита паузы. После прерывания [уведомление о возобновлении][notice] указывает гарантированную контрольную точку: сохранность незакоммиченных изменений остановленного запуска не гарантируется. Если точки нет, уведомление объясняет возврат к основе задачи.

Если задача редактировала файлы и запускала фоновые задания, перед повторением операций проверьте указанный коммит, `git status` и `job_list`. Прерванные вызовы получают сведения для восстановления, а не вымышленные успешные результаты. Версия также исправляет дублирование дочерних агентов, ошибочное восстановление интерактивных сессий как задач после аварийной паузы и улучшает восстановление при достижении лимита ходов.
## Увидеть работу, которая казалась простоем
Инспектор и Assistant используют текущую активность и атомарные снимки наблюдения. Сжатие контекста и подготовка следующего хода имеют собственные активные фазы вместо статуса простоя. Context Memory показывает текущие вызовы в последних строках, сохраняя исторические рассуждения статичными. Это помогает понимать тихие интервалы и отличать сжатие от зависшего запроса.

Разрешения инструментов, принадлежащие планировщику, ограничивают параллельные вызовы и сохраняют владельца при передаче в фон. Брошенные запуски отклоняются; очистка для локализации последствий тайм-аута завершается до остановки задач инструментов. Уведомления о завершении и проверки состояния ОС вынесены из блокирующего пути реестра; завершение сессии также избегает синхронных барьеров сохранения. Запись контрольных точек объединяет очередь и ограничивает её размер и объём данных, сдерживая нагрузку на хранилище.
## Более явные настройки и согласования
API настроек на основе схемы поддерживает частичные обновления; Assistant может обнаруживать конфигурацию и искать проекты только для чтения. Диалоги и уведомления согласования показывают инициатора, его полномочия и статус выполнения. Улучшены область уведомлений, управление фокусом, запрос разрешений и режим уменьшенной анимации.

Проектные сессии Assistant включают изолированные диалоги, загрузки и отслеживание задач; [статья о проектном процессе][workflow] объясняет взаимодействие. Явные команды просмотра локальных skills обходят проверки разрешений инструментов. Автоматический резервный коммит обрабатывает пропущенный или неудачный шаг фиксации агента.
## Обновить и проверить восстановленную работу
Для установленного сервера headless [руководство этой версии][update] описывает:
```bash
genesis update --check
genesis update
```
При доступном обновлении проверка возвращает код 10. Дайте активной работе завершиться перед обновлением: программа проверяет активность сервера, подготавливает версию, перезапускает и проверяет работоспособность. В новой версии задачи, ещё переходящие в паузу, блокируют обновление; уже приостановленные сохраняют возможность продолжения и не блокируют его. На странице выпуска есть пакеты Linux x64, Linux ARM64 и macOS ARM64.

Базы данных теперь обновляются обычными миграциями без отдельного исторического согласования. Конфликты старых идентификаторов согласуются аддитивно; остаточные или незавершённые состояния миграции отклоняются. Путь ремонта SQLite предназначен только для разработки. Неиспользуемые вспомогательные функции возобновления и псевдоним завершения удалены из публичного API; собственные интеграции должны учесть это.

Зависимости включают Plug 1.20.4 с исправлением безопасности ограничения длины multipart и ReqLLM 1.31.0; обновлены хеши зависимостей Nix и предварительные проверки. После обновления проверьте версию и работоспособность сервера, затем небольшую сохраняемую задачу: приостановите её, подтвердите контрольную точку, возобновите ту же задачу и изучите результаты детей и фазы активности. Сопоставляйте диагностику миграций вашей установки с [полными примечаниями к выпуску][release].
