EvoX Compiler v0.2.3 опубликован 25 ноября 2026 года UTC в виде Python wheel и архива исходников. Краткая заметка GitHub ссылается на сравнение v0.2.2 и v0.2.3; журнал изменений этой версии описывает существенные обновления ветки 0.2 и исправления упаковки, приведшие к этому дистрибутиву. При переходе с 0.1 важно выбрать пару компилятор/runtime, физическое устройство и численные проверки, которые нужно повторить. [Выпуск][release] · [Журнал изменений][changes]

## Согласуйте компилятор и runtime

Дополнение IREE теперь требует компилятор и runtime версии не ниже 3.13.0 и ниже 3.14. Скомпилированные артефакты зависят от версии: нельзя считать, что файл, созданный другой парой, загрузится без изменений. Разработчики повторно проверили llvm-cpu и ROCm/HIP на AMD Instinct MI300X с ROCm 7.1, включая циклы и сканирования, не работавшие в прежних версиях IREE. Эти проверки не распространяются автоматически на CUDA, выполнение с несколькими rank или все модельные бенчмарки. [Требования этой версии][requirements] · [Журнал изменений][changes]

Адаптер также управляет чтением результатов с устройства на хост вместо безусловного использования упрощённого пути runtime. Это важно, когда вычисление проходит успешно, но получение результата завершается ошибкой. Для памяти хоста можно сохранить путь с отображением памяти; буферам устройства нужна явная передача. Учитывайте время передачи в нагрузке приложения отдельно от времени ядра.

## Найдите плагин XLA и выберите его устройство

Регистрация XLA больше не проверяет плагины без опций до того, как вызывающая сторона сможет передать путь. Поиск учитывает явную опцию плагина, её переменную окружения, известные расположения и установленные пакеты плагинов JAX, не импортируя сам JAX. Доступность проверяется при компиляции и загрузке, когда опции уже известны. Вспомогательные функции сборки передают разрешённые опции загрузчику, исправляя ситуацию, когда компилятор находил плагин, а загрузчик терял его настройки. [Руководство по backend][guide]

Плагин ROCm должен обслуживать устройство ROCm, а плагин CUDA — устройство CUDA. Сочетание GPU-плагина с выбранным по умолчанию CPU отклоняется. Для эксперимента на GPU выберите соответствующее устройство и явно перенесите туда тензоры. Перед копированием результатов на хост проверьте расположение выходных данных. При ошибке выполнения XLA также очищаются кешированные слоты выходных указателей, чтобы следующий вызов не использовал устаревшие указатели на буферы.

## Проверьте семантику до сравнения скорости

Эталонный интерпретатор NumPy кеширует планы диспетчеризации, освобождает ненужные промежуточные значения после последнего использования и разделяет неизменяемый экземпляр устройства хоста. Это уменьшает затраты подготовки и выделения памяти без изменения публичного способа вызова. Измерения TensorNEAT в журнале относятся к конкретным нагрузкам, а не к универсальному коэффициенту ускорения.

Скомпилированная операция остатка теперь следует NumPy floormod: знак результата совпадает со знаком делителя. Поэтому отрицательные входные значения полезны при проверке обновления. Сохраните фиксированные входы и эталонные выходы, затем сравните интерпретатор и компилятор с допусками для соответствующего типа данных. Исправления упаковки разрешают каталог разделяемых библиотек, включаемый maturin, и размещают проверенные файлы дистрибутива в плоской структуре, устраняя ошибки, мешавшие публикации. [Зафиксированные исправления][changes]

## Обновляйтесь в чистой среде

Требуется Python 3.11 или новее. Установите выбранный wheel 0.2.3 из ресурсов выпуска через pip: доступны wheel для Linux, macOS и Windows и архив исходников. Для дополнения IREE используйте `pip install "evoxc[iree]==0.2.3"`, и проверьте обе зависимости IREE. Отдельный дистрибутив evoxc-hf сохраняет собственную версию. Выполните `pip check`, проверьте установленную версию и повторите один характерный граф, случай отрицательного остатка и передачу на устройство и обратно, прежде чем переносить крупную нагрузку. [Руководство по установке][guide]

Преобразования графов, пользовательские операции и явные стадии компиляции вокруг этих backend описаны в статье о [настраиваемой компиляции][related]; читайте её вместе с документацией этого выпуска.
