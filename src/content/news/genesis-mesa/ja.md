科学ソフトウェアの書き換えでは、アルゴリズム以上のものを引き継ぐ必要があります。後続の計算が依存する数値的な振る舞いも維持しなければなりません。Genesis の MESA 事例では、13の Fortran モジュールを Rust クレートに再構築し、元の出力を参照にしています。注目すべきは、その継続性をどう検査可能にしたかです。

![層状の恒星彫刻の下に、輪郭が一致する異素材の二つのリング](./mesa-numerical-continuity.webp)

*概念イラスト：新しい実装と共通の数値基準。*

## 13モジュールからなる数値計算の連鎖

[2026年9月7日の Evidence 記録](https://genesis.evox.group/evidence/mesa/)は **13 モジュール、Fortran 139,414 行から Rust 89,946 行**を報告しています。スナップショットの規模であり、ライブラリのみの行数とは異なります。

対象は補間、ソルバ、反応ネットワーク、状態方程式、不透明度などの数値・物理モジュールです。MESA 全体の代替ではなく、恒星・連星進化エンジンや文書に記された他の要素は対象外です。

## ビルドだけでなく計算を調べる

各モジュールに対応する crate と、インターフェース・制約文書があります。ゴールデンテストは元の Fortran 出力と比較し、統合テストはモジュール間の動作を確認します。

数値等価には許容誤差と課題の指定が必要です。単一結果の一致だけでは解法経路の違いを隠すため、単一区画燃焼の代理課題では積分ステップの動作も記録しています。単なるビルド成功より有用な証拠です。

## テスト記録に含まれるもの

リポジトリは **1,052 件成功、失敗なし、18 件無視**を報告しています。無視された項目にはベンチマークと時間のかかる全期間燃焼テストが含まれます。Evidence の **10.64 米ドル**はハードウェアを除くモデルのトークン料金で、モデル名、エピソード数、経過時間は未記載です。

単一実行について出典が報告した結果であり、独立再現はありません。まず文書化されたモジュールと負荷の範囲から確認できます。

## 二つのスナップショット、それぞれの高速化率

[Evidence](https://genesis.evox.group/evidence/mesa/) は中央値 **1.55–6.87 倍**の高速化を示します。一方、8月5日の README 表は15回の中央値で、端から端までの単一区画燃焼代理課題は **1.25 倍**です。 [README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md#latest-verified-results-2026-08-05-15-run-medians-taskset-0-3)

単一ゾーン燃焼モデルについて、README は両実装で **199 積分ステップ、198 回受理、1 回棄却**と記録しています。出力の許容誤差とこの過程を併せて比較すれば、数値経路の異なる計算の時間だけを比べるより高速化率を理解しやすくなります。

## 範囲を広げる前に一つの負荷を再現する

[README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md)にはツールチェーン、ビルド、テスト、ベンチマーク手順があります。環境を整えた後のテスト入口は次です。

```bash
cargo test --workspace
```

研究に関連する負荷を選び、[MESA 再開発リポジトリ](https://github.com/EMI-Group/genesis-demo-mesa-rs)で参照出力、許容誤差、ベンチマークドライバを調べてください。[Genesis の紹介](/ja/news/evox-genesis)はエージェント開発の背景を、この事例は必要な挙動が書き換え後も保たれたかを調べる具体的な方法を示します。
