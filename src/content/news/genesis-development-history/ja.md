エージェントツリーは現在の作業者を示します。プロジェクトの履歴には、作業後に何が残ったかを示す役割もあります。2026年9月26日公開の Genesis 0.13.4 は、0.13.2 のコミット履歴表示と 0.13.3 の永続参照を発展させ、一時的な活動を確認可能なソフトウェアの版と結び付けます。

![コミットを表すタイル付きの分岐レールが層状の記録に集まる](./durable-agent-history.webp)

## 稼働中のエージェントから永続参照へ

タスク単位の履歴 API は永続参照と基準コミットを解決し、回収済みエージェントのコミットも時間軸表示に残します。従来の API は複数リポジトリのコミット範囲と参照を照会し、タスク層が特定の開発を追い続けるための文脈を与えます。 [v0.13.2](https://github.com/EMI-Group/genesis/releases/tag/v0.13.2) · [v0.13.3](https://github.com/EMI-Group/genesis/releases/tag/v0.13.3)

モジュールを委任したエージェントが終了しても、その貢献のレビューは必要な場合があります。Git 履歴は変更の識別情報を保ち、タスク表示は全体の中でそれを見つける助けになります。一回の実行終了で、タスクと成果コードの関連まで失う必要はありません。

## 貢献の関係を表示する

0.13.4 はエージェント別レーンにコミットを並べ、同じサブツリーをまとめ、委任とマージの関係を示します。所有者のないコミットには中立レーンを使います。選択、ホバー連動、キーボード操作を備え、一部リポジトリの取得失敗でも全体表示は消えません。 [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

表示は100コミットで切り詰められ、その状態が示されます。以前の変更を調べる際は、タスクの基点と先端の参照から該当する Git 範囲を確認できます。

## 貢献を統合まで追跡する

タスクの基点コミットからエージェントのレーンをたどり、委派とマージバックを確認します。残す成果を決める際には差分とテスト結果も開きます。複数コードベースの変更は[複数リポジトリのレビュー](/ja/news/genesis-multi-repository)で統合へ進めます。
