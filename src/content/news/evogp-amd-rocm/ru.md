С GPU AMD можно исследовать древовидное генетическое программирование EvoGP без отдельного поискового движка. [PR #12][s2], включённый 17 июня 2026 года UTC (18 июня по Пекину), добавляет путь через ROCm/HIP. Изменение касается сборки расширения и сохранения смысла программ при исполнении.

![Одинаковые деревья программ над двумя разными ускорителями](./rocm-backend.webp)

*Концептуальная иллюстрация: единое представление пересекает границы GPU-бэкендов.*

## Один исходный код для CUDA и ROCm

Июньская интеграция использует HIP-преобразование PyTorch при сборке CUDA-расширений для AMD. Параметры выбираются по бэкенду, а CUDA-специфичный заголовок защищён. С ROCm PyTorch не требуется отдельная реализация алгоритмов.

Динамическое выделение стеков интерпретатора заменено локальными массивами фиксированного размера. Автор связал ошибки AMD с наложением выделенной памяти между одновременно резидентными wavefront. Отдельные стеки необходимы: чужое временное состояние может исказить fitness и последующий отбор.

## Перевод исходников ядер — лишь часть сборки

HIP-преобразование PyTorch переводит CUDA-код, но аргументы всё равно поступают компилятору устройства. Параметры NVIDIA нельзя напрямую передать `hipcc`. Настройка сохраняет список CUDA и использует `-O3` в ветке ROCm; отдельная защита закрывает заголовок, доступный только в CUDA. ROCm PyTorch обеспечивает преобразование, но EvoGP должен согласовать с ним и конфигурацию сборки. [Изменения сборки][s2]

## Подготовить окружение нужного бэкенда

[Инструкция по исходникам][s3] требует подходящих GPU-инструментов, компилятора C++ и PyTorch. Для AMD используются ROCm с `hipcc` и ROCm PyTorch. Сборка через `--no-build-isolation` использует уже установленную среду PyTorch.

Примеры сохраняют строки устройства `cuda` под ROCm — так устроен интерфейс PyTorch. `PYTORCH_ROCM_ARCH` выбирает конкретную архитектуру AMD. Это настройка сборки, а не переписывание деревьев или эволюционных операторов.

## Запустить тот же поиск на проверенном бэкенде

Автор сообщает о проверках на MI250X, W7800, RX 9070 XT и PRO V710 с указанными в PR ОС и версиями ROCm. Использованы 1 000 особей, 100 поколений и фиксированный seed. Это результаты для этих конфигураций, не универсальная гарантия производительности.

```bash
python -m evogp.sr_test
```

Для символьной регрессии сначала проверьте сборку и завершение небольшого регрессионного теста с конечной приспособленностью. Проверки автора охватывают wave32 и wave64 и сообщают о совпадающих траекториях при фиксированном seed, а не о новом универсальном ускорении. Сохраняйте данные, популяцию и seed при сравнении своего оборудования. [Обзор EvoGP][related] объясняет представление программ, а более позднее [исправление отчётности][logging] касается другой составляющей времени поколения.
