Дерево агентов показывает, кто работает сейчас. История проекта должна объяснять и то, что останется потом. Genesis 0.13.4 от 26 сентября 2026 года развивает представление коммитов из 0.13.2 и постоянные ссылки задач из 0.13.3, связывая временную активность с проверяемыми версиями ПО.

![Действия агентов сохраняются в истории проекта](./durable-agent-history.webp)

## От активных агентов к постоянным ссылкам

API истории задачи разрешает постоянные ссылки и базовый коммит. Временное представление сохраняет коммиты уже освобождённых агентов. Прежний API запрашивает диапазоны и ссылки между репозиториями; уровень задачи добавляет контекст для отслеживания определённой разработки. [v0.13.2](https://github.com/EMI-Group/genesis/releases/tag/v0.13.2) · [v0.13.3](https://github.com/EMI-Group/genesis/releases/tag/v0.13.3)

Когда агент делегирует модуль и завершает работу, его вклад всё ещё может требовать проверки. Git даёт изменению постоянный идентификатор, а представление задачи помогает найти его. Конец исполнения не должен стирать связь задачи с полученным кодом.

## Показать отношения между вкладами

Версия 0.13.4 размещает коммиты на дорожках агентов, группирует поддеревья и показывает делегирование и обратные слияния. Коммиты без владельца получают нейтральную дорожку. Выбор, синхронизация наведения и клавиатура помогают проверке; частичная ошибка чтения репозиториев не очищает весь граф. [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

Представление отмечает усечение при лимите 100 коммитов. Для более ранних изменений используйте базовую и конечную ссылки задачи, чтобы изучить соответствующий диапазон Git.

## Проследить вклад до интеграции

Начните с базового коммита задачи и проследите полосу агента через делегирование и обратное слияние. Откройте различия и результаты тестов, решая, что сохранить. Для нескольких кодовых баз следующий шаг интеграции — [проверка нескольких репозиториев](/ru/news/genesis-multi-repository).
