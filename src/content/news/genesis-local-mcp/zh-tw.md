程式代理通常已取得開發目標和專案路徑。把工作交給另一個引擎時，呼叫端需要在同一段對話中啟動工作、追蹤進度並取回結果。2026 年 11 月 11 日，Genesis 將本機模型上下文協定（MCP）端點合併到 `main`。相容的程式代理可透過一條連線使用 Genesis 既有的任務 API。[合併紀錄][pr]

## 連線至負責執行任務的 Genesis 程序

Streamable HTTP 端點 `/mcp` 掛載在執行中的 Genesis 伺服器上。伺服器驗證請求和參數，再呼叫既有的任務或排程器 API。HTTP 請求結束後，工作仍在伺服器上執行。連線本身不保留狀態，後續查詢使用任務 ID。

Genesis 接受回送位址連線，並驗證 Host 與 Origin。請求的 bearer 憑證來自執行個體的 `mcp-token` 檔案。程式代理的宿主須支援 Streamable HTTP，並能持久保存授權標頭。Genesis 和可寫入的專案目錄須位於同一部電腦。[連線指南][guide]說明如何設定含有此改動的原始碼建置。已發行版本的伺服器設定請參閱 [Genesis 0.14.1][related]。

## 提供足夠的任務背景

假設程式代理找到了剖析器缺陷，你請它委派迴歸測試。呼叫端可先使用 `genesis_check` 檢查本機設定，再以 `genesis_start_task` 提交主要取出目錄的絕對路徑，以及說明異常輸入、預期行為和測試方式的目標。Genesis 使用自己設定的模型，因此目標要包含呼叫端對話中的相關脈絡。

九項工具涵蓋就緒檢查、重新載入設定、查詢模型、提交任務、列表、狀態、結果、訊息與取消。既有的 Git 儲存庫至少要有初始提交。此入口要求主要取出目錄含有 `.git` 目錄，因此不接受連結工作樹或子模組根目錄。[任務和儲存庫要求][guide]

## 重新連線後依任務 ID 追蹤

保留提交時傳回的 ID。用戶端重新連線後，可以用這個 ID 呼叫 `genesis_get_task`，或先查詢專案近期的任務，再決定是否重送。狀態介面從排程器與已儲存的任務狀態提供有限的進度資訊。輪詢時可省略完整結果，使用傳回的變更權杖等待一段有限時間。

訊息回應代表請求已排入佇列。取消回應說明已接受的請求和已儲存的狀態。要確認結果，應查看最終任務狀態，以 `genesis_get_result` 取得已儲存的結果，並核對報告中的提交與測試證據。[任務觀察與控制][guide]

## 先驗證連線，再委派任務

從包含改動的原始碼版本建置 Genesis，並在實際執行工作的個體上設定模型供應商。依指南建立私有憑證，在用戶端登記實際回送位址。接著開啟新的用戶端工作階段並呼叫 `genesis_check`，分別檢查 MCP 連線和模型就緒狀態，再提交任務。[設定與連線檢查][guide]
