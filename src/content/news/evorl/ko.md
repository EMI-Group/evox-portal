*2026년 11월 7일 업데이트. 현재 프로젝트 구현을 바탕으로 내용을 확장했습니다.*

Physical AI는 다양한 행동을 탐색하고 상호작용으로 시험하며 유용한 경험을 다음 학습에 반영해야 합니다. EvoRL은 이 순환을 병렬 시뮬레이션으로 가져옵니다. 개별 정책은 경험에서 배우고 개체군 탐색은 대안과 학습 구성을 조사하므로, 학습과 진화의 관계를 실험적으로 연구할 수 있습니다.

EvoRL은 이러한 질문을 위한 오픈소스 연구 프레임워크입니다. JAX를 기반으로 강화학습, 진화 연산, 환경 시뮬레이션을 공통 학습 워크플로에 통합하여 기존 방법과 하이브리드 방법의 개발 및 평가를 지원합니다. EvoX의 자매 프로젝트인 EvoRL은 진화와 강화학습을 결합하여 개체군 수준 탐색에 현대 GPU의 병렬 처리 능력을 활용합니다. [프로젝트 소개](https://github.com/EMI-Group/evorl)

## 진화와 강화학습을 결합하는 이유

걷기를 배우는 로봇을 생각해 봅시다. 동일한 과제에도 걸음걸이, 속도와 안정성의 균형, 에너지 요구량이 다른 여러 유효한 정책이 있을 수 있습니다. 하나의 학습 경로만 따라 정책을 개선하면 이러한 가능성을 충분히 탐색하지 못할 수 있습니다.

강화학습은 상호작용 데이터를 이용해 정책을 개선합니다. 진화 연산은 후보 집합을 유지하면서 평가, 선택, 변이를 통해 여러 탐색 방향을 보존합니다. 둘을 결합하면 개체는 경험으로 학습하고 개체군은 유용한 결과를 개체 사이에 전달하는 더 풍부한 학습 과정을 연구할 수 있습니다.

진화 탐색은 정책 매개변수에 직접 적용하거나 강화학습의 하이퍼파라미터를 조정하는 데 사용할 수 있습니다. 전자는 어떤 정책을 찾을지, 후자는 정책이 더 효과적으로 학습하도록 어떻게 도울지에 관한 질문입니다.

이러한 상호 보완성이 모든 과제에서 하이브리드 방법의 우월성을 뜻하지는 않습니다. 검증할 설계 선택지가 늘어난다는 의미이며, EvoRL은 이를 탐색하는 구현 비용과 계산 비용을 줄이고자 합니다.

## 핵심 설계: GPU에 맞춘 전체 학습 파이프라인

개체군 방법의 장점은 다양성에서 나오지만 계산 부담도 함께 증가합니다. 후보 정책 하나가 추가될 때마다 환경 상호작용, 평가, 매개변수 업데이트가 늘어날 수 있습니다. 이 단계들을 CPU와 GPU에서 나누어 실행하면 반복적인 데이터 전송과 스케줄링이 병목이 될 수 있습니다.

호환되는 GPU 시뮬레이션 환경에서 EvoRL은 환경 상호작용, 정책 계산, 진화 연산, 학습 업데이트를 종단 간 GPU 파이프라인으로 구성합니다. JAX의 벡터화와 JIT 컴파일은 반복 계산을 일괄 처리하고 학습 단계의 계산 그래프를 최적화합니다. [기술 개요](https://evorl.readthedocs.io/latest/)

병렬화는 세 수준에서 이루어집니다.

- **환경 병렬화**: 하나의 정책이 여러 환경 인스턴스와 동시에 상호작용하여 경험을 일괄 수집합니다.
- **개체 병렬화**: 개체군 안의 여러 후보 정책을 동시에 평가합니다.
- **학습 병렬화**: 여러 에이전트의 학습을 동시에 진행하여 하이브리드 방법과 개체군 학습을 지원합니다.

이 설계는 더 많은 정책을 한 번에 탐색하는 실험을 구현하기 쉽게 만듭니다. 다만 개체군 크기는 GPU 메모리, 환경 비용, 네트워크 크기를 고려해야 합니다. [아키텍처 논문](https://arxiv.org/abs/2501.15129)

## 하나의 프레임워크에서 네 가지 방법 비교하기

EvoRL은 서로 다른 접근법에 공통 실험 기반을 제공합니다. 연구자는 기준선을 만든 다음 새로운 탐색 또는 학습 메커니즘을 추가할 수 있습니다.

| 방법 유형 | 대표 알고리즘 | 주요 연구 질문 |
| --- | --- | --- |
| 강화학습 | PPO, TD3, SAC 등 | 상호작용 데이터로 정책을 어떻게 개선할까? |
| 진화 알고리즘 | OpenES, ARS, CMA-ES 등 | 후보 평가 결과를 개체군 탐색에 어떻게 활용할까? |
| 진화 유도 강화학습 | ERL, CEM-RL 및 변형 | 진화 탐색과 경사 기반 학습을 어떻게 협력시킬까? |
| 개체군 기반 AutoRL | PBT-PPO, PBT-SAC 등 | 학습 중에 학습 설정을 어떻게 조정할까? |

특히 두 가지 하이브리드 방향에 주목할 수 있습니다.

**진화 유도 강화학습**은 개체군 탐색과 개별 학습을 연결합니다. 개체군이 정책 매개변수 공간의 서로 다른 영역을 탐색하고 강화학습 업데이트가 후보 정책을 개선할 수 있습니다. 알고리즘마다 경험 공유, 개체 업데이트, 개체군 선택 방식이 다르며, EvoRL은 이를 연구할 구현을 제공합니다.

**개체군 기반 AutoRL**은 학습 설정을 탐색합니다. 예를 들어 PBT에서는 여러 개체가 각각 학습하다가 주기적 평가에 따라 성능이 좋은 개체의 학습 상태를 물려받고, 하이퍼파라미터에 변화를 주어 탐색을 이어 갑니다. 따라서 하이퍼파라미터가 학습 도중에도 달라질 수 있습니다.

사용 가능한 알고리즘과 변형은 현재 저장소 구현을 기준으로 확인하세요. [알고리즘 목록](https://github.com/EMI-Group/evorl#algorithms)

## 모듈화: 연구 아이디어를 실험으로 옮기기

하이브리드 알고리즘을 개발할 때는 환경 연결, 데이터 구성, 평가 절차, 구성 요소 간 인터페이스 조정에 많은 시간이 듭니다. EvoRL은 핵심 추상화를 통해 이러한 역할을 정리합니다.

- **Env**는 공통 환경 상호작용 인터페이스를 제공합니다.
- **Agent**는 에이전트 행동과 관련 학습 로직을 정의합니다.
- **SampleBatch**는 궤적과 샘플 데이터를 구성합니다.
- **Workflow**는 알고리즘의 학습 단계를 정의합니다.
- **EC**는 진화 알고리즘과 관련 연산자를 제공합니다.

연구자는 필요한 부분만 바꿀 수 있습니다. 예를 들어 환경과 정책 네트워크를 유지하면서 탐색 방법을 교체하거나, 진화 연산을 추가하기 전후의 학습 양상을 비교할 수 있습니다. [프레임워크 및 API 문서](https://evorl.readthedocs.io/latest/)

공통 구현은 변수 통제에도 도움이 됩니다. 과제, 평가 절차, 계산 예산을 맞추면 알고리즘 개선과 구현 차이의 영향을 더 명확하게 구분할 수 있습니다. 프레임워크는 비교를 돕지만 엄밀한 실험 설계는 연구자의 몫입니다.

## 성능 향상은 무엇을 의미할까?

EvoRL 논문은 Intel Xeon Gold 6132 CPU 두 개, 128 GiB RAM, RTX 3090 GPU 한 개를 갖춘 시스템에서 Brax의 Swimmer 환경을 이용해 계산 효율을 비교합니다. 테스트한 설정에서 OpenES는 RLlib의 CPU 분산 구현보다 최대 60배 이상, CEM-RL은 공식 구현보다 약 5–9배 빨랐습니다.

이 수치는 특정 과제, 개체군 크기, 비교 기준에서의 계산 효율을 나타냅니다. 모든 과제에서 같은 향상을 보장하지 않으며 목표 보상에 도달하는 데 필요한 샘플 수가 같은 비율로 줄어든다는 뜻도 아닙니다. [실험 설정 및 결과](https://arxiv.org/html/2501.15129v1#S5)

실험 계획 관점에서 처리량 증가는 더 많은 난수 시드, 더 충실한 절제 실험, 더 큰 개체군을 고려할 여지를 줍니다. 주어진 예산 안에서 더 많은 아이디어를 검증할 수 있다는 것이 프레임워크 가속의 실용적 가치입니다.

## 로봇 제어에서 새로운 의사결정 과제까지

EvoRL은 연속 제어, 정책 탐색, 개체군 학습을 위해 Brax와 MuJoCo Playground 같은 로봇 시뮬레이션 환경을 지원합니다. gymnax, Jumanji, JaxMARL과의 실험적 통합은 고전 제어, 게임, 조합 최적화, 다중 에이전트 환경으로 확장됩니다. 각 설정에서 알고리즘 호환성을 확인해야 합니다. 일부 CPU 환경도 지원하므로 전체 GPU 파이프라인의 가능 여부는 선택한 환경과 알고리즘 조합에 달려 있습니다. [환경 지원 안내](https://github.com/EMI-Group/evorl#rl-environments)

진화 강화학습 연구자는 기존 알고리즘으로 기준선을 세운 뒤 개체군 탐색과 정책 학습의 협력 방식을 바꿀 수 있습니다. AutoRL에 관심이 있다면 PBT로 시작해 학습 설정의 영향을 살펴볼 수 있습니다. 새로운 최적화 방법을 개발한다면 공통 인터페이스로 자체 구성 요소를 점진적으로 통합할 수 있습니다.

## 첫 실험 실행하기

먼저 [설치 안내](https://evorl.readthedocs.io/latest/guide/installation.html)에 따라 하드웨어에 맞게 JAX를 설정하세요. 그런 다음 소스에서 EvoRL을 설치하여 예제에 필요한 학습 스크립트와 설정을 준비합니다.

```bash
git clone https://github.com/EMI-Group/evorl.git
cd evorl
pip install -e .
```

Brax의 Ant 환경에서 PPO 기준선으로 시작할 수 있습니다.

```bash
python scripts/train.py agent=ppo env=brax/ant
```

EvoRL은 Hydra로 실험 설정을 관리합니다. 기준선이 실행되면 난수 시드, 알고리즘 설정, 환경 설정을 바꾼 뒤 하이브리드 방법이나 개체군 학습으로 진행하세요. 전체 사용법은 [빠른 시작](https://evorl.readthedocs.io/latest/guide/quickstart.html)을 참고하세요.

EvoRL은 진화와 학습의 결합을 더 쉽게 실천하도록 돕고자 합니다. 하나의 프레임워크에서 질문을 세우고, 방법을 조합하고, 실험하고, 결과로 아이디어를 검증할 수 있습니다. [GitHub 저장소](https://github.com/EMI-Group/evorl)에서 기존 알고리즘을 시험하거나 구현을 기여하고, [Discussions](https://github.com/EMI-Group/evorl/discussions)에서 연구 및 사용 경험을 나누어 주세요.
