[2026年9月7日的 Evidence 記錄](https://genesis.evox.group/evidence/compiler-continuation/)描述了一次從 **GLM 5.2 到 DeepSeek V4 Flash** 的編譯器交接，過程中未攜帶前序智慧體的對話上下文。已驗收的原始碼樹和 Git 開發歷史保持可用。工程上的問題在於，接收模型可以檢查哪些內容，以及隨後的變更如何評估。

![在不同工具鏈之間保留的編譯器專案](./compiler-model-handoff.webp)

該記錄報告在延續後，**1,820/1,820 個保留的 LLVM SingleSource 案例透過測試**，且任務遞迴深度從 4 增加到 8。它並未公佈逐項修復日誌，也未公佈延續過程中增加的程式碼量和成本。下方的公開 jcc 原始碼解釋了該編譯器的介面和迴歸機制；它們的獨立快照並不能重構交接操作的確切序列。

## 接手模型需要保留哪些模組邊界

[jcc 架構](https://github.com/EMI-Group/genesis-demo-jcc/blob/a8c116ec7ed3d59479ad3be8fed3e63384f50a87/docs/architecture.md)將前端、型別化的 CIR 中間表示、最佳化器、機器碼後端、彙編器和命令列驅動程式進行了分離。前端將經過檢查的語法樹交給表示轉換；後續階段使用生成的表示，而不是獨立地重新解釋原始原始碼。

當新模型修改某個元件時，這一點至關重要。表示轉換中的算術修復仍必須滿足 CIR 型別檢查；呼叫約定的變更必須與暫存器分配和目標檔案生成保持一致。這些是架構文件中記錄的依賴關係示例，而非針對特定移交修復的斷言。

驅動程式暴露了中間停止點：`-E` 用於預處理，`-emit-jcc-ir` 用於 CIR，`-S` 用於彙編，`-c` 用於目標檔案生成。這些產物有助於在測試連結的可執行檔案之前，定位哪個階段發生了變化。

## 迴歸檢查涵蓋了成功的程式和應被拒絕的輸入

[測試指南](https://github.com/EMI-Group/genesis-demo-jcc/blob/a8c116ec7ed3d59479ad3be8fed3e63384f50a87/docs/testing.md)描述了檢查退出狀態和輸出的編譯執行案例，以及檢查診斷嚴重程度、訊息和原始碼位置範圍的編譯失敗案例。最佳化 pass 同樣具有表示驗證檢查。

因此，後繼者面臨不止一個驗收條件。如果輸出發生變化，生成可執行檔案是不夠的；如果語言策略要求拒絕某個程式，那麼接受它也是不夠的。診斷測試保留了僅關注成功的基準測試會遺漏的行為。

[版本化 README](https://github.com/EMI-Group/genesis-demo-jcc/blob/a8c116ec7ed3d59479ad3be8fed3e63384f50a87/README.md#feature-status) 列出了具體的限制，例如部分 `long double` 運算和推遲的目標平臺。這些限制是很有用的繼承資訊：修改文件中記錄的拒絕項是一項功能決策，而不自動等同於迴歸修復。

## LLVM 測試框架實際比較的內容

公開的 [LLVM-suite 執行器](https://github.com/EMI-Group/genesis-demo-jcc/blob/a8c116ec7ed3d59479ad3be8fed3e63384f50a87/tools/llvm-suite/run.py) 使用受試編譯器配置測試套件，構建可執行檔案，並將其輸出與參考檔案進行比較。其直接比較是基於空白符 token 的：非數字 token 必須完全匹配；數字 token 使用可配置的浮點容差（預設為 1e-4）；最終退出碼必須完全匹配。

這說明了為什麼測試計數需要清單和比較策略。執行器文件中記錄的 36 個案例的 Regression/C 子集，與延續記錄中 1,820 個保留案例的評估範圍不同。較小的快照不能用於推斷移交時的初始透過率，將兩個總數相減也無法衡量進度。

初始編譯器記錄和延續記錄連結到同一個倉庫。它們不應被視為兩個獨立的編譯器專案，且其不同範圍的測試總數應保持分離。

## 使移交過程可檢查

對於應用此方法的開發者，一個有用的移交包由已驗收的修訂版本、構建命令、介面契約、確切的迴歸測試清單和已知排除項組成。這是從公開架構和測試框架中得出的實踐建議，而非聲稱該實驗已存檔了此類形式的完整包。

從微小的變更開始，並將其中間產物、診斷資訊和可執行檔案行為與該修訂版本進行比較。[Genesis 演化歷史檢視](/news/genesis-development-history)為在執行任務的智慧體結束後跟蹤後續貢獻提供了相關上下文。
