一つの機能が API サービス、クライアント、共通ライブラリにまたがることがあります。変更の目標は同じでも、Git リポジトリは別です。2026年9月26日公開の Genesis 0.13.4 は、書き込み可能な関連リポジトリに永続的なワークツリーを追加し、実行の境界を明確にしました。

![一つのプロジェクトにつながる別々のリポジトリ履歴](./companion-worktrees.webp)

## アクセスから作業の分離へ

0.11.4 は追加リポジトリの読み書き、リポジトリ別レビュー、読み取り専用リポジトリへの書き込み制限を導入しました。0.13.4 では、各関連リポジトリの永続的なワークツリーでエージェントが作業し、主 HEAD や主作業ツリーを変更せずに済みます。 [v0.11.4](https://github.com/EMI-Group/genesis/blob/v0.11.4/CHANGELOG.md)

関連リポジトリのパスは、そのワークツリーを基準に解決されます。初期コンテキストに場所を示し、リポジトリを越えた委任もそこを基準にします。ディレクトリ構造が異なったり、別の開発が同時に進んだりしても、変更場所が明示されます。 [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

## 統合判断はリポジトリごとに

0.13.0 は個別のマージ・却下操作、マージ確認、処理状態を持つレビューカードを導入しました。一括マージは未処理のリポジトリをまとめて受け入れつつ、個別結果を示します。関連リポジトリだけが変更された場合のレビューも修正しました。 [v0.13.0](https://github.com/EMI-Group/genesis/releases/tag/v0.13.0)

API の変更では、サービス、クライアント、共有ライブラリを各履歴で確認します。インターフェースの版と統合順序を決め、組み合わせた結果をテストします。

## リポジトリ横断レビューを準備する

委派前に各リポジトリの書き込み可能なワークツリーを確認し、完了後はレビューカードで変更、マージチェック、処理状態を調べます。プロジェクトをまたぐ作業を具体的な受入判断につなげられます。[開発履歴ビュー](/ja/news/genesis-development-history)でその背後のコミットを追跡できます。
