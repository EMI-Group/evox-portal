一個功能可能同時涉及 API 服務、用戶端應用程式和共用程式庫。這些修改屬於同一個目標，卻不一定屬於同一個 Git 儲存庫。2026 年 9 月 26 日發布的 Genesis 0.13.4 為可寫的關聯儲存庫加入持久化工作樹，讓跨儲存庫工作有了更明確的執行邊界。

![紅色飄帶連接三個獨立庭院，每個庭院都有自己的入口](./companion-worktrees.webp)

## 從存取程式碼到隔離工作

0.11.4 已引入額外儲存庫的讀寫支援，包括逐儲存庫審查以及對唯讀儲存庫的寫入限制。0.13.4 在此基礎上，為每個可寫關聯儲存庫提供持久化工作樹：智慧體在其中工作，而不移動儲存庫主 HEAD，也不干擾其主要工作區。 [v0.11.4](https://github.com/EMI-Group/genesis/blob/v0.11.4/CHANGELOG.md)

指向關聯儲存庫的路徑會相對於該工作樹解析。智慧體的初始上下文顯示其位置，跨儲存庫任務委派也以此為基礎。當不同儲存庫具有不同目錄結構，或仍有其他開發活動時，這讓變更發生的位置更加清晰。 [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

## 整合仍然逐儲存庫決定

0.13.0 引入逐儲存庫審查卡片，分別顯示合併、拒絕操作、合併檢查與處理狀態。全部合併快捷操作可以一起接受尚未處理的儲存庫，同時保留各自的結果。該版本也修復了任務只修改關聯儲存庫時的審查流程。 [v0.13.0](https://github.com/EMI-Group/genesis/releases/tag/v0.13.0)

一次 API 修改可以沿服務、用戶端與共用函式庫各自的歷史接受審查。先約定介面版本與整合順序，再針對組合後的結果執行檢查。

## 準備一次跨儲存庫審查

委派前，確認各儲存庫可寫工作樹的位置；完成後，透過對應審查卡片檢查修改、合併檢查與處理狀態。跨專案任務因此落實為一組明確的驗收決定。[開發歷史視圖](/zh-tw/news/genesis-development-history)可協助追溯背後的提交。
