에이전트 트리는 지금 누가 작업하는지를 보여 줍니다. 프로젝트 이력은 작업 후 무엇이 남았는지도 설명해야 합니다. 2026년 9월 26일 출시된 Genesis 0.13.4는 0.13.2의 커밋 이력 뷰와 0.13.3의 지속 참조를 발전시켜 일시적인 활동과 확인 가능한 소프트웨어 버전을 연결합니다.

![프로젝트 이력에 보존된 에이전트 활동](./durable-agent-history.webp)

## 실행 중인 에이전트에서 지속적인 참조로

작업별 이력 API는 지속 참조와 작업 기준 커밋을 찾아, 회수된 에이전트의 커밋도 시간순 뷰에 남깁니다. 기존 API가 저장소 간 커밋 범위와 참조를 조회하고, 작업 계층이 특정 개발 활동을 계속 추적할 맥락을 제공합니다. [v0.13.2](https://github.com/EMI-Group/genesis/releases/tag/v0.13.2) · [v0.13.3](https://github.com/EMI-Group/genesis/releases/tag/v0.13.3)

모듈 작업을 위임한 에이전트가 종료되어도 그 기여는 검토가 필요할 수 있습니다. Git 이력은 변경의 식별 정보를 보존하고 작업 뷰는 전체 활동에서 이를 찾도록 돕습니다. 한 번의 실행이 끝나도 작업과 결과 코드의 관계까지 사라질 필요는 없습니다.

## 기여 사이의 관계를 보여 줍니다

0.13.4는 커밋을 에이전트 레인으로 나누고 같은 하위 트리를 모으며 위임과 병합 관계를 표시합니다. 소유자가 없는 커밋은 중립 레인을 사용합니다. 선택, 호버 연동, 키보드 접근을 지원하고 일부 저장소 조회 실패가 전체 그래프를 지우지 않도록 했습니다. [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

이력은 100개 커밋 표시 한도에 도달하면 잘림을 표시합니다. 오래된 변경은 작업의 기준 및 끝 참조로 해당 Git 범위를 확인할 수 있습니다.

## 기여를 통합까지 추적하기

작업의 기준 커밋에서 시작해 에이전트 레인을 따라 위임과 병합 복귀를 추적하세요. 유지할 결과를 결정할 때 해당 차이와 테스트 결과도 확인하세요. 여러 코드베이스의 변경은 [다중 저장소 검토](/ko/news/genesis-multi-repository)를 통해 통합할 수 있습니다.
