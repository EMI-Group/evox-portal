Physical AI 需要探索不同的行为，通过交互检验它们，并将有价值的经验带入下一轮学习。EvoRL 将这个循环放入并行仿真：个体策略从经验中学习，种群搜索探索不同策略与学习配置，使学习和演化之间的关系成为能够系统研究的实验问题。

![模拟四足模型探索不同运动方式](./population-learning-loop.webp)

EvoRL 围绕这些问题构建了一套开源研究框架。它基于 JAX，将强化学习、演化计算与环境仿真接入统一的训练流程，支持从经典算法到混合方法的开发与评估。作为 EvoX 的姊妹项目，EvoRL 聚焦于演化计算与强化学习的结合，让种群层面的搜索能够充分利用现代 GPU 的并行计算能力。[项目介绍](https://github.com/EMI-Group/evorl)

## 为什么要把演化与强化学习结合起来？

以机器人学习行走为例，同一个任务可能存在多种有效策略：不同的步态、不同的速度与稳定性取舍，以及不同的能耗表现。只围绕一条学习轨迹改进策略，可能难以充分探索这些选择。

强化学习擅长利用交互数据持续优化策略；演化计算则通过维护一组候选解，在种群中进行评估、选择和变化，为搜索保留多个方向。将两者结合，就可以研究一种更丰富的学习过程：既让个体从经验中改进，也让种群在不同个体之间传播有价值的结果。

在这个过程中，演化搜索可以直接作用于策略参数，也可以用于调整强化学习的超参数。两种方式回答的是不同的问题：前者关注“寻找什么样的策略”，后者关注“怎样让策略学得更好”。

这种互补关系并不意味着混合算法在所有任务上都优于单独使用强化学习。它提供的是更多可检验的设计选择，而 EvoRL 希望降低探索这些选择的工程与计算成本。

## 核心设计：让整个训练流程适应 GPU

种群方法的吸引力来自多样性，计算压力也来自多样性。每增加一个候选策略，就可能增加一批环境交互、策略评估和参数更新。如果这些环节分别运行在 CPU 和 GPU 上，频繁的数据传输与调度就可能成为瓶颈。

EvoRL 的核心设计，是在兼容的 GPU 仿真环境下，将环境交互、策略计算、演化操作和学习更新组织为端到端的 GPU 计算流程。它利用 JAX 的向量化与即时编译能力，把大量重复计算批量执行，并优化训练步骤中的计算图。[技术概览](https://evorl.readthedocs.io/latest/)

可以从三个层次理解它的并行方式：

- **环境并行**：让同一策略同时与多个环境实例交互，批量收集经验。
- **个体并行**：同时评估种群中的多个候选策略。
- **训练并行**：同时推进多个智能体的学习过程，为混合算法与种群训练提供支持。

这套设计让“同时尝试更多策略”更容易成为可执行的实验。当然，种群规模仍需结合显存、环境开销和网络规模选择。[架构论文](https://arxiv.org/abs/2501.15129)

## 在同一框架中比较四类方法

EvoRL 将不同路线放在共同的实验基础上，便于研究者建立基线，再逐步加入新的搜索或学习机制。

| 方法类别 | 代表算法 | 主要研究问题 |
| --- | --- | --- |
| 强化学习 | PPO、TD3、SAC 等 | 如何利用环境交互数据改进策略？ |
| 演化算法 | OpenES、ARS、CMA-ES 等 | 如何根据候选策略的评估结果进行种群搜索？ |
| 演化引导的强化学习 | ERL、CEM-RL 及其变体 | 如何让演化搜索与梯度学习相互配合？ |
| 基于种群的自动强化学习 | PBT-PPO、PBT-SAC 等 | 如何在训练过程中调整学习配置？ |

其中，两类混合方向尤其值得关注。

**演化引导的强化学习**把种群搜索与个体学习联系起来。例如，可以用种群探索不同的策略参数区域，再结合强化学习更新改进候选策略。不同算法对经验共享、个体更新和种群选择采用不同安排，EvoRL 为研究这些安排提供了现成实现。

**基于种群的自动强化学习**则把搜索推进到训练配置层面。以 PBT 为例，多个学习个体分别训练，周期性地依据评估结果继承较好个体的训练状态，并扰动超参数，继续探索。这样，超参数可以随训练过程调整。

上述算法及具体变体以当前仓库实现为准。[算法列表](https://github.com/EMI-Group/evorl#algorithms)

## 模块化，让研究想法更容易落到实验中

开发混合算法时，真正耗时的工作往往包括环境适配、数据组织、评估流程以及不同组件之间的接口协调。EvoRL 用一组核心抽象组织这些工作：

- **Env** 提供统一的环境交互接口。
- **Agent** 定义智能体行为及相关学习逻辑。
- **SampleBatch** 组织轨迹与样本数据。
- **Workflow** 定义算法的训练步骤。
- **EC** 提供演化算法与相关操作组件。

这些模块让研究者能够围绕某个环节进行修改。例如，在保留环境和策略网络的情况下替换搜索方法，或比较加入演化操作前后的学习表现。[框架与 API 文档](https://evorl.readthedocs.io/latest/)

对研究而言，共同实现基础的价值还在于更容易控制变量：使用相同任务、评估方式与计算预算，才能更清楚地判断改进来自算法设计，还是来自实现细节。统一框架为这种比较提供便利，严谨的实验设置仍需要研究者自行完成。

## 性能提升意味着什么？

EvoRL 论文在 Brax 的 Swimmer 环境上，使用配备双 Intel Xeon Gold 6132 CPU、128 GiB 内存及一张 RTX 3090 GPU 的机器进行了计算效率比较。在所测配置中，OpenES 相比 RLlib 的 CPU 分布式实现最高获得超过 60 倍的加速；CEM-RL 相比其官方实现获得约 5–9 倍加速。

这些数字反映的是特定任务、种群规模与基线下的计算效率，不能直接解读为所有任务都能获得同样提升，也不等同于达到目标奖励所需的样本数按同等比例减少。[论文实验设置与结果](https://arxiv.org/html/2501.15129v1#S5)

从实验规划的角度看，更高的计算吞吐量意味着可以考虑更多随机种子、更充分的消融实验，或更大的种群。这是框架加速对研究工作最直接的价值：让更多设想能够在可用预算内接受验证。

## 从机器人控制到新的决策任务

EvoRL 支持 Brax 和 MuJoCo Playground 等机器人仿真环境，适合开展连续控制、策略搜索和种群训练实验。项目也提供 gymnax、Jumanji、JaxMARL 等环境的实验性接入，覆盖经典控制、游戏、组合优化与多智能体等方向；这些扩展的算法兼容性需要按具体配置确认。框架还支持部分 CPU 环境，因此是否能实现完整的 GPU 计算流程，取决于选用的环境与算法组合。[环境支持说明](https://github.com/EMI-Group/evorl#rl-environments)

如果你正在研究演化强化学习，可以先用现成算法建立基线，再调整种群搜索与策略学习之间的协作方式；如果你关注 AutoRL，可以从 PBT 入手，观察训练配置如何影响学习过程；如果你希望开发新的优化方法，也可以利用统一接口，逐步接入自己的组件。

## 开始第一个实验

当前安装要求为 Python 3.12 或更新版本，以及 JAX/jaxlib 0.10.0 或更新版本。 [EvoRL](https://github.com/EMI-Group/evorl#installation)

建议先按[安装指南](https://evorl.readthedocs.io/latest/guide/installation.html)配置与硬件匹配的 JAX 环境，再从源码安装 EvoRL，以获得示例所需的训练脚本和配置：

```bash
git clone https://github.com/EMI-Group/evorl.git
cd evorl
pip install -e .
```

随后，可以从 Brax 的 Ant 环境和 PPO 基线开始：

```bash
python scripts/train.py agent=ppo env=brax/ant
```

EvoRL 使用 Hydra 管理实验配置。跑通基线后，可以进一步修改随机种子、算法配置和环境设置，再开展混合算法或种群训练实验。完整用法见[快速入门](https://evorl.readthedocs.io/latest/guide/quickstart.html)。

将第一次 PPO 运行保留为基线：修改组件前，保存环境、随机种子、配置和学习曲线。如果希望先从更简单的种群搜索入手，可以阅读 [EvoX 工作流教程](/zh-cn/news/evox-quickstart)。
