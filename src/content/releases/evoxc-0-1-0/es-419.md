Cuando los candidatos de una búsqueda son programas, depurar solo la salida final deja oculta buena parte del experimento. EvoX Compiler hace que el propio programa sea inspeccionable: puedes conservar su grafo, transformarlo y elegir un backend mediante etapas separadas y visibles.

![Estructura del programa visible para su inspección](./evoxc-visible-stages.webp)

*Ilustración conceptual: la estructura del programa se hace visible entre definición y ejecución.*

**EvoX Compiler (evoxc) v0.1.0** se publicó el 29 de octubre de 2026. Este frontend y runtime Python para grafos de tensores requiere Python 3.11 o posterior y utiliza la licencia Apache-2.0. [v0.1.0](https://github.com/EMI-Group/evoxc/releases/tag/v0.1.0)

## De una definición a un ejecutable inspeccionable

El flujo es `trace → lower → compile → load → run`. El trazado construye EvoXIR desde la definición y las especificaciones de entrada; lowering prepara la representación del backend; la compilación crea un artefacto que se carga en un dispositivo y se ejecuta con datos. Cada etapa produce un objeto inspeccionable.

Así se distinguen grafos inválidos, operaciones no compatibles y errores de dispositivo. Los grafos y artefactos admitidos pueden guardarse. Los compiladores externos optimizan, planifican y generan código; evoxc proporciona el frontend y los contratos entre etapas.

## Reunir una población de programas en un grafo

`vmap`, `grad`, `jvp` y `vjp` producen grafos combinables antes de ejecutarlos. [`batch_functions`](https://github.com/EMI-Group/evoxc/blob/v0.1.0/README.md#batch-transformation--one-graph-for-a-whole-population) agrupa funciones candidatas con especificaciones de entrada y salida coincidentes en un grafo de población.

En programación genética, búsqueda de arquitecturas y síntesis de algoritmos, los candidatos pueden ser programas diferentes. Agruparlos puede reducir compilaciones e invocaciones, pero el beneficio depende de la estructura y del backend; no está garantizado.

## Elegir el backend según las operaciones necesarias

NumPy es la única dependencia obligatoria y ofrece el intérprete CPU de referencia. Los adaptadores opcionales conectan IREE, XLA mediante un plugin PJRT del usuario y TVM mediante StableHLO. La cobertura de operadores y hardware varía.

El README versionado documenta Vulkan sobre Mesa lavapipe, un dispositivo software, y TVM ROCm solo en compilación. Las entradas GPU y su ubicación son explícitas. Verifique las operaciones compatibles antes de trasladar un grafo CPU.

## Empezar en CPU y trasladar después el grafo

Instale la versión fijada, ejecute el ejemplo CPU del README, inspeccione el grafo y seleccione después un backend compilado:

```bash
pip install evoxc==0.1.0
```

La integración de HuggingFace se instala por separado como `evoxc-hf`, con su propia distribución y ciclo de actualización.

## Leer la validación junto con su entorno

Con las dependencias opcionales documentadas, el README de la versión reporta **7,511 pruebas aprobadas, 77 omitidas y 4 fallos esperados**, sin fallos inesperados, en las suites principales y de integración. Las omisiones incluyen condiciones de hardware y dependencias. El repositorio atribuye el código, las pruebas y la documentación a Genesis.

Consulte el [README versionado](https://github.com/EMI-Group/evoxc/blob/v0.1.0/README.md), la [publicación](https://github.com/EMI-Group/evoxc/releases/tag/v0.1.0) y [GitHub](https://github.com/EMI-Group/evoxc) para API, artefactos y desarrollo posterior.

El proceso de desarrollo con agentes se presenta en [Genesis y EvoX Compiler](/es-419/news/genesis-evoxc). Para tu experimento, conserva un grafo de referencia y examina cada transformación antes de comparar los backends.
