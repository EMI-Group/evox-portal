ソフトウェアシステムの構築では、プロジェクトが成長しても有用な局所変更が互換性を保つ必要があります。Genesis の WASM Render はグラフィックス処理を通じてこの課題を調べます。シェーダ処理、描画、API の動作を整合した全体へ育てることが、EvoX の Agentic AI とシステム構築を結びます。

![幾何シーンの処理段階をそろえるガラス板](./software-graphics-pipeline.webp)

Genesis の公開記録は DeepSeek V4 Flash による TypeScript ソフトウェアレンダラを説明します。対象集合で Khronos CTS 2,017/2,019、WebGL2 1,184/1,184が成功しました。約36米ドルはトークンのみで機器費用を含みません。最初と最後のエージェントコミット間65.9時間は履歴上の期間で、実働時間ではありません。

[Genesis Evidence](https://genesis.evox.group/evidence/tbench-wasm/)

## 個別のコードから完全なシステムへ、何が難しいのか？

WASM Render は Terminal-Bench Challenges に含まれるグラフィックスシステムの課題です。ブラウザー、GPU、外部ランタイムライブラリを使わずに WebGL プログラムを動作させることが求められます。

これは、グラフィックスパイプラインをソフトウェアで実装することに相当します。シェーダープログラムを解釈し、グラフィックスを計算し、多数のインターフェースと状態変化の整合性を保たなければなりません。個別の機能が動くことと、システム全体が連携して動くことの間には、大きな隔たりがあります。この課題では、AI が何度も開発を重ねながら目標との整合性を維持し、モジュール間の依存関係を扱い、テストのフィードバックに基づいて誤りを修正し、最終的にシステム統合と回帰検証を完了する必要があります。

初期12時間試行とは開発予算が異なるため、成功率は統制された順位比較になりません。Evidence は厳格な0.1%閾値で three.js 16/38、Babylon.js 13/16も報告します。いずれも選択された部分集合です。API適合率の高さは、全視覚回帰成功や完全な描画互換性を意味しません。

![WebGL2.0 適合性テストの結果と Genesis の Khronos CTS テスト記録](./wasm-render-results-en.png)

*WebGL2.0 適合性テストの結果と Genesis の Khronos CTS テスト記録。*

135,165行の追跡テキストには生成済み renderer.js、外部コード、ロックファイル、文書が含まれ、描画ソースのみではありません。早期の自律提出という説明は主催者公表の順位ではありません。結果はプロジェクト報告で独立再現されていません。

今回の開発では最終的に 2,017 件の Khronos CTS テストに合格し、モデルの token 利用料は約 36 米ドル、キャッシュヒット率は約 98% でした。これほど大規模なソフトウェア開発を低いモデル利用コストで継続し、統合まで進めたことは、Genesis が低コストのオープンソースモデルを用いて長期的な開発を遂行できることも示しています。

## プロジェクトを継続的に進化させ、Agent は必要に応じて参加する

Genesis は、ソフトウェアを再帰的に進化させる AI システムです。ユーザーがソフトウェア開発の目標を記述すると、システムはその目標を中心にタスクを展開し、必要な箇所に局所的な Agent を割り当て、採用されたコードと検証結果をソフトウェアプロジェクトに残します。

大規模なプロジェクトに取り組む際、直感的な方法の一つは Agent により多くを与えることです。コンテキストを長くし、セッションを長く維持し、事前に定めた協調の仕組みをより複雑にする、といった方法です。Genesis は開発の連続性をソフトウェアプロジェクト自体に持たせます。最上位の目標と制約が開発全体を導き、タスクはリポジトリ構造に沿って再帰的に展開されます。Agent は局所的な作業を担当し、完了すると終了します。後続の Agent は、それまでに形作られたプロジェクトを引き継ぎます。

Genesis は以前にも、空のリポジトリから出発して約 25 万行のコードからなる C コンパイラを構築し、モデルを切り替えながら開発を継続しました。今回の WASM Render チャレンジのテスト結果は、複雑なグラフィックスシステムの開発における Genesis の自律的な構築・統合能力をさらに裏付けるものです。

## 進化を続けられるオープンなシステム

この事例のオープンソースとしての価値は、システム構築を検査可能にする点にあります。インターフェース、実装、検証結果は後続作業でも使えます。エージェントのタスクをまたいで有用な変更を蓄積し、統合後の振る舞いで進展を測る、EvoX のソフトウェア進化の方向を進めます。
