Reescribir software científico exige conservar algo más que los algoritmos: también el comportamiento numérico del que dependen los cálculos posteriores. En el caso MESA de Genesis, trece módulos Fortran se reconstruyeron como crates Rust usando las salidas originales como referencia. Lo interesante es cómo el proyecto hace verificable esa continuidad.

![Una escultura estelar por capas sobre dos anillos de materiales distintos con contornos coincidentes](./mesa-numerical-continuity.webp)

*Ilustración conceptual: una nueva implementación y una referencia numérica compartida.*

## Trece módulos en una cadena numérica conectada

El [registro del 7 de septiembre de 2026](https://genesis.evox.group/evidence/mesa/) cubre **13 módulos**, de **139.414 líneas Fortran a 89.946 líneas Rust**. Son tamaños del snapshot, no del código de biblioteca exclusivamente.

El port incluye interpolación, solvers, redes de reacción, ecuación de estado y opacidad. No reemplaza todo MESA: los motores de evolución estelar y binaria y otros componentes documentados quedan fuera.

## Comprobar el cálculo, no solo la compilación

Cada módulo corresponde a un crate con interfaces y restricciones documentadas. Las pruebas de referencia comparan salidas Fortran y las de integración comprueban las interacciones.

La equivalencia numérica necesita tolerancia y carga definidas. Un escalar coincidente puede ocultar una trayectoria de solución diferente; por eso se registran también pasos de integración del proxy de combustión de una zona. Esto aporta más que compilar correctamente.

## Qué contiene el registro de pruebas

El repositorio reporta **1,052 pruebas aprobadas, ningún fallo y 18 ignoradas**, incluidos benchmarks y una combustión lenta de duración completa. Evidence indica **10.64 dólares de costo de tokens del modelo**, sin hardware; no especifica modelo, número de episodios ni tiempo transcurrido.

Son resultados reportados por la fuente para una sola ejecución, sin reproducción independiente. El alcance documentado de módulos y cargas ofrece un punto de partida para examinarlos.

## Dos instantáneas, distintas cifras de aceleración

[Evidence](https://genesis.evox.group/evidence/mesa/) informa de **1,55–6,87× de aceleración mediana**. La tabla README del 5 de agosto usa medianas de 15 ejecuciones y da **1,25×** para el proxy de combustión de una zona de extremo a extremo. [README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md#latest-verified-results-2026-08-05-15-run-medians-taskset-0-3)

Para el proxy de combustión de una zona, el README registra **199 pasos de integración, 198 aceptados y 1 rechazado** en ambas implementaciones. Comparar ese comportamiento junto con las tolerancias de salida explica mejor la aceleración que cronometrar cálculos con trayectorias numéricas distintas.

## Reproducir una carga antes de ampliar el alcance

El [README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md) detalla herramientas, compilación, pruebas y benchmarks. Tras preparar el entorno:

```bash
cargo test --workspace
```

Elige una carga relevante y examina sus salidas de referencia, tolerancias y controladores en el [repositorio de reconstrucción de MESA](https://github.com/EMI-Group/genesis-demo-mesa-rs). La [presentación de Genesis](/es-419/news/evox-genesis) aporta el contexto del desarrollo con agentes; este caso ofrece una forma concreta de comprobar si la reescritura conserva el comportamiento que necesitas.
