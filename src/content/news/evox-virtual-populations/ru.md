Изменения EvoX от 7–8 июля 2026 года вводят путь обработки виртуальной популяции для нейроэволюции. Обычный подход может требовать отдельный вектор параметров для каждой сети-кандидата. VirtualES хранит общий центр и случайное начальное значение для каждой особи, восстанавливая гауссовские возмущения по необходимости. Это ответ на конкретный инфраструктурный вопрос: какое разнообразие кандидатов можно представить при заданном объёме памяти?

## Компактная популяция и явный путь оценки

Для P кандидатов с D параметрами хранение всех параметров требует памяти, пропорциональной P × D. Представлению через центр и начальные значения нужно примерно D + P элементов. Сравнение касается только параметров: активации, приспособленность, состояние оптимизатора и буферы оценки также занимают память.

VirtualES передаёт `(center, seeds, sigma)` рабочему процессу. VirtualProblem оценивает кандидатов послойно. Объединённая операция Triton совмещает базовое линейное вычисление с возмущениями весов и смещений, восстановленными из начальных значений, не создавая полного тензора возмущённых сетей. Приспособленность определяет обновление центра для следующего поколения.

## Границы реализации

Полные гауссовские возмущения заменяют прежнюю низкоранговую формулировку LoRA. VirtualProblem поддерживает `nn.Sequential` с линейными слоями и указанными функциями активации. Это не универсальный оценщик произвольных архитектур; документированный интерфейс не поддерживает обёртку HPO. Виртуальный путь также пропускает распределённую оценку и преобразования решений.

## Значение представления

Работа по-новому связывает популяционный поиск с исполнением. Она позволяет исследовать компромиссы памяти без предварительного хранения весов всех кандидатов. Пиковая память и пропускная способность всё ещё зависят от структуры сети, размера популяции, пакетов и оборудования; изменения сами по себе не доказывают универсального ускорения. Для EvoX это конкретный шаг к более гибкой вычислительной организации эволюционного поиска.
