一つの機能が API サービス、クライアント、共通ライブラリにまたがることがあります。変更の目標は同じでも、Git リポジトリは別です。2026年9月26日公開の Genesis 0.13.4 は、書き込み可能な関連リポジトリに永続的なワークツリーを追加し、実行の境界を明確にしました。

## アクセスから作業の分離へ

0.11.4 は追加リポジトリの読み書き、リポジトリ別レビュー、読み取り専用リポジトリへの書き込み制限を導入しました。0.13.4 では、各関連リポジトリの永続的なワークツリーでエージェントが作業し、主 HEAD や主作業ツリーを変更せずに済みます。

関連リポジトリのパスは、そのワークツリーを基準に解決されます。初期コンテキストに場所を示し、リポジトリを越えた委任もそこを基準にします。ディレクトリ構造が異なったり、別の開発が同時に進んだりしても、変更場所が明示されます。

## 統合判断はリポジトリごとに

0.13.0 は個別のマージ・却下操作、マージ確認、処理状態を持つレビューカードを導入しました。一括マージは未処理のリポジトリをまとめて受け入れつつ、個別結果を示します。関連リポジトリだけが変更された場合のレビューも修正しました。

API 変更なら、サービス、クライアント、ライブラリの貢献をそれぞれの履歴で確認できます。互換性のあるインターフェースと適切なテストは依然必要です。複数リポジトリのマージ操作は、原子的なトランザクションや自動的な互換性保証を意味しません。

## より大きなソフトウェアシステムの基盤

重要なのは変更の生成だけでなく、作業の組織化です。Genesis は、ユーザーが確認して採用する場所を維持しながら、リポジトリ間の貢献を調整します。独立して保守される複数の部分へ EvoX のソフトウェア進化の方向を広げ、採用済みの版を次の開発の起点にします。
