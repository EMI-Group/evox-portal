一個功能可能同時涉及 API 服務、用戶端應用程式和共用程式庫。這些修改屬於同一個目標，卻不一定屬於同一個 Git 儲存庫。2026 年 9 月 26 日發布的 Genesis 0.13.4 為可寫的關聯儲存庫加入持久化工作樹，讓跨儲存庫工作有了更明確的執行邊界。

## 從存取程式碼到隔離工作

0.11.4 已引入額外儲存庫的讀寫支援，包括逐儲存庫審查以及對唯讀儲存庫的寫入限制。0.13.4 在此基礎上，為每個可寫關聯儲存庫提供持久化工作樹：智慧體在其中工作，而不移動儲存庫主 HEAD，也不干擾其主要工作區。

指向關聯儲存庫的路徑會相對於該工作樹解析。智慧體的初始上下文顯示其位置，跨儲存庫任務委派也以此為基礎。當不同儲存庫具有不同目錄結構，或仍有其他開發活動時，這讓變更發生的位置更加清晰。

## 整合仍然逐儲存庫決定

0.13.0 引入逐儲存庫審查卡片，分別顯示合併、拒絕操作、合併檢查與處理狀態。全部合併快捷操作可以一起接受尚未處理的儲存庫，同時保留各自的結果。該版本也修復了任務只修改關聯儲存庫時的審查流程。

對於一次 API 修改，這意味著服務、用戶端與共用程式庫的貢獻能夠沿各自歷史接受審查。儲存庫之間仍需相容的介面與適當測試；一次多儲存庫合併操作，並不等於原子交易或自動保證跨專案相容。

## 面向更大軟體系統的基礎

這個節點關注的不只是如何生成修改，也包括如何組織工作。Genesis 能夠跨儲存庫協調貢獻，同時保留使用者檢查與接受成果的明確位置。這將 EvoX 的軟體演化方向延伸至由多個獨立維護部分組成的系統，讓被接受的版本成為後續開發的起點。
