# Showcase-inspired EvoX redesign

The homepage adopts the Genesis Showcase reference's monochrome surfaces, generous spacing, large Instrument Sans typography, restrained red accents, and corner chapter navigation. A one-shot full-viewport EVOX opening leads into EvoX's purpose, evolution, AI applications, hardware support, resources, and recent updates. SVG diagrams explain evolution and the four application areas.

`HomeIntro.astro` displays the full vector BrandWordmark in a fixed opening overlay; its translated cue links to the existing hero at `#home`. One downward wheel gesture, click/tap anywhere in the opening, upward one-finger swipe, or PageDown/ArrowDown/Space/End press starts a 1050ms native Web Animations flight. The actual displayed logo shrinks and moves to the upper-left header wordmark while the curtain fades away. Source and destination are measured once, the native scrollbar remains in place to keep the target stable, and the header target stays hidden until the flying logo arrives. The shared 64px header fades in during entry; the chapter rail appears on completion.

The opening appears once per document. Completion hides the overlay, restores temporarily inert content and chrome, and removes the temporary input listeners. It leaves no scrolling placeholder, so scrolling up or following `#top` returns to the normal homepage and cannot replay the opening. `#top` belongs to the homepage wrapper; `#home` belongs to the hero. Keyboard entry moves focus to the hero title. Escape, interruption handlers, and a 1.6-second safety timeout ensure that entry always releases input. Deep links and restored scroll positions bypass the overlay. Reduced-motion preferences enter instantly and disable cue, header, and optional reveal motion. Without JavaScript, an in-flow opening, a normal `#home` cue, and visible navigation keep the page usable. Other routes show the header immediately. The chapter rail appears at viewport widths of at least 1280px; cards and content rows adapt for mobile.

The four application illustrations are independent server-rendered SVGs under `src/components/art/`, selected by `ParadigmArt.astro`. Model matrices merging, the author's Genesis tree, three quadruped-training stages, and a real airfoil section retain the original flat diagram style. The quadruped sequence shows loss of balance followed by a fall, a shaky standing posture maintained by small corrective steps, and coordinated walking. The fallen model keeps making rapid, unsuccessful low recovery motions after landing and resets while faded out. Its loop lasts 2 seconds; the middle model completes eight corrective steps in a 1.6-second loop, with continuous body sway. Each model contains only a torso and four two-segment legs, without circular joint markers, heads, foot plates, or body details. Server-computed poses keep the hips connected to the torso during CSS path animation. The middle model lifts one foot at a time to widen or narrow its support area while its torso sways in place; its support feet remain fixed between corrections. Only the final model has an alternating diagonal walking gait. The model matrices send short selection pulses into the merged result, the Genesis tree grows one level at a time as messages are delivered and returned, and fine moving arrows follow the airfoil streamlines from left to right and align to their tangents. The matrix, quadruped, and airfoil drawings use CSS motion. The Genesis illustration uses event-driven incremental SVG updates, native SVG path motion and CSS state effects, with a complete static fallback. Reduced-motion preferences stop all animation and hide moving signal overlays, preserving the original diagrams and the three quadruped poses. All four use subtle solid fills and EvoX red accents, with no gradients, shadows, or perspective. Their 480×280 view boxes scale with the cards while non-scaling strokes preserve fine details on mobile. Shared colors respond to both themes. Only the Genesis lifecycle requires a small client script; all four illustrations remain decorative for assistive technology.

### Application illustration sources

`genesisTree.ts` reuses the author's seeded `hash`/`rng`/`treeSpec` generator from [Showcase projects-data.js](https://github.com/liangfang-wen/genesis-showcase/blob/616262121528d2fa302cc137dda30ec050f6ed72/v6-copy2-corner-tree/projects-data.js) and its [evotree.js cover layout](https://github.com/liangfang-wen/genesis-showcase/blob/616262121528d2fa302cc137dda30ec050f6ed72/v6-copy2-corner-tree/evotree.js). The engine originates in the author's [Genesis PR #157](https://github.com/EMI-Group/genesis/pull/157), head `1428e7ced6c156386a2036592a6cc5b72ea7b5f9`, which was closed without merging. The cover version uses a tidy layout; the original LiveView hook has a different live relaxation layout. The adaptation retains the seeded branching/status rules, spacing, node radii, Bezier construction, and fit equations. Seed `evox` produces nine nodes across four levels. It renders fixed SVG geometry, omits interactive labels and live layout effects, and maps the original palette to site colors. The component uses these coordinates as stable reserved slots, then creates the actual SVG nodes and edges incrementally. Its runtime states are independent of the generator's random snapshot states. The upstream AGPL-3.0 license is preserved alongside the source. Eight generator seed/scale cases and the displayed tree's coordinates and edges were checked against the original functions.

`agenticLifecycle.ts` separates the message sequence from the layout: the root dispatches to level two, level two dispatches to level three, and all new level-three nodes share the same pending appearance. One result travels back and is parked; a second travels back for processing and receives a continuation command. Only that branch then generates level four. `agenticPlayer.ts` reconciles node IDs with this timeline, so the live SVG node count grows from one to three, seven, and nine. It retains the original parent-to-child growth and reverse-message semantics, without importing LiveView or its interactive interface. The player schedules only semantic boundaries rather than reconciling every frame. It adapts the original Genesis growEdge/convergeSpark mechanics: CSS draws newly generated paths and SVG animateMotion follows the forward or reversed cubic, with duration taken from the authored message timeline. Pending dots breathe over 2.4 seconds, running nodes use a 2.6-second halo and 2.2-second expanding ripple, and waiting nodes breathe over 3.4 seconds, matching the original keyframes. Flat solid halos replace the original blur and glow to preserve this design. Geometry is measured once per new edge; no JavaScript path sampling runs during motion. The event clock, CSS keyframes/transitions and SVG animation pause together offscreen or in a hidden tab; resume retains progress. The loop resets every node, edge, and signal together. Server-rendered final geometry remains available without JavaScript and when reduced motion is requested.

`science-airfoil-data.ts` uses the [P-51D Mustang root section at BL17.5 from UIUC](https://m-selig.ae.illinois.edu/ads/coord/p51droot.dat), explicitly identified by the [coordinate index](https://m-selig.ae.illinois.edu/ads/coord_database.html#P) and [aircraft listing](https://m-selig.ae.illinois.edu/ads/aircraft.html). The 21 upper and 21 lower source points are interpolated without changing the original approximately 16.5% thickness ratio. A uniform scale and 3-degree rotation preserve the geometry. Seventeen streamlines were calculated offline using 236 constant-source panels, a uniform vortex, a no-penetration condition and a trailing-edge Kutta condition, then integrated with RK4. The method follows the [AeroPython panel-method reference](https://github.com/barbagroup/AeroPython/blob/master/lessons/11_Lesson11_vortexSourcePanelMethod.ipynb); [NASA's streamline explanation](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/definition-of-streamlines/) supplies the flow visualization reference. The paths are simplified to at most 0.2 SVG units of deviation, with sparse section stations. Sixteen of the seventeen calculated streamlines are displayed: the lower line with only 0.537 SVG units of clearance is omitted, leaving a minimum displayed gap of approximately 7.99 units. The remaining computed paths and real airfoil contour are unchanged. Fine moving arrows replace fixed arrows and thick moving dashes; the red upper-contour accent is removed to keep the outline separate from the field. Validation found no streamline crossings through the section after simplification. This is an incompressible, inviscid, two-dimensional schematic, not measured flow or cruise CFD; it does not model shocks, viscosity, turbulence, or separation.

Dark is the default theme. The header toggle switches to light and saves `evox-theme` in localStorage; Layout restores it before paint. Shared CSS tokens also adapt existing content pages. Instrument Sans Latin and Latin Extended fonts are served locally, with system fallbacks for other scripts. All 13 locales remain supported, including a translated theme-toggle label.

## Run locally

### Brand logo theme sweep

`src/components/BrandMark.astro` ports the author's public [Genesis implementation](https://github.com/EMI-Group/genesis/commit/bbb8c454965df48acad79b9aa90b151693617244) from `feat/brand-mark-theme-sweep` (not merged into Genesis main at the time of integration). It preserves the 18 SVG paths, precomputed 23ms delays, 150ms easing, dark/light fills, and constant red diagonal. Explore and footer use the mark directly. It needs no component JavaScript and remains visible without JavaScript; reduced-motion preferences disable the sweep.

`src/components/BrandWordmark.astro` combines the EVO letter paths supplied by the user in `新版本evox-svg.zip` with that animated X. The supplied source is preserved at `src/assets/brand/evox-wordmark-source.svg`. The component preserves the lettering's gradient and the full wordmark's source proportions, uses unique SVG gradient IDs, and responds to the shared dark/light theme. The opening, homepage hero, and header share this same vector component, so the full opening logo can scale into the header precisely. Parent elements provide accessible names; the SVG is decorative. The shared header brand remains in the upper-left corner on all routes. Its `[data-intro-logo]` wrapper supplies the measured flight destination, so the opening follows the current responsive header geometry without a separate positioning prop.

### Development server

Use the pinned pnpm version from `package.json`:

```sh
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

Open the URL printed by Astro. English is `/`; other locales use prefixes such as `/zh-cn`, `/ja`, and `/pt-br`. To check production output, run `pnpm build`, then `pnpm preview --host 127.0.0.1`.

### Portable HTML preview

Run `pnpm export:preview` to build the site and run `scripts/export-preview.mjs`. It writes independent Chinese (`evox-preview.html`) and English (`evox-preview-en.html`) previews to the ignored `dist-preview/` directory. Use `pnpm export:preview <directory>` to choose another output directory.

Each HTML embeds its CSS, scripts, fonts, images, and original licensing, retaining the homepage animations and theme switch. Recipients can open either file directly without installing dependencies or running a server. In-page anchors stay local; documentation, article, and non-current-locale links point to `https://www.evox.group`.

## Validation and release status

The current responsive layout skips the opening at widths up to 1000px and shows a text-led hero with vertical actions. The shared header uses the same breakpoint for both its CSS and menu cleanup. The evolution chapter pairs localized copy and five selectable cycle stages on the left with the animated, fixed-orientation candidate ring on the right; mobile layouts stack the copy above the animation. News precedes Explore, which highlights Genesis beside the remaining resource links.

- Production build passed and generated 729 pages.
- All 13 locale JSON files parse and have the same 245 keys.
- Homepage translation keys and linked article paths were checked against locale files and content collections.
- Browser acceptance checks cover desktop/mobile layouts, both themes, navigation and language switching, anchor links, reduced-motion behavior, and contrast on existing content routes.

The redesign is prepared for review on the `ui` branch. Publishing that branch does not merge the changes into the default branch or deploy them to the production website.
