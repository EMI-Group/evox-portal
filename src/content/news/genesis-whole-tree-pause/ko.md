개발 작업은 사용자가 일시 중지를 누를 때 여러 자식 에이전트를 기다리고 있을 수 있습니다. 단지 멈추려고 자식 배치를 완료 처리하면 보존할 작업 자체가 달라집니다. 2026년 11월 25일 Genesis main 변경은 조정된 전체 트리 스냅샷을 도입합니다. 부모는 대기 위치를, 자식은 식별자와 체크포인트를 유지하고, 재개는 같은 작업 ID 아래에서 관계를 다시 구성합니다. [스냅샷 설계와 구현 기록][design]

## 일시 중지는 전역 제한이 아닌 작업 수명 주기

스케줄러 전체의 일시 중지는 새 작업 접수만 멈추며 실행 중인 개별 작업을 영속적인 휴지 상태로 만들지 않습니다. 작업 단위 프로토콜은 pausing을 거쳐 paused로 이동하면서 결과 문맥을 보존하고 종료 시각은 설정하지 않습니다. 취소는 별도 동작이며 일시 중지 도중 들어오면 우선합니다. 대화형 세션은 이 프로토콜의 범위 밖입니다. [레지스트리 통합][registry]

예를 들어 파서와 테스트 모음을 조정하는 에이전트가 두 자식을 기다릴 수 있습니다. 일시 중지는 가짜 완료 결과를 만들지 않고 그 대기를 보존해야 합니다. 조정기는 실행 중인 구성원에 중지 표시를 하고 대기 중인 모델 및 도구 슬롯 요청을 제거하며, 자식 배치를 기다리는 부모를 대기 위치에 세웁니다. 각 에이전트는 도구 배치 이후의 턴 경계 또는 이미 대기하던 위치에서 멈춥니다. [동결 조정기][coordinator]

## 자원을 회수하기 전에 작업 보존하기

에이전트는 멈추기 전에 백그라운드 작업을 정리하고 작업 트리를 체크포인트로 저장하며, 영속적인 미처리 도구 표시를 보존하고 상태를 기록합니다. 체크포인트 커밋은 참조로 고정되어 나중에 작업 트리를 회수해도 사라지지 않습니다. 스냅샷은 에이전트가 턴 경계인지, 자식 대기 중인지, 중단된 배치 안인지 기록합니다. 일시 중지는 자체 결과만 보고하며 미완료 자식을 성공 처리하거나 그 작업을 병합하지 않습니다. [에이전트 동결 경로][agent]

대기에는 한도가 있습니다. 문서의 기본값은 정지 대기 120초에 강제 동결 유예 10초입니다. 모든 에이전트가 중단 없는 영속적 정지를 입증해야 clean pause가 됩니다. 시간이 초과되거나 입증하지 못하면 dirty pause로 기록합니다. 이 구분은 저장한 실행 상태를 설명하며 임의의 외부 부작용을 되돌릴 수 있다는 뜻은 아닙니다.

## 기존 협업 관계 다시 구성하기

재개는 영속화된 옵션으로 같은 작업을 다시 큐에 넣습니다. 영속적인 루트 행이 필요하므로 자식 행만으로는 부족하며, 상태 저장소를 읽을 수 없으면 명시적으로 오류를 냅니다. 복원 계획기는 식별자, 토폴로지, 실행 위치를 다시 구성합니다. 완료된 자식은 저장한 결과를 제공하고, 실행 중이던 자식은 자신의 식별자와 체크포인트로 재시작하며, 등록 전에 동결된 자식은 원래 호출 명세로 시작할 수 있습니다. 부모는 실제 결과가 도착할 때까지 기다립니다. [해동 경로][thaw]

정상적으로 동결된 배치는 중단된 작업에 쓰는 미결 도구 복구 없이 복원됩니다. dirty 스냅샷에는 복구와 재개 알림이 적용되어 완료가 확실한 작업과 실행 여부가 불확실한 작업을 구분합니다. 체크포인트를 입증할 수 없다면 정상 자식 체크포인트로 조용히 채택해서는 안 됩니다. 재시작이나 임대 상태 조정 시 영속화와 루트 행이 있는 running 또는 pausing 작업은 dirty paused 상태가 됩니다. 재개할 수 없는 작업은 기존처럼 임대 만료 실패로 처리됩니다.

## 일시 중지와 재개를 한 번 확인하기

이 커밋들이 포함된 소스 빌드를 사용하고 에이전트 상태 영속화를 켜십시오. 자식이 실행 중인 개발 작업을 중지하고 paused 상태 기록을 기다린 뒤 재개하여 같은 작업 식별자, 자식 관계, 저장 작업이 유지되는지 확인합니다. 외부 작업을 이어가기 전에 dirty pause 알림을 검토하십시오. 영속화가 꺼져 있으면 일시 중지는 거부되며 복구 범위는 영속 체크포인트로 제한됩니다. [이전 작업 워크플로][related]는 프로젝트와 승인 문맥을 설명하고 이번 변경은 미완료 실행을 보존하는 방법을 정의합니다.
