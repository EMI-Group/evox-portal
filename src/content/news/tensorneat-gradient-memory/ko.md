게놈 자체가 메모리에 들어가도 변환 및 평가 작업 배열 때문에 GPU 메모리가 부족할 수 있습니다. TensorNEAT의 [2026년 4월 4일 업데이트][s2]는 변환을 순차 개체군 배치 안으로 옮기고 조회 중간 배열을 줄입니다. 후보 수를 유지하면서 작업 집합을 제어할 수 있습니다.

![서로 다른 신경망이 작은 처리 입구를 묶음으로 통과하는 모습](./cover.webp)

*개념 삽화: 개체군은 유지하고 활성 작업 배치만 제한합니다.*

## 탐색 공간 대신 작업 집합 나누기

4월 변경은 NEAT와 Pipeline에 `pop_batch_size`를 추가합니다. Pipeline 값이 알고리즘 설정을 덮어쓰며 개체 수는 배치 크기로 나누어져야 합니다. 이전 `eval_batch_size` 인수는 대체되므로 기존 설정을 수정해야 합니다.

단일 장치에서는 변환을 `jax.lax.scan` 루프 안으로 옮겨 전체 개체군의 밀집 인접 중간값을 먼저 만들지 않고 배치별 변환·평가를 합니다. 변이도 같은 배치 제어를 사용합니다. 개체군 크기는 유지되고 동시에 필요한 작업 집합만 바뀝니다. 다양성이 필요하지만 GPU 메모리 한계에 도달한 실험에 유용합니다.

핵심은 배치가 시작되는 위치입니다. 전체 개체군을 변환한 뒤 평가만 나누면 큰 인접 중간 배열은 이미 할당된 상태입니다. 두 작업을 scan 본문에 넣어야 수명이 달라집니다. 커밋은 개체군 × 노드 × 노드 배열이 배치 × 노드 × 노드로 바뀐다고 설명합니다. 이는 구현 수준 비교이며 전체 장치 메모리 공식은 아닙니다. 게놈, 영속 상태, 다른 버퍼도 공간을 사용합니다.[변환 변경][s2]

배치 처리는 실행 방식입니다. 생존 후보를 줄이거나 실험이 요청한 개체군 수를 바꾸지 않습니다. 반면 개체군을 줄이면 참여 후보가 바뀌어 탐색 자체가 달라질 수 있습니다. 메모리 부족을 진단할 때 두 설정을 구별하세요. 우선 개체군을 고정하고 작업 배치의 유효한 약수만 바꾸어 비교하면 도움이 됩니다.

## 큰 비교 중간값 없이 조회하기

교차의 중첩 비교는 해시 매칭과 정렬 검색으로 바뀌고 연결 키를 노드 인덱스로 매핑할 때도 정렬·검색을 사용합니다. 개체 수와 네트워크 용량이 함께 커질 때 비싸지는 임시 배열을 줄이는 변화입니다.

커밋은 DefaultGene과 OriginGene 구성에서 고정 시드로 15세대의 동일한 진화 궤적을 보고합니다. 이는 특정 회귀 결과이며 모든 의존성·하드웨어 조합의 궤적을 보장하지 않습니다. 저장소의 정확성·메모리 스크립트로 구현과 주장을 함께 검토할 수 있습니다.

## 재현 가능한 실험으로 배치 선택

작은 함수 근사 문제에서 노드·연결 상한을 고정하고 배치 없는 손실·적합도 순서를 기록합니다. 개체 수를 나누는 배치를 선택하고 먼저 정확성을 비교한 뒤 최대 메모리, 컴파일 시간, 단계 시간을 따로 측정합니다. 작은 배치는 메모리 부담과 동시에 가능한 병렬 작업량을 바꿉니다.

[4월 소스 스냅샷][s4]으로 이름이 바뀐 배치 인수까지 설정 의미를 고정하세요. TensorNEAT는 JAX 기반이며 문서의 EvoX 연동은 JAX 시기의 브랜치를 대상으로 합니다. 측정에 의존성 버전을 기록하세요. 매개변수 개선도 필요한 실험은 별도의 [개체군 기울기 기사][gradient]에서 학습 경로를 확인할 수 있습니다. 먼저 배치를 바꿔도 선택한 실행 결과가 유지되는지 검증한 뒤 메모리와 시간의 절충을 평가합니다.
