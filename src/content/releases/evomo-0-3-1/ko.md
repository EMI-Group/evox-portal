다목적 최적화는 빠른 평가기뿐 아니라 유용한 절충안을 유지하는 선택, 정확한 문제 공식, 재시작 가능한 상태가 필요합니다. 베이징 시간 2026년 10월 8일 공개된 [EvoMO v0.3.1][s1]은 문서를 보강합니다. 주요 알고리즘 확장과 수정은 [9월 24일 v0.3.0][s2]에 포함되었습니다.

![서로 경쟁하는 목적 지형 위에 놓인 다양한 탐색 도구](./cover.webp)

*개념 삽화: 서로 다른 알고리즘이 유용한 절충안을 탐색합니다.*

## 공통 텐서 기반에서 더 많은 알고리즘 비교

v0.3.0은 텐서화 다목적 알고리즘 48개를 추가합니다. 공통 기반은 같은 평가 흐름의 비교를 쉽게 하면서 각 방법의 선택, 변이, 상태 갱신 차이를 유지합니다.

경쟁 목적을 연구할 때 문제, 결정 경계, 개체 수, 평가 예산을 고정하고 알고리즘만 바꿀 수 있습니다. 가치는 다양한 탐색 동작을 이용하는 데 있습니다. 알고리즘 수만으로 특정 과제의 더 좋은 절충안이 입증되지는 않습니다.

## 정확성 수정은 비교 자체에 영향

여러 방법의 개체군 갱신과 선택을 수정합니다. 비지배 정렬은 환경 선택에 필요한 경계 프런트를 완성한 뒤 멈추며, 혼잡 거리는 상수 목적, 작은 개체군, 마스크, 장치 배치를 처리합니다. PyTorch가 기본이고 선택적 Triton은 명시적으로 사용하는 실험 기능입니다. [선택 변경][s3]

ZDT1–4와 ZDT6는 행별 평가 및 ZDT6의 차원 의존 계산을 수정합니다. Monte Carlo 하이퍼볼륨은 최소화, 참조점, 빈 입력, 샘플링 장치를 수정합니다. 기존 연구가 해당 경로를 사용했다면 이전 결과를 보존하고 통제된 비교를 다시 수행해 다른 정의의 값을 섞지 않아야 합니다.

## 제약과 시뮬레이션을 각각 확인

v0.3은 v0.2.2의 제약 벤치마크 86개, 제약 인식 NSGA-II, `UnifiedWorkflow`를 이어갑니다. 후속 수정은 제약 버퍼 지연 등록, 체크포인트 복원, 제약 Pareto 프런트 자료의 배포 포함을 추가합니다. [제약 기준][s4]

MoRobtrol은 Playground/MJX, 과제별 목적과 시각화를 추가하고 관측 정규화·체크포인트를 개선합니다. 로봇 제어 비교에서는 시뮬레이터 설정과 목적 정의도 최적화기처럼 기록해야 합니다. 좋아 보이는 Pareto 집합이 과제나 지표 변경의 결과일 수 있기 때문입니다. [시뮬레이션 및 통합][s5]

## 작은 기준 실험으로 업그레이드

[버전 설치 안내][s6]에 따라 EvoX를 먼저 설치합니다. `pip install evox` 다음 `pip install evomo==0.3.1`을 실행하고 해결된 의존성을 기록합니다. 소스 설치는 v0.3.1 태그를 고정할 수 있습니다. 패치는 문서를 추가하며 기능 변경은 v0.3.0 설명을 참고합니다.

큰 벤치마크 전에 알려진 목적 계산, 작은 선택 사례, 필요한 상태 복원을 확인합니다. 제약에서는 실행 가능성과 품질을 함께, 하이퍼볼륨에서는 같은 참조점과 샘플링을 유지합니다. [GPU 다목적 연구 소개][related]는 텐서화의 의미를 설명하고 v0.3은 더 넓고 명확한 실험 기반을 제공합니다.
