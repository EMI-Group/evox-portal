과학 소프트웨어를 다시 쓰려면 알고리즘 이상의 것을 이어받아야 합니다. 이후 계산이 의존하는 수치 동작도 유지해야 합니다. Genesis의 MESA 사례에서는 Fortran 모듈 13개를 Rust crate로 재개발하고 원래 출력을 기준으로 삼았습니다. 핵심은 그 연속성을 어떻게 검증 가능한 형태로 만들었는가입니다.

![층을 드러낸 항성 조형물 아래에 같은 윤곽을 가진 서로 다른 재질의 두 고리](./mesa-numerical-continuity.webp)

*개념 일러스트: 새로운 구현과 공유하는 수치 기준.*

## 13개 모듈로 연결된 수치 계산 체계

[2026년 9월 7일 Evidence 기록](https://genesis.evox.group/evidence/mesa/)은 **13개 모듈, Fortran 139,414줄에서 Rust 89,946줄**을 보고합니다. 스냅샷 규모이며 저장소의 라이브러리 전용 줄 수와는 다릅니다.

보간, 솔버, 반응 네트워크, 상태 방정식, 불투명도 등의 수치·물리 모듈이 대상입니다. MESA 전체를 대체하지 않으며 항성·쌍성 진화 엔진 등 문서에 명시된 구성 요소는 범위 밖입니다.

## 빌드뿐 아니라 계산 과정 확인하기

모듈마다 Rust crate가 있고 인터페이스와 제약을 기록합니다. 골든 테스트는 원래 Fortran 출력과 비교하며 통합 테스트는 모듈 사이 동작을 확인합니다.

수치 동등성에는 허용 오차와 과제가 필요합니다. 스칼라 결과 일치만으로는 해법 경로 차이를 놓칠 수 있어 단일 구역 연소 대리 과제의 적분 단계 동작도 기록합니다. 빌드 성공보다 유용한 이식 근거입니다.

## 테스트 기록에 담긴 내용

저장소는 **1,052개 통과, 실패 0개, 무시 18개**를 보고합니다. 무시한 항목에는 벤치마크 테스트와 오래 걸리는 전체 시간 구간 연소 작업이 포함됩니다. Evidence의 **미화 10.64달러**는 하드웨어를 제외한 모델 토큰 비용이며 모델명, 에피소드 수와 경과 시간은 제시되지 않았습니다.

독립 재현 없이 출처가 보고한 단일 실행 결과입니다. 문서에 명시된 모듈과 작업 범위부터 살펴볼 수 있습니다.

## 두 스냅샷과 서로 다른 속도 향상 수치

[Evidence](https://genesis.evox.group/evidence/mesa/)는 중앙값 **1.55–6.87배** 가속을 보고합니다. 별도로 8월 5일 README 표는 15회 실행 중앙값을 사용하며 종단 간 단일 구역 연소 대리 과제는 **1.25배**입니다. [README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md#latest-verified-results-2026-08-05-15-run-medians-taskset-0-3)

단일 구역 연소 대리 작업에 대해 README는 두 구현 모두 **적분 단계 199회, 수락 198회, 거부 1회**라고 기록합니다. 이 동작과 출력 허용 오차를 함께 비교하면 수치 경로가 다른 계산의 시간만 재는 것보다 속도 향상의 의미를 잘 이해할 수 있습니다.

## 범위를 넓히기 전에 작업 하나 재현하기

[README](https://github.com/EMI-Group/genesis-demo-mesa-rs/blob/2ad071e658f8d4de21aa9f0e906592c364e10023/README.md)에 도구 체인, 빌드, 테스트, 벤치마크 절차가 있습니다. 환경 준비 후 테스트 진입점은 다음과 같습니다.

```bash
cargo test --workspace
```

연구와 관련된 작업을 골라 [MESA 재개발 저장소](https://github.com/EMI-Group/genesis-demo-mesa-rs)에서 기준 출력, 허용 오차와 벤치마크 드라이버를 살펴보세요. [Genesis 소개](/ko/news/evox-genesis)는 에이전트 개발의 배경을, 이 사례는 재작성 후 필요한 동작이 보존되었는지 확인하는 구체적 방법을 제공합니다.
