하나의 기능이 API 서비스, 클라이언트 앱, 공용 라이브러리에 걸칠 수 있습니다. 목표는 같아도 Git 저장소는 다를 수 있습니다. 2026년 9월 26일 출시된 Genesis 0.13.4는 쓰기 가능한 연관 저장소에 지속적인 작업 트리를 추가해 저장소 간 작업의 실행 경계를 명확히 했습니다.

## 코드 접근에서 작업 격리로

0.11.4는 추가 저장소 읽기·쓰기, 저장소별 검토, 읽기 전용 저장소의 쓰기 제한을 도입했습니다. 0.13.4에서는 각 연관 저장소의 지속적인 작업 트리에서 에이전트가 작업하므로 주 HEAD나 기본 작업 트리를 건드리지 않습니다.

해당 저장소의 경로는 작업 트리를 기준으로 해석합니다. 초기 컨텍스트가 그 위치를 보여 주며 저장소 간 위임도 이를 기준으로 합니다. 저장소의 디렉터리 구조가 다르거나 다른 개발 활동이 진행되어도 변경 위치가 명확합니다.

## 통합 결정은 저장소별로 유지됩니다

0.13.0은 개별 병합·거부 버튼, 병합 검사와 처리 상태를 갖춘 검토 카드를 도입했습니다. 전체 병합 기능은 미처리 저장소를 함께 수락하면서도 개별 결과를 보여 줍니다. 연관 저장소만 바뀐 작업의 검토 흐름도 수정했습니다.

API 변경이라면 서비스, 클라이언트, 라이브러리의 기여를 각자의 이력에서 검토할 수 있습니다. 호환되는 인터페이스와 적절한 테스트는 여전히 필요합니다. 여러 저장소를 병합하는 기능이 원자적 트랜잭션이나 프로젝트 간 호환성을 자동 보장하지는 않습니다.

## 더 큰 소프트웨어 시스템을 위한 기반

중요한 것은 변경 생성뿐 아니라 작업 조직입니다. Genesis는 사용자가 검토하고 수락하는 위치를 유지하면서 저장소 경계를 넘는 기여를 조율합니다. 독립적으로 유지되는 여러 구성 요소로 EvoX의 소프트웨어 진화 방향을 확장하고, 수락된 버전을 다음 개발의 출발점으로 삼습니다.
