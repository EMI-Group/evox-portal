探索対象がプログラムそのものであるとき、最終出力だけのデバッグでは実験の多くが見えません。EvoX Compiler はプログラム自体を検査可能にします。グラフを保持して変換し、明確に分かれた段階を通じて実行バックエンドを選択できます。

![浮かぶグラフ層が整列した構造と小さな赤い成果物へ変わる](./evoxc-visible-stages.webp)

*概念イラスト：定義と実行の間にあるプログラム構造を可視化。*

**EvoX Compiler（evoxc）v0.1.0** は2026年10月29日に公開されました。Python のテンソルグラフ・フロントエンドとランタイムで、Python 3.11 以降を必要とし、Apache-2.0 ライセンスを採用しています。 [v0.1.0](https://github.com/EMI-Group/evoxc/releases/tag/v0.1.0)

## 定義から検査可能な実行オブジェクトへ

流れは `trace → lower → compile → load → run` です。定義と入力仕様から EvoXIR グラフを構築し、バックエンド表現へ変換、成果物へコンパイル、デバイスにロードした後、実データで実行します。各段階のオブジェクトを確認できます。

不正なグラフ、未対応の変換、デバイス不一致を切り分けやすく、グラフや対応成果物も保存できます。最適化、スケジューリング、コード生成は外部コンパイラが担当し、evoxc はフロントエンドと段階間の契約を提供します。

## プログラム集団を一つのグラフへ

`vmap`、`grad`、`jvp`、`vjp` は実行前に合成できるグラフを生成します。[`batch_functions`](https://github.com/EMI-Group/evoxc/blob/v0.1.0/README.md#batch-transformation--one-graph-for-a-whole-population) は入出力仕様が一致する候補関数を一つの集団グラフにまとめます。

遺伝的プログラミング、アーキテクチャ探索、アルゴリズム合成では、候補はパラメータだけでなくプログラム自体です。統合によってコンパイルや呼び出しの反復を減らせますが、効果は構造とバックエンド次第で、必ず高速化するわけではありません。

## 必要な演算に合わせてバックエンドを選ぶ

必須依存は NumPy のみで、参照 CPU インタープリタを提供します。任意のアダプタで IREE、利用者の PJRT プラグイン経由の XLA、StableHLO フロントエンド経由の TVM に接続します。算子・ハードウェア対応は同一ではありません。

当該 README の Vulkan 検証はソフトウェアデバイス Mesa lavapipe、TVM ROCm はコンパイルのみです。GPU 入力と配置は明示的に扱います。CPU から移行する前に対応算子を確認してください。

## CPU から始めてグラフを移す

固定バージョンを導入し、README の CPU 例でグラフを調べてからコンパイルバックエンドを選びます。

```bash
pip install evoxc==0.1.0
```

HuggingFace 統合は別パッケージ `evoxc-hf` としてインストールし、独自の配布・更新サイクルを持ちます。

## 検証結果を実行環境と併せて読む

文書に記載された追加依存関係を導入した環境で、リリース README はコア・統合テストの **7,511 件成功、77 件スキップ、4 件の期待された失敗**、想定外の失敗なしを報告しています。スキップにはハードウェアや依存関係の条件確認が含まれます。リポジトリはコード、テスト、文書を Genesis が生成したと記しています。
