EvoX Compiler v0.2.3은 2026년 11월 25일 UTC에 Python wheel과 소스 압축 파일로 공개됐습니다. 짧은 GitHub 설명은 v0.2.2와 v0.2.3의 비교로 연결되며, 버전이 고정된 변경 이력에는 이번 배포에 이르는 0.2 계열의 주요 변경과 패키징 수정이 기록되어 있습니다. 0.1에서 옮기는 사용자는 컴파일러와 런타임 조합, 물리 장치 선택, 다시 확인할 수치 동작에 주목해야 합니다. [릴리스][release] · [변경 이력][changes]

*개념 삽화: 사용할 수 있는 배포본은 실행 환경과 맞아야 합니다.*

## 컴파일러와 런타임을 함께 맞추기

IREE 추가 의존성은 이제 컴파일러와 런타임 모두 3.13.0 이상 3.14 미만을 요구합니다. 컴파일 산출물은 버전에 종속되므로 다른 조합으로 만든 파일을 그대로 불러올 수 있다고 가정해서는 안 됩니다. 상위 프로젝트는 llvm-cpu와 ROCm 7.1을 사용하는 AMD Instinct MI300X의 ROCm/HIP를 재검증했으며, 이전 IREE에서 실패했던 루프와 스캔도 포함했습니다. 이 검증이 CUDA, 다중 rank 실행, 모든 모델 벤치마크까지 포괄하지는 않습니다. [버전별 요구 사항][requirements] · [변경 이력][changes]

어댑터는 런타임의 간편 경로에 전적으로 의존하지 않고 장치에서 호스트로 결과를 읽는 과정도 제어합니다. 계산은 정상인데 결과를 가져올 때 실패하는 경우에 중요한 변화입니다. 호스트 메모리는 매핑 경로를 유지할 수 있지만 장치 버퍼에는 명시적인 전송이 필요합니다. 애플리케이션 워크로드를 평가할 때 전송 시간을 포함하되 커널 시간과 분리해서 측정하십시오.

## XLA 플러그인을 찾은 뒤 올바른 장치 선택하기

XLA 등록은 호출자가 경로를 전달하기 전에 옵션 없는 플러그인 탐색을 실행하지 않습니다. 검색은 명시적 플러그인 옵션, 해당 환경 변수, 알려진 위치, 설치된 JAX 플러그인 패키지를 고려하며 JAX 자체를 가져오지 않습니다. 사용 가능 여부는 옵션이 준비된 컴파일 및 로드 시점에 확인합니다. 빌드 도우미도 해석된 옵션을 로드에 전달하여 컴파일에서는 찾았던 플러그인 설정이 로드에서 사라지는 문제를 해결합니다. [백엔드 안내][guide]

ROCm 플러그인은 ROCm 장치, CUDA 플러그인은 CUDA 장치를 사용해야 합니다. GPU 플러그인을 주면서 기본 CPU 선택을 유지하면 거부됩니다. GPU 실험에서는 대응 장치를 선택하고 텐서를 명시적으로 옮기십시오. 호스트로 결과를 복사하기 전에 출력 위치를 확인해야 합니다. XLA 실행이 실패하면 캐시된 출력 포인터 슬롯도 비워 다음 호출이 오래된 버퍼 포인터를 재사용하지 않게 합니다.

## 속도 비교 전에 수치 의미 확인하기

NumPy 참조 인터프리터는 디스패치 계획을 캐시하고, 마지막 사용이 끝난 중간값을 해제하며, 불변 호스트 장치 인스턴스를 공유합니다. 공개 호출 방식을 바꾸지 않고 준비와 할당 비용을 줄이는 변경입니다. 변경 이력의 TensorNEAT 측정은 특정 워크로드에 관한 것이며 일반적인 가속 배수가 아닙니다.

컴파일된 나머지 연산은 이제 NumPy floormod를 따라 결과 부호가 제수와 같아집니다. 따라서 음수 입력은 유용한 업그레이드 검사입니다. 고정 입력과 참조 출력을 보관한 뒤 자료형에 맞는 허용 오차로 인터프리터와 컴파일러 결과를 비교하십시오. 패키징 수정은 maturin이 포함하는 공유 라이브러리 디렉터리를 허용하고 검증한 배포 파일을 평평한 구조로 준비하여 산출물 공개를 막던 실패를 해결합니다. [수정 기록][changes]

## 깨끗한 환경에서 업그레이드하기

Python 3.11 이상이 필요합니다. 릴리스 자산에서 고른 0.2.3 wheel을 pip로 설치하십시오. Linux, macOS, Windows wheel 및 소스 압축 파일을 제공합니다. `pip install "evoxc[iree]==0.2.3"`으로 IREE 추가 의존성을 설치하고 컴파일러와 런타임이 맞는지 확인합니다. 별도 배포인 evoxc-hf는 자체 버전을 유지합니다. `pip check`와 설치 버전 확인 후 대표 그래프, 음수 나머지 사례, 장치 왕복 전송을 각각 점검하고 더 큰 워크로드를 옮기십시오. [설치 안내][guide]

이 백엔드와 관련된 그래프 변환, 사용자 정의 연산, 명시적 컴파일 단계는 이번 릴리스 문서와 함께 [사용자 정의 컴파일 기사][related]에서 확인할 수 있습니다.
