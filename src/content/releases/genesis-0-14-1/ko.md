모델을 선택한다는 것은 비용을 부담할 계정, 인증 정보, 작업에 전달할 추론 설정도 선택한다는 뜻입니다. **2026년 11월 8일 정식 출시된 Genesis 0.14.1**은 이 식별 정보를 Settings, Projects, Assistant, 스케줄러와 런타임 전반에서 일관되게 유지합니다. 원격 실행을 헤드리스 서버로 통합하고 런타임 점검을 더 세밀하게 제어하는 기능도 추가했습니다. [전체 릴리스 노트][release]

![선택한 계정 탭과 해당 모델 선택지가 연결된 모습](./provider-account-continuity.webp)

## 계정은 한 번 설정하고 작업은 구체적으로 선택하기

Provider profile은 인증, 엔드포인트, 동시 실행 수와 일정을 보관합니다. 하위 모델 목록에는 해당 계정에서 사용할 모델과 모델별 생성·추론 설정을 둡니다. 작업에는 인증 정보 없이 프로필 ID, 모델 ID, 선택적 추론 강도만 전달됩니다. 구체적으로 선택하면 이후 실행에서도 이 조합이 고정되고, **Auto**는 설정된 규칙에 선택을 맡깁니다.

예를 들어 업무용 계정의 두 모델은 동시 실행 슬롯과 속도 제한 시 대기 정책을 공유합니다. 모델을 추가해도 별도 할당량 풀이 생기지 않습니다. 개인 계정에는 별도 인증과 일정을 둘 수 있습니다. 서로 다른 API key가 필요하다면 프로필 ID뿐 아니라 인증 정보 이름도 구분해야 합니다. [프로필 설정과 선택 규칙][profiles]

선택할 모든 모델을 `[[llm.providers.models]]`에 등록해야 하며 `default_model`만으로는 충분하지 않습니다. 기본 추론 강도와 지원 강도 목록도 별도입니다. 대시보드는 목록이 비어 있지 않고 기본값을 찾지 못하면 첫 항목을 선택하지만, 코어 API에서 강도를 생략하면 매개변수 자체를 보내지 않을 수 있습니다. 프로필을 바꾼 뒤 모델과 강도를 다시 확인하십시오.

이번 버전은 작업·에이전트·시스템 계층 사이에서 명시적 선택이 사라지는 문제, 스케줄러 대체 풀, 불완전한 모델 설정 스냅샷으로 발생하는 `:model_spec_schema_unavailable`을 수정했습니다. 보관된 설정은 JSON에 안전한 형태로 저장하며 인증 정보를 가립니다. 새 작업뿐 아니라 저장된 설정을 다시 사용하는 경우에도 중요한 수정입니다.

## 구독 로그인도 계정 설정을 따르기

지원되는 프로필에 OAuth/구독 인증과 프로필별 로그인 상태가 추가됐습니다. Genesis는 공급업체 CLI 로그인 파일을 ReqLLM이 사용하는 관리형 인증 파일로 가져옵니다. `openai_codex`는 OAuth 전용이며, Anthropic 구독 프로필은 `auth_mode = "oauth"`를 사용합니다. 버전별 가이드는 계정을 실제로 사용할 노드에서 `codex login` 또는 Claude CLI 로그인을 수행하는 것부터 안내합니다. [구독 인증 설정][oauth]

기본 관리 파일은 `config.toml` 옆의 `auth.json`입니다. 사용자 지정 `oauth_file`은 provider profile에 설정하며 전역 `[llm] oauth_file`은 제거됐습니다. 새 관리 파일은 `0600` 권한을 사용하고 가져오기는 원자적으로 이뤄집니다. 파일에는 provider당 하나의 항목이 있으므로 프로필 ID만 다르게 지정해도 여러 구독 로그인이 분리되는 것은 아닙니다.

원격 작업에서는 원격 노드의 로그인 상태를 확인해야 합니다. 공급업체 로그인은 있으나 관리 파일 대상이 읽기 전용이면 프로필에 쓰기 가능한 비공개 경로를 지정하십시오. 다시 로그인해도 쓰기 권한 문제는 해결되지 않습니다. 환경 변수로만 제공한 OAuth token은 자동 갱신할 수 없습니다. 개선된 상태 메시지는 이 경우들을 구분합니다.

## 원격 실행과 대시보드를 하나의 서버로

별도 `genesis_remote` 배포판은 폐지됐습니다. 원격 명령과 부트스트랩은 공통 `genesis_server`를 사용합니다. HTTP는 항상 사용할 수 있고 Erlang distribution은 SIGHUP으로 시작하는 파일 프로토콜을 통해 실행 중 전환할 수 있습니다. CLI는 `genesis remote start`, `stop`, `status`, `logs`를 제공합니다. [서버 및 설치 안내][readme]

노트북에서 대시보드를 유지하고 SSH 호스트에서 실행하는 경우 서비스 관리가 달라집니다. 예전 배포판을 참조하는 스크립트를 검토하고 공통 서버를 관리해야 합니다. 원격 프로젝트 테스트와 호출 시 테스트 실행 재개도 지원합니다. 헤드리스 HTTP 서버는 기본적으로 localhost에서 수신하며 인증이 내장되어 있지 않습니다. 문서의 원격 접근 방식은 SSH 터널입니다.

## 긴 실행 중 상호작용을 복구하기 쉽게

계층형 중개 Elixir 평가기에 정확한 코드에 대한 승인과 채팅에서 복구 가능한 승인이 추가됐습니다. 출력이 남은 예산을 넘으면 실패하는 대신 잘라 냅니다. 턴 제한 뒤의 짧은 복구 구간, 도구를 호출하지 않는 최종 응답, 짧은 순차 작업 ID, OpenAI/Codex GPT 호출에서 에이전트 실행별로 안정적인 프롬프트 캐시 식별 정보도 포함됩니다. 대시보드에는 통합 캡슐 패널과 공통 작업·모델 컨트롤이 추가됐습니다. [변경 및 수정 사항][release]

## 설정을 보면서 업그레이드하기

1. [v0.14.1][release]에서 대상 플랫폼용 설치 파일이나 서버 자산을 받으십시오. 계정 구조를 바꾸기 전에 기존 설정을 백업합니다. 예전 `[[llm.models]]`는 호환 입력으로 유지되지만 표준 provider profiles가 우선하며, Settings/설정을 명시적으로 저장할 때 마이그레이션합니다.
2. **Settings → LLM → Provider profiles**에서 인증, 하위 모델 목록, 기본 추론 강도, 사용자 지정 `oauth_file`을 확인합니다. 원격 서버를 포함해 작업 실행 프로세스가 인증 정보에 접근할 수 있어야 합니다.
3. 헤드리스 서버를 재시작한 뒤 `genesis status`를 확인합니다. 명시적인 프로필·모델·강도 선택, Auto 선택, 실제 원격 연결도 점검하십시오. 예전 데몬 스크립트는 재사용 전에 검토합니다. 이는 문서에 기록된 변경에서 도출한 업그레이드 확인 항목입니다.
