대화, 개발 작업, Git 변경 사항을 오갈 때마다 프로젝트 맥락을 다시 만들 필요는 없어야 합니다. 2026년 11월 20일 `main`에 병합된 Genesis PR #175는 프로젝트 탐색, 탭, 작업·대화 기록, Git 패널, 통합 설정을 갖춘 LiveView 워크벤치를 도입합니다. 관련 워크스페이스와 초안 범위 변경은 선택한 프로젝트의 식별 정보를 여러 화면에 걸쳐 유지합니다. [병합된 통합 변경][pr]

![공용 작업대의 개별 프로젝트 서랍에 각자의 메모와 도구가 보관된 모습](./cover.webp)

*개념 삽화: 프로젝트마다 고유한 작업 맥락을 유지합니다.*

## 한곳에서 프로젝트 확인하기

워크벤치는 탐색과 작업 화면을 연결합니다. 프로젝트로 돌아와 작업이나 대화 기록을 확인하고 Git 변경을 살펴볼 때 화면마다 다시 시작할 필요가 줄어듭니다. 기존 워크스페이스 선택기, 계정 설정, 작업 일시 중지·재개 흐름은 유지됩니다. 재연결 시 승인 맥락도 복구합니다. 이는 [기존 Assistant 작업 흐름][previous]을 확장하는 연속성 개선이며, 허용되는 동작은 여전히 구조화된 승인이 결정합니다. [워크벤치 통합][pr]

라이브러리와 이를 사용하는 애플리케이션을 번갈아 개발한다고 가정해 보겠습니다. 애플리케이션 탭을 열어도 라이브러리 요구사항 초안은 해당 라이브러리에 남아 있어야 합니다. Git 작업 역시 선택한 프로젝트의 서버와 저장소를 대상으로 해야 합니다. 병합된 변경은 Git 동작 전에 프로젝트 소속을 확인하며, 연결할 수 없어도 선택한 노드를 유지하고 대시보드 호스트로 작업을 돌리지 않습니다.

## 초안의 식별자는 경로만이 아닙니다

공유 `DraftScope`는 브라우저 초안을 `{node, token}`으로 정의합니다. Virtual Context Tree에 마운트된 프로젝트는 `vct:///projects/<name>` 지점을 사용하고, 아직 마운트되지 않았다면 운영체제의 절대 경로를 사용합니다. 둘 다 있으면 VCT 지점이 우선합니다. 따라서 같은 마운트 프로젝트의 다른 경로 표기가 하나의 초안으로 연결되고, 같은 경로 위의 서로 다른 VCT 지점은 분리됩니다. [초안 범위 구현][scope]

브라우저 저장 키는 노드와 토큰을 결합합니다. 후속 수정은 VCT 지점이 생기면 경로 기준 초안을 인계하여 디렉터리 선택에서 프로젝트 등록으로 넘어가는 과정을 처리합니다. 이는 브라우저 초안의 연속성이며, 작업 영속성이나 서버 재시작 후 대화의 영구 복구 보장과는 구분됩니다. [초안 인계 수정][adopt]

원격 프로젝트에서는 경로를 그대로 유지하는 것도 중요합니다. 대시보드가 브라우저 호스트의 파일시스템 규칙으로 경로를 정규화해서는 안 됩니다. 복구된 초안을 제출하기 전, 특히 로컬과 원격 프로젝트 사이를 전환한 뒤에는 노드, 저장소, 모델을 확인하십시오.

## 워크스페이스는 묶음이며 작업에는 실제 디렉터리가 필요합니다

VCT에 `vct:///workspaces/<name>` 그룹 계층이 추가되었습니다. 워크스페이스에는 순서가 있는 구성원 목록과 선택적 설명이 있습니다. 구성원은 프로젝트 마운트 지점 또는 운영체제 경로를 참조하고, 워크스페이스는 중첩되지 않습니다. Projects 팔레트와 Assistant 선택기에 그룹을 표시하며, 읽기 전용 API로 구성원을 확인할 수 있습니다. [운영 인터페이스][workspace]

그룹 자체에는 실행 디렉터리가 없습니다. 따라서 워크스페이스만 선택하면 `DraftScope.path/1`은 경로를 반환하지 않고, 작업 접수도 VCT 지점을 작업 경로로 거부합니다. 라이브러리와 앱을 함께 탐색하도록 묶은 다음, 개발 작업을 시작할 때는 실제 작업을 받을 구성원 프로젝트를 선택해야 합니다. 그룹화가 모든 구성원을 암묵적인 쓰기 대상으로 만들지는 않습니다.

소스 체크아웃에서는 `mix vct.workspace list`와 `mix vct.workspace show <name>`으로 그룹을 확인합니다. 문서의 `create` 명령은 반복되는 `--member`와 선택적 `--data-dir`을 받습니다. 대상 Genesis 인스턴스의 데이터 디렉터리를 사용하십시오. 누락된 구성원은 조용히 제외하지 않고 보고합니다. 그룹을 바꾸기 전에 연결된 명령 규약을 확인하십시오.

## 화면 사이의 인계를 검증하기

PR에는 작업 생성과 완료, Assistant 키보드 제출과 스트리밍, 계정 설정 화면에 대한 브라우저 검증이 기록되어 있습니다. 프로젝트로 범위를 제한한 Assistant 작업 조회가 시간 초과된 기록도 있습니다. 장시간 작업에서는 요청 접수와 결과 관찰이 서로 다른 사건이라는 점이 중요합니다. [검증 기록][pr]

변경을 포함한 빌드에서 두 프로젝트에 서로 다른 초안을 남기고, 선택 노드를 다시 연결한 뒤 대상 프로젝트의 Git 패널을 열어 보십시오. 초안이 올바른 프로젝트로 돌아오는지, 승인이 실제 실행 대상을 가리키는지 확인합니다. 이후에는 기록된 작업 상태를 따라가며, 탭 복구 자체를 백그라운드 작업 완료의 증거로 보지 않아야 합니다.

2026년 11월 27일 main에 병합된 PR #178은 기존 프로젝트 선택기를 개선합니다. 최근 프로젝트를 먼저 표시하고 폴더 탐색을 지원하며 수동 경로 입력은 접힌 상태로 유지합니다. 선택은 현재 초안을 보존하고 대화상자를 연 대화에 연결되므로 오래된 대화상자가 다른 대화를 바꿀 수 없습니다. Windows의 컴퓨터 버튼은 선택 노드의 드라이브 루트를 탐색합니다. 내부 프로젝트 알림은 화면 대화에서 숨기지만 모델에는 문맥을 전달하며, 첫 전송 시 중복 기록도 방지합니다. 프로젝트를 바꾼 뒤 History가 새 범위를 확정한 후 결과를 확인하십시오.
