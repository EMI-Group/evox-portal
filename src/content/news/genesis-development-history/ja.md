エージェントツリーは現在の作業者を示します。プロジェクトの履歴には、作業後に何が残ったかを示す役割もあります。2026年9月26日公開の Genesis 0.13.4 は、0.13.2 のコミット履歴表示と 0.13.3 の永続参照を発展させ、一時的な活動を確認可能なソフトウェアの版と結び付けます。

## 稼働中のエージェントから永続参照へ

タスク単位の履歴 API は永続参照と基準コミットを解決し、回収済みエージェントのコミットも時間軸表示に残します。従来の API は複数リポジトリのコミット範囲と参照を照会し、タスク層が特定の開発を追い続けるための文脈を与えます。

モジュールを委任したエージェントが終了しても、その貢献のレビューは必要な場合があります。Git 履歴は変更の識別情報を保ち、タスク表示は全体の中でそれを見つける助けになります。一回の実行終了で、タスクと成果コードの関連まで失う必要はありません。

## 貢献の関係を表示する

0.13.4 はエージェント別レーンにコミットを並べ、同じサブツリーをまとめ、委任とマージの関係を示します。所有者のないコミットには中立レーンを使います。選択、ホバー連動、キーボード操作を備え、一部リポジトリの取得失敗でも全体表示は消えません。

100コミットの表示上限で履歴が切られた場合は、その旨を示します。開発をたどるための表示であり、無制限のアーカイブや全判断の完全な説明ではありません。

## 選択を支える追跡可能性

グラフは変更元とブランチへの統合を示せますが、正しさは証明しません。差分、テスト、レビューが必要です。EvoX のソフトウェア進化において、提案された貢献と残された版の関係を見えるようにし、次の開発に何を引き継ぐかを判断しやすくします。
