長時間の開発作業には、再起動ボタンだけでなく、どのエージェントが働き、何を学び、どのファイル状態を復元できるかという記録が必要です。2026年11月19日公開の [Genesis 0.14.3][release] は、タスク単位の一時停止・再開、永続エージェント状態、明確なライブ活動表示と、設定・承認・デプロイの改善をまとめています。

![枝分かれした機械の木が、それぞれ固定された基部に再接続する](./whole-tree-resume.webp)

*概念図：タスクの復旧は、各枝を固有の保存状態へ再接続することです。*

## キャンセルせずに一つのタスクを止める
実行中のタスクは `pausing` を経て `paused` になります。エージェントは実行中のツールバッチを終え、会話のチェックポイントを保存し、作業ツリーをコミットしてから停止します。一時停止したタスクは表示と再開が可能なままで、完了やキャンセルにはなりません。再開には同じタスク ID を使います。

複数エージェントによる実装を別の作業時間へ持ち越す場合に役立ちます。状態の永続化を有効にして一時停止を要求し、停止済みになるまで保存完了と判断しないでください。永続化は既定で有効で、`genesis_start_task` の `persistent_state` でも制御できます。対話セッションは一時停止できず、永続化を無効にしたタスクは再開できません。[当該版の実装][pause] はルートエージェントの永続レコードも要求します。子の記録だけでは目標を再開できません。
## ファイルの復元範囲を明示してツリーを戻す
独立した SQLite ストアが各エージェントの会話、実行 ID、ツールと子エージェントのバッチ進捗を保持します。ツリー全体の再開時、完了した子は保存済み結果を渡し、実行中だった子は自身の永続チェックポイントと作業ツリーの基点から続行します。安定した ID が関連付けを維持し、ID が使用済みなら警告付きの代替処理を行います。

`refs/genesis/agent-state` 配下の Git 参照は、作業ブランチの回収後もチェックポイントのコミットを到達可能に保ちます。正常な一時停止なら、記録された停止コミットから作業ツリーを再構築できます。中断後の[再開通知][notice] は保証できるチェックポイントを示します。終了した実行の未コミット変更は保存が保証されません。チェックポイントがなければ、タスクの基点へ戻ったことを通知します。

ファイル編集やジョブ起動の途中だったタスクでは、操作を繰り返す前に、示されたコミット、`git status`、`job_list` を確認してください。中断したツール呼び出しには、架空の成功結果ではなく修復情報が入ります。子エージェントの重複生成、対話セッションが異常停止タスクとして復元される問題も修正し、ターン上限からの復旧を改善しています。
## アイドルに見えていた処理を可視化
インスペクターと Assistant はライブ活動と原子的な監視スナップショットを読み取ります。コンテキスト圧縮と次ターンの準備には専用の実行中フェーズがあり、アイドルとは表示されません。Context Memory ではライブ呼び出しを末尾行に表示し、過去の推論は静的に保ちます。静かな待機時間を理解し、圧縮とリクエスト停止を区別しやすくなります。

スケジューラー所有のツール許可が並列呼び出し数を制限し、バックグラウンドへの引き継ぎ中も所有権を維持します。放棄された起動は拒否され、タイムアウト後の封じ込め処理はツールタスク停止前に完了します。ジョブ完了通知と OS 状態確認はレジストリーをブロックする経路から外れ、セッション終了も同期永続化バリアを避けます。チェックポイント書き込みはキュー内の処理をまとめ、滞留量とペイロードを制限して、ストレージ負荷が全エージェントを止めないようにします。
## 設定と承認を明確に
スキーマに基づく設定 API は部分更新に対応し、Assistant は設定の発見と読み取り専用のプロジェクト検索を行えます。承認ダイアログと通知は要求者の ID、権限、実行状態を示します。通知範囲、フォーカス、許可プロンプト、動きを減らす設定への対応も改善されました。

プロジェクトを認識する Assistant セッションは、独立した会話、アップロード、タスク追跡を本版に含みます。詳細は[プロジェクトワークフローの記事][workflow]を参照できます。明示的なローカルスキル一覧コマンドはツール権限確認を省略でき、エージェントがコミットしなかった場合や失敗した場合には自動コミットが補います。
## 更新後に復旧状態を確認
既存のヘッドレスサーバーでは、[当該版の更新ガイド][update]が次を説明しています。
```bash
genesis update --check
genesis update
```
更新がある場合、確認コマンドの終了コードは 10 です。更新前に実行中の作業を完了させてください。更新処理はサーバーの活動を確認し、新版を準備して再起動し、健全性を検証します。新版では一時停止処理中のタスクは更新を妨げますが、停止済みタスクは再開可能なまま更新を妨げません。Release には Linux x64、Linux ARM64、macOS ARM64 の新規インストール用パッケージがあります。

データベース更新は通常のマイグレーションを使用し、独立した履歴整合処理は不要になります。古い ID の競合は追加的に調整し、残存または不完全なマイグレーション状態は拒否します。SQLite 修復経路は開発専用です。未使用の再開ヘルパーと完了エイリアスが公開 API から削除されたため、独自連携では確認が必要です。

依存関係には multipart 長さ制限のセキュリティ修正を含む Plug 1.20.4 と ReqLLM 1.31.0 が入り、Nix の依存ハッシュと事前確認も更新されています。更新後はサーバーの版と健全性を確認し、小さな永続タスクを停止、チェックポイント確認、同一タスクの再開という順で試し、子の結果と活動表示を確認してください。環境固有のマイグレーション診断は[完全なリリースノート][release]と照合できます。
