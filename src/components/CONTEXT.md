# src/components/

## Intent
Shared site chrome, decorative SVG components, and page-body components for the Astro 7 EvoX Portal. Layout renders Header, main content, and Footer as siblings. HomeContent uses `<Layout fullBleed>` to retain shared chrome while omitting the main element's header padding. Its opening hands off to the shared upper-left header brand. RuntimeContent and EcosystemContent use standard padded Layout content.

## API Surface
- **BrandMark.astro** — `size?: number` (default 29px). Server-rendered SVG port of liangfang-wen's public Genesis commit `bbb8c45`, retaining all 18 paths, 23ms sweep steps, 150ms easing, and permanent red diagonal. Used directly in Footer and Explore, and inside BrandWordmark for Header, the homepage opening, and hero. Colors respond to `html[data-theme]`; reduced motion disables transitions. Decorative SVGs rely on the parent element's accessible name.
- **BrandWordmark.astro** — No props. Combines the supplied `新版本evox-svg.zip` vector EVO lettering, its original gradient, and source proportions with the existing animated BrandMark X. The source is preserved in `../assets/brand/evox-wordmark-source.svg`. The responsive wrapper fills its parent's width; each instance generates a unique gradient ID. Theme colors adapt through SVG stops and the X's existing per-path sweep. The opening, hero, and header share identical vector geometry for a precise flying-logo handoff. The wrapper and SVG are decorative, with accessible naming supplied by their parents.
- **Header.astro** — `locale?: Locale`, `localePath?: string`; legacy `animated?` and `sticky?` props remain declared but have no behavior. The header is fixed and 64px tall. The brand remains on the left, followed by navigation and actions in matching DOM and keyboard order. The full wordmark wrapper exposes `[data-intro-logo]` as the opening's flight destination. Header is immediately visible on other routes; HomeIntro controls its visibility during the homepage opening without changing its measured position. Navigation contains Ecosystem, Blog (News/Releases), Docs (Guide/Tutorials/API/Runtime), GitHub, and all 13 languages. Desktop dropdowns use native `<details>` with hover, click, ArrowDown, outside-click, and Escape handling. Up to 1000px wide, a `<details>` mobile menu replaces desktop navigation. Locale links preserve query/hash. Theme buttons use translated `theme.toggle`, sync `aria-pressed`, persist `evox-theme`, and respond to storage events.
- **HomeIntro.astro** — `scrollLabel: string`, supplied from translated `hero.scroll`. On desktop widths above 1000px, a fixed full-viewport overlay shows BrandWordmark on an initial top-of-page visit, with a cue linking to `#home`; mobile widths skip the opening. One downward wheel gesture, click/tap anywhere, upward one-finger swipe, or PageDown/ArrowDown/Space/End press starts a 1050ms native Web Animations flight: the actual full logo translates and scales to the upper-left `[data-intro-logo]`, while the curtain and cue fade. Source and destination are measured once and the native scrollbar stays in place. The target remains hidden until handoff. States are `active`, `entering`, and permanently `complete` for the current document; completion hides the overlay without leaving scrollable space. Underlying homepage sections and chrome are temporarily inert; input listeners use an AbortController and are removed on completion. Keyboard entry focuses the hero title. Escape, restored scroll, non-top hash changes, interruption handlers, and a 1.6-second watchdog finish safely. Deep links and restored positions skip the overlay, and returning to `#top` cannot replay it. Reduced motion enters instantly. Without JavaScript, an in-flow opening and visible navigation remain usable.
- **Footer.astro** — `locale?: Locale`. Logo, localized resource links, five social links, and translated copyright. Community targets `/libs#community` in the active locale. An inline script refreshes the copyright year.
- **EvolutionDiagram.astro** — Localized, responsive Canvas 2D illustration of an evolutionary loop. The left column contains the supplied stage labels, localized explanatory copy, and selectable generation, execution, evaluation, selection, and improvement controls. The right column contains a fixed-orientation ring with generated candidates, fitness evaluation, survivor selection, and offspring. Playback, restart, direct stage selection, reduced motion, offscreen and hidden-page suspension are supported. An SVG fallback remains visible until Canvas initialization. The 11-second animation is a deterministic synthetic illustration, not benchmark data; behavior is implemented in `art/evolutionRing.js` and based on the owner's supplied standalone HTML.
- **ParadigmArt.astro** — `kind: "generative" | "agentic" | "physical" | "science"`. Selects a decorative SVG from `art/` and supplies shared theme colors and non-scaling strokes. Each 480×280 illustration uses flat linework, subtle solid fills, and red accents. GenerativeArt shows model matrices merging, with CSS selection pulses and a response in the merged weights. AgenticArt uses `genesisTree.ts`, a deterministic server port of the author's submitted Genesis/Showcase tree generator and cover layout; upstream license is retained in `genesis-tree.LICENSE.txt`. The original generator reserves stable layout coordinates. `agenticLifecycle.ts` describes a separate message lifecycle; `agenticPlayer.ts` incrementally creates SVG nodes and edges when each level is reached. All third-level nodes start in the same pending state. A returned result is parked; another is processed and receives a continuation command before generating the fourth level. The player reconciles only at lifecycle events. Genesis-style CSS breathing, ripple, state transitions and line growth animate natively; SVG animateMotion carries forward and returning messages. The event clock, CSS animations/transitions and SVG motion pause together offscreen or while the document is hidden. No continuous JavaScript frame loop or per-frame path sampling is used. Without JavaScript or with reduced motion, the full static final diagram remains visible. PhysicalArt shows three minimal quadruped training stages: losing balance and falling, maintaining a shaky stance with small corrective steps, and coordinated walking. Each model contains only a torso and four two-segment legs, without joint markers or extra body details. Server-computed poses keep torso and hip connections aligned during CSS path animation; reduced motion preserves a distinct static pose for each stage. ScienceArt uses `science-airfoil-data.ts`, containing real P-51D Mustang root (BL17.5) coordinates and 17 precomputed incompressible potential-flow streamlines. Sixteen streamlines are displayed; the lower line that nearly touches the section is omitted. Fine arrows travel left to right along selected paths and follow their tangents. Fixed arrows, moving thick segments, and the upper-contour accent are omitted. Sources and model limits are in the data module and design document. The other three illustrations use CSS animation without client JavaScript. All four retain flat geometry without gradients, shadows, or perspective. Reduced-motion preferences disable animation and hide moving signal overlays while preserving complete static diagrams.
- **pages/HomeContent.astro** — Homepage with HomeIntro before the hero, Layout's shared chrome, native section anchors, optional scroll reveals, and chapter rail visible after the opening at widths of at least 1280px. See `pages/CONTEXT.md`.
- **pages/EcosystemContent.astro** — Shared `/libs` body: featured Genesis, library cards, and Community with QQ QR modal and Discord.
- **pages/RuntimeContent.astro** — `/runtime` hero followed by RuntimeExamples.
- **pages/RuntimeExamples.astro** — Tabbed code and live Plotly/Brax examples.

## Styling and Behavior
- `src/styles/global.css` owns `--site-*` colors and typography. Default dark uses black/charcoal surfaces with EvoX red; light uses white/pale-gray surfaces. Layout restores the saved theme before paint. Header and homepage wordmarks use theme-aware SVG lettering; Footer's existing word image uses the theme's logo filter. The X mark uses BrandMark's per-path CSS sweep and must never receive a whole-image filter.
- Instrument Sans is self-hosted in Latin and Latin Extended subsets; system fonts cover other scripts. Header and footer links are 12px; copyright is 11px. Shared chrome has a 1216px maximum inner width; the homepage body uses 1040px.
- Older content pages retain Tailwind utilities. `.site-main-padded` rules adapt surfaces, text, borders, prose, and hover states. Keep paired foreground/background states consistent when editing these rules.
- Homepage content remains visible without JavaScript. With JavaScript, the opening is a fixed overlay above the normal homepage and never reserves scrollable height. A single entry gesture starts the full-logo flight to the header; completion removes the overlay and all temporary input guards. Ordinary scrolling and `#top` then reach the normal homepage without replaying the opening. Header fades in during entry, the target wordmark appears at handoff, and the chapter rail appears on completion. Other routes show navigation immediately. Reduced-motion preferences make entry instant and disable reveal motion and smooth scrolling.

## Constraints
- Use `loadTranslations(locale)` and `t()` for interface copy. Product names, social brand labels, and the public QQ group number are intentional literals.
- Use `getLocalizedUrl(path, locale)` for internal links without trailing slashes. External new-tab links require `rel="noopener noreferrer"`.
- Pages without a locale counterpart, such as 404, must pass `localePath` for valid language-menu destinations.
- Astro bundles typed component scripts; Footer's inline year script stays dependency-free. Icons use `astro-icon/components` with Heroicons or Simple Icons.

## Known Issues and Dependencies
- RuntimeContent retains `genesis.hero.github` for its GitHub link. Genesis is external; there is no internal Genesis route.
- RuntimeExamples depends on externally loaded Plotly and a lazy Brax iframe. Preserve readiness guards, resize calls, and fallback behavior.
- Header's legacy `animated` and `sticky` props are compatibility declarations only.
