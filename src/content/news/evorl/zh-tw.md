Physical AI 需要探索不同的行為，透過互動檢驗它們，並將有價值的經驗帶入下一輪學習。EvoRL 將這個迴圈放入並行模擬：個體策略從經驗中學習，種群搜尋探索不同策略與學習配置，使學習和演化之間的關係成為能夠系統研究的實驗問題。

![機械腿模型圍繞共享模擬循環探索不同路徑](./population-learning-loop.webp)

EvoRL 圍繞這些問題建立了一套開源研究框架。它以 JAX 為基礎，將強化學習、演化計算與環境模擬整合至共同的訓練流程，支援經典方法與混合方法的開發及評估。作為 EvoX 的姊妹專案，EvoRL 專注於演化計算與強化學習的結合，讓族群層級的搜尋能運用現代 GPU 的平行運算能力。[專案介紹](https://github.com/EMI-Group/evorl)

## 為什麼要結合演化與強化學習？

以機器人學習行走為例，同一項任務可能有多種有效策略，包含不同步態、速度與穩定性的取捨，以及不同的能源需求。僅沿著一條學習軌跡改進策略，可能無法充分探索這些選擇。

強化學習運用互動資料持續改善策略；演化計算則維護一組候選解，透過評估、選擇與變異保留多個搜尋方向。結合兩者，可研究更豐富的學習過程：個體從經驗中進步，族群則在個體之間傳遞有價值的結果。

演化搜尋可以直接作用於策略參數，也能調整強化學習的超參數。兩者回答不同的問題：前者關注「尋找什麼樣的策略」，後者關注「如何讓策略學得更好」。

這種互補關係不代表混合演算法在每項任務上都優於單獨使用強化學習。它帶來更多可驗證的設計選項，而 EvoRL 希望降低探索這些選項的工程與運算成本。

## 核心設計：讓整個訓練流程適應 GPU

族群方法的吸引力來自多樣性，運算負擔也來自多樣性。每增加一個候選策略，就可能增加一批環境互動、策略評估與參數更新。如果這些階段分別在 CPU 與 GPU 上執行，頻繁的資料傳輸與排程就可能形成瓶頸。

在相容的 GPU 模擬環境下，EvoRL 將環境互動、策略計算、演化操作與學習更新組織成端到端的 GPU 流程。JAX 的向量化與即時編譯能力可批次執行重複計算，並最佳化訓練步驟的計算圖。[技術概覽](https://evorl.readthedocs.io/latest/)

其平行化可分成三個層次：

- **環境平行**：同一策略同時與多個環境實例互動，批次蒐集經驗。
- **個體平行**：同時評估族群中的多個候選策略。
- **訓練平行**：同時推進多個智慧體的學習，支援混合方法與族群訓練。

這套設計讓同時探索更多策略的實驗更容易實現。族群大小仍需考量 GPU 記憶體、環境成本與網路規模。[架構論文](https://arxiv.org/abs/2501.15129)

## 在同一框架中比較四類方法

EvoRL 為不同方法提供共同的實驗基礎，讓研究者先建立基準，再逐步加入搜尋或學習機制。

| 方法類別 | 代表演算法 | 主要研究問題 |
| --- | --- | --- |
| 強化學習 | PPO、TD3、SAC 等 | 如何運用互動資料改善策略？ |
| 演化演算法 | OpenES、ARS、CMA-ES 等 | 如何依候選策略的評估結果進行族群搜尋？ |
| 演化引導的強化學習 | ERL、CEM-RL 及其變體 | 如何讓演化搜尋與梯度學習合作？ |
| 基於族群的自動強化學習 | PBT-PPO、PBT-SAC 等 | 如何在訓練過程中調整學習設定？ |

其中，兩類混合方向尤其值得關注。

**演化引導的強化學習**連結族群搜尋與個體學習。例如，以族群探索策略參數空間的不同區域，再透過強化學習更新改善候選策略。各種演算法對經驗共享、個體更新及族群選擇採用不同安排，EvoRL 提供現成實作以研究這些選擇。

**基於族群的自動強化學習**則搜尋訓練設定。以 PBT 為例，多個個體分別訓練，定期依評估結果繼承較佳個體的訓練狀態，並擾動超參數以繼續探索。因此，超參數能隨訓練過程調整。

可用演算法及變體以目前儲存庫的實作為準。[演算法清單](https://github.com/EMI-Group/evorl#algorithms)

## 模組化：讓研究想法更容易成為實驗

開發混合演算法時，環境調適、資料組織、評估流程與元件介面協調往往相當耗時。EvoRL 透過幾個核心抽象組織這些工作：

- **Env** 提供統一的環境互動介面。
- **Agent** 定義智慧體行為與相關學習邏輯。
- **SampleBatch** 組織軌跡與樣本資料。
- **Workflow** 定義演算法的訓練步驟。
- **EC** 提供演化演算法與相關運算元。

這些模組讓研究者能針對特定環節修改。例如，保留環境與策略網路、替換搜尋方法，或比較加入演化操作前後的學習表現。[框架與 API 文件](https://evorl.readthedocs.io/latest/)

共同實作也有助於控制變因。採用相同任務、評估程序及運算預算，才能更清楚區分演算法改進與實作差異。框架讓比較更方便，嚴謹的實驗設計仍需由研究者完成。

## 效能提升代表什麼？

EvoRL 論文在 Brax 的 Swimmer 環境中，使用配備兩顆 Intel Xeon Gold 6132 CPU、128 GiB 記憶體及一張 RTX 3090 GPU 的機器比較運算效率。在受測設定下，OpenES 相較於 RLlib 的 CPU 分散式實作，最高加速超過 60 倍；CEM-RL 相較於其官方實作，約有 5–9 倍加速。

這些數字反映特定任務、族群大小與基準下的運算效率，不代表每項任務都有相同提升，也不等於達到目標獎勵所需的樣本數同比例減少。[實驗設定與結果](https://arxiv.org/html/2501.15129v1#S5)

規劃實驗時，更高吞吐量讓研究者有機會採用更多隨機種子、更完整的消融實驗，或更大的族群。這是框架加速的實際價值：在可用預算內驗證更多想法。

## 從機器人控制到新的決策任務

EvoRL 支援 Brax 與 MuJoCo Playground 等機器人模擬環境，可用於連續控制、策略搜尋與族群訓練。它也實驗性整合 gymnax、Jumanji、JaxMARL，涵蓋經典控制、遊戲、組合最佳化與多智慧體情境；各設定的演算法相容性需另行確認。框架亦支援部分 CPU 環境，因此能否全程使用 GPU，取決於所選環境與演算法組合。[環境支援說明](https://github.com/EMI-Group/evorl#rl-environments)

研究演化強化學習時，可先以現有演算法建立基準，再調整族群搜尋與策略學習的協作方式。關注 AutoRL 的研究者可從 PBT 開始，觀察訓練設定如何影響學習。開發新最佳化方法時，也能透過共同介面逐步整合自己的元件。

## 開始第一個實驗

目前安裝需求為 Python 3.12 或更新版本，以及 JAX/jaxlib 0.10.0 或更新版本。 [EvoRL](https://github.com/EMI-Group/evorl#installation)

先依[安裝指南](https://evorl.readthedocs.io/latest/guide/installation.html)設定與硬體相符的 JAX 環境，再從原始碼安裝 EvoRL，以取得範例所需的訓練腳本與設定：

```bash
git clone https://github.com/EMI-Group/evorl.git
cd evorl
pip install -e .
```

接著從 Brax 的 Ant 環境與 PPO 基準開始：

```bash
python scripts/train.py agent=ppo env=brax/ant
```

EvoRL 使用 Hydra 管理實驗設定。成功執行基準後，可調整隨機種子、演算法與環境設定，再進行混合方法或族群訓練實驗。完整操作請參閱[快速入門](https://evorl.readthedocs.io/latest/guide/quickstart.html)。

將第一次 PPO 執行保留為基準：修改元件前，保存環境、隨機種子、設定與學習曲線。若希望先從更簡單的種群搜尋入手，可閱讀 [EvoX 工作流程教學](/zh-tw/news/evox-quickstart)。
