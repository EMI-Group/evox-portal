Physical AI では異なる行動を探り、相互作用を通じて試し、有用な経験を次の学習へ引き継ぐ必要があります。EvoRL はこれを並列シミュレーションに取り込みます。個々の方策は経験から学び、集団探索は別の方策や学習設定を調べるため、学習と進化の関係を実験的に研究できます。

EvoRL は、これらの問いに取り組むオープンソースの研究フレームワークです。JAX を基盤に、強化学習、進化計算、環境シミュレーションを共通の学習ワークフローに統合し、従来手法からハイブリッド手法までの開発と評価を支援します。EvoX の姉妹プロジェクトとして進化計算と強化学習の融合に焦点を当て、集団レベルの探索で GPU の並列計算能力を活用します。[プロジェクト紹介](https://github.com/EMI-Group/evorl)

## なぜ進化と強化学習を組み合わせるのか

歩行を学ぶロボットを考えてみましょう。同じ課題にも、歩容、速度と安定性のバランス、消費エネルギーが異なる複数の有効な方策があります。一つの学習経路だけに沿って改善すると、こうした選択肢を十分に探索できない可能性があります。

強化学習は相互作用データから方策を改善します。進化計算は候補の集団を保持し、評価、選択、変異を通じて複数の探索方向を維持します。両者を組み合わせると、個体が経験から学ぶと同時に、集団内で有用な成果を共有する学習過程を研究できます。

進化的探索は方策のパラメータを直接探索することも、強化学習のハイパーパラメータを調整することもできます。前者は「どのような方策を探すか」、後者は「どうすればよりよく学べるか」という問いに対応します。

この相補性は、すべての課題でハイブリッド手法が強化学習単独を上回ることを意味しません。検証可能な設計の選択肢が増えるということであり、EvoRL はその探索に必要な実装と計算の負担を減らすことを目指しています。

## 中心となる設計：学習パイプライン全体を GPU 向けに

集団手法の魅力は多様性ですが、その分だけ計算量も増えます。候補方策が一つ増えるたびに、環境との相互作用、評価、パラメータ更新が追加される可能性があります。これらを CPU と GPU に分けて実行すると、頻繁なデータ転送やスケジューリングがボトルネックになり得ます。

互換性のある GPU シミュレーション環境では、EvoRL は環境との相互作用、方策計算、進化的操作、学習更新を、エンドツーエンドの GPU パイプラインにまとめます。JAX のベクトル化と JIT コンパイルにより、反復計算をまとめて実行し、学習ステップの計算グラフを最適化します。[技術概要](https://evorl.readthedocs.io/latest/)

並列化は三つの階層で行われます。

- **環境の並列化**：一つの方策が複数の環境インスタンスと同時に相互作用し、経験をバッチ収集します。
- **個体の並列化**：集団内の複数の候補方策を同時に評価します。
- **学習の並列化**：複数エージェントの学習を同時に進め、ハイブリッド手法や集団学習を支えます。

これにより、より多くの方策を同時に試す実験が実装しやすくなります。ただし、集団サイズは GPU メモリ、環境の計算コスト、ネットワーク規模を踏まえて決める必要があります。[アーキテクチャ論文](https://arxiv.org/abs/2501.15129)

## 一つのフレームワークで四つの手法群を比較

EvoRL は異なる手法に共通の実験基盤を提供します。まずベースラインを作り、そこに探索や学習の仕組みを追加できます。

| 手法群 | 代表的なアルゴリズム | 主な研究課題 |
| --- | --- | --- |
| 強化学習 | PPO、TD3、SAC など | 相互作用データから方策をどう改善するか |
| 進化的アルゴリズム | OpenES、ARS、CMA-ES など | 候補の評価を集団探索にどう生かすか |
| 進化誘導型強化学習 | ERL、CEM-RL とその派生手法 | 進化的探索と勾配学習をどう連携させるか |
| 集団ベースの AutoRL | PBT-PPO、PBT-SAC など | 学習中に設定をどう適応させるか |

特に注目したいのは、二つのハイブリッドの方向性です。

**進化誘導型強化学習**は、集団探索と個体の学習を結び付けます。集団で方策パラメータ空間の異なる領域を探索し、強化学習による更新で候補を改善できます。経験共有、個体更新、集団の選択方法はアルゴリズムごとに異なり、EvoRL はそれらを調べるための実装を提供します。

**集団ベースの AutoRL**は、学習設定を探索します。例えば PBT では、複数の個体がそれぞれ学習し、定期的な評価に基づいて成績のよい個体の学習状態を継承し、ハイパーパラメータに摂動を加えて探索を続けます。これにより、学習中にもハイパーパラメータを変えられます。

利用可能なアルゴリズムと派生手法は、現在のリポジトリの実装を参照してください。[アルゴリズム一覧](https://github.com/EMI-Group/evorl#algorithms)

## モジュール化で研究の着想を実験へ

ハイブリッド手法の開発では、環境への対応、データの整理、評価手順、コンポーネント間のインターフェース調整に多くの時間がかかります。EvoRL はこれらを少数の主要な抽象化で整理しています。

- **Env**：環境との相互作用に共通インターフェースを提供します。
- **Agent**：エージェントの行動と関連する学習ロジックを定義します。
- **SampleBatch**：軌跡とサンプルデータを整理します。
- **Workflow**：アルゴリズムの学習ステップを定義します。
- **EC**：進化的アルゴリズムと関連演算子を提供します。

研究者は必要な部分だけを変更できます。例えば、環境と方策ネットワークを維持して探索手法を置き換えたり、進化的操作の導入前後で学習の挙動を比較したりできます。[フレームワークと API ドキュメント](https://evorl.readthedocs.io/latest/)

共通実装は条件の統制にも役立ちます。同じ課題、評価手順、計算予算を使うことで、改善がアルゴリズム設計によるものか実装の違いによるものかを見極めやすくなります。フレームワークは比較を容易にしますが、厳密な実験設計は研究者が行う必要があります。

## 高速化の数値は何を意味するのか

EvoRL の論文では、Intel Xeon Gold 6132 CPU 2基、128 GiB RAM、RTX 3090 GPU 1基を搭載したマシンで、Brax の Swimmer 環境の計算効率を比較しています。検証した設定において、OpenES は RLlib の CPU 分散実装に対して最大で 60 倍を超える高速化、CEM-RL は公式実装に対して約 5–9 倍の高速化を達成しました。

これは特定の課題、集団サイズ、比較対象における計算効率です。あらゆる課題で同じ効果が得られるわけではなく、目標報酬に必要なサンプル数が同じ割合で減るという意味でもありません。[実験設定と結果](https://arxiv.org/html/2501.15129v1#S5)

実験計画の面では、スループットの向上により、乱数シードの追加、より充実したアブレーション実験、集団の拡大を検討できます。利用可能な予算内でより多くの着想を検証できることが、研究にとっての実用的な価値です。

## ロボット制御から新しい意思決定課題へ

EvoRL は Brax や MuJoCo Playground などのロボットシミュレーション環境に対応し、連続制御、方策探索、集団学習に利用できます。gymnax、Jumanji、JaxMARL との実験的な統合により、古典制御、ゲーム、組合せ最適化、マルチエージェント環境も対象になります。ただし、各設定でアルゴリズムの互換性確認が必要です。一部の CPU 環境にも対応するため、全処理を GPU 上で実行できるかは環境とアルゴリズムの組合せによります。[対応環境](https://github.com/EMI-Group/evorl#rl-environments)

進化的強化学習の研究では、既存手法でベースラインを作ってから、集団探索と方策学習の連携を変更できます。AutoRL なら PBT から始め、設定が学習に及ぼす影響を調べられます。新しい最適化手法の開発者は、共通インターフェースを通じて独自のコンポーネントを段階的に組み込めます。

## 最初の実験を実行する

まず[インストールガイド](https://evorl.readthedocs.io/latest/guide/installation.html)に従い、ハードウェアに合う JAX 環境を設定してください。続いて EvoRL をソースからインストールし、例で使う学習スクリプトと設定を取得します。

```bash
git clone https://github.com/EMI-Group/evorl.git
cd evorl
pip install -e .
```

Brax の Ant 環境で PPO のベースラインを実行します。

```bash
python scripts/train.py agent=ppo env=brax/ant
```

EvoRL は Hydra で実験設定を管理します。ベースラインが動作したら、乱数シード、アルゴリズム設定、環境設定を変え、ハイブリッド手法や集団学習へ進めます。詳しくは[クイックスタート](https://evorl.readthedocs.io/latest/guide/quickstart.html)を参照してください。

EvoRL は進化と学習の組合せを実践しやすくすることを目指しています。共通の枠組みで問いを立て、手法を組み合わせ、実験を行い、結果から着想を検証できます。[GitHub リポジトリ](https://github.com/EMI-Group/evorl)で既存手法を試し、新たな実装を提供したり、[Discussions](https://github.com/EMI-Group/evorl/discussions)で研究や利用経験を共有したりしてください。
