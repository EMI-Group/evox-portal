[2026년 9월 7일 Evidence 기록](https://genesis.evox.group/evidence/compiler-continuation/)은 수락된 동일 개발 이력에서 **GLM 5.2에서 DeepSeek V4 Flash로** 인계한 사례입니다. 이전 에이전트의 대화 맥락은 전달되지 않았습니다.

![서로 다른 두 설계 작업면을 잇는 연속된 다리](./compiler-model-handoff.webp)

인계받은 모델은 기존 소스, 프로젝트 구조와 수락된 개발 이력을 사용할 수 있었습니다.

## 후속 모델이 보존할 것

컴파일러는 구문 분석, 의미 분석, 중간 표현, 코드 생성을 연결합니다. 작은 수정도 다른 모듈에 영향을 주므로 코드 추가 외에 통합과 회귀 검증이 필요합니다.

jcc 저장소에는 Rust 구현, 명시적 중간 표현, 기능 경계 문서, 테스트 도구가 있습니다. 다만 README는 다른 개발 시점을 설명하므로 인계 실험 기록을 대신할 수 없습니다.

## 보고된 결과

재귀 작업 깊이는 **4에서 8로** 늘었고, 인계 후 **유지된 LLVM SingleSource 1,820/1,820개 사례를 통과**했다고 보고됩니다. LLVM 전체 테스트 모음은 아닙니다. [GW-000002](https://genesis.evox.group/evidence/evidence.json)

깊이는 해당 실행의 작업 분해를 나타내며 품질의 직접 지표가 아닙니다. 동작 증거는 테스트 결과이며, 일반적 신뢰성 주장을 위해서는 다른 과제와 반복 실행이 필요합니다.

## 연속성의 의미

후속 수행자가 검증할 수 있는 코드, 인터페이스, 제약, 수락된 변경, 평가 절차를 보존하는 것이 실용적 교훈입니다. 대화 기억도 도움은 되지만 진척을 담는 유일한 수단일 필요는 없습니다.

## 성과를 축적하는 개발

초기 구축과 인계 기록은 [같은 저장소](https://github.com/EMI-Group/genesis-demo-jcc)를 사용합니다. 독립 프로젝트로 세거나 범위가 다른 테스트 수를 합산하면 안 됩니다. 후속 단계의 추가 코드량과 비용은 보고되지 않았습니다.

유용한 인계 자료는 승인된 리비전과 테스트 목록, 실행 명령, 알려진 제외 항목을 함께 담습니다. 다음 모델에 검증 가능한 작은 변경을 맡긴 뒤 기준선과 비교합니다. [개발 이력 보기](/ko/news/genesis-development-history)는 에이전트가 종료된 후에도 기여를 추적하는 방법을 설명합니다.
