프로그램을 탐색하면 컴파일도 실험 예산에 포함됩니다. 매 세대 그래프 준비가 오래 걸리면 장치 실행만 빨라져서는 부족합니다. 2026년 10월 30일 공개된 [EvoX Compiler v0.1.1][s1]은 준비 경로와 백엔드 실패 사례를 개선합니다. [45개 커밋의 변경][s2]은 v0.1.0의 명시적 그래프 파이프라인을 발전시킵니다.

![서로 다른 프로그램 구조를 간결한 병렬 그룹으로 정리한 모습](./cover.webp)

*개념 삽화: 컴파일 전에 프로그램 개체군을 구성합니다.*

## 프로그램 그룹에도 비용 모델이 필요하다

`batch_functions`는 호환되는 후보 프로그램을 하나의 그래프로 결합합니다. v0.1.1은 내부 클래스 그래프에 행 의존성을 전파하고 `bands="auto"`의 기하급수적 그룹 탐색을 확장합니다. 개별 구성원에 의존하는 계산과 적절한 그룹 구성을 판단하기 위한 변화입니다.

유전 프로그래밍 후보들은 입력 규격을 공유하면서 연산은 다를 수 있습니다. 하나의 평평한 그룹이 항상 가장 저렴한 표현은 아닙니다. 밴드 분할은 다른 구성을 제공하고 자동 정책은 비용 모델로 비교합니다. 핵심 검증은 의미 보존입니다. 결합 결과의 i번째 행은 후보 i를 별도로 실행한 결과와 같아야 합니다. 릴리스는 관련 회귀 테스트도 갱신합니다.

## 그래프 준비의 반복 계산 제거

여러 수정은 장치 실행 전 CPU 작업을 줄입니다. 소스 위치를 직접 프레임 순회로 얻고, lowering의 중복 검증을 없애며, IR 검증에 선형 사용 관계 추적과 결과 타입 추론 메모이제이션을 적용합니다. StableHLO 출력에는 상수 텍스트 일괄 생성, 타입 텍스트 캐시, 테이블 기반 연산 분배가 추가됩니다.

이는 서로 다른 단계의 개선입니다. 출력이 빨라져도 GPU 커널 자체가 빨라졌다는 뜻은 아닙니다. 추적, 변환, lowering, 컴파일, 정상 상태 실행을 나누어 측정하십시오. 상수가 많은 큰 개체군과 수치 커널이 비싼 작은 그래프는 비용 구조가 다릅니다.

## 백엔드 실패를 더 쉽게 진단

IREE 어댑터는 디스패치당 HAL 바인딩 한계를 대응 가능한 `BackendError`로 보고합니다. 자원 한계와 수치 프로그램 오류를 구분하기 쉬워집니다. XLA 어댑터는 `PJRT_Client_Create` 호출 중 공유 클라이언트 잠금을 유지하지 않도록 해 동일 스레드 finalizer의 교착을 수정하고 회귀 테스트를 추가합니다.

지원 범위는 버전별 표를 따릅니다. NumPy는 CPU 인터프리터이며 IREE, XLA, TVM은 의존성과 장치 조건이 다릅니다. 인터프리터 결과를 기준으로 삼은 뒤 컴파일 경로를 확인할 수 있습니다. [버전 README][s3]는 지원 범위와 명시적인 장치 전송을 설명합니다.

## 대표 개체군으로 업그레이드하기

기본 패키지는 `pip install evoxc==0.1.1`, IREE 환경은 `pip install "evoxc[iree]==0.1.1"`로 설치합니다. Python 3.11 이상이 필요합니다. 별도 배포판 `evoxc-hf`는 독립적인 버전 주기를 갖습니다. 기존 백엔드 플러그인 설정도 보존하십시오.

저장한 개체군과 고정 입력으로 결합 출력을 개별 참조 실행과 비교한 뒤 준비와 실행 시간을 나눠 측정합니다. 가속기가 바인딩 오류를 보고하면 실험을 조용히 바꾸지 말고 그래프와 백엔드 정보를 진단용으로 남깁니다. [v0.1.0 소개][related]는 파이프라인을 설명하고, v0.1.1은 준비 단계와 백엔드 경계를 실제로 다루기 쉽게 만듭니다.
