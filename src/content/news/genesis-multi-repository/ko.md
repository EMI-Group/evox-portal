하나의 기능이 API 서비스, 클라이언트 앱, 공용 라이브러리에 걸칠 수 있습니다. 목표는 같아도 Git 저장소는 다를 수 있습니다. 2026년 9월 26일 출시된 Genesis 0.13.4는 쓰기 가능한 연관 저장소에 지속적인 작업 트리를 추가해 저장소 간 작업의 실행 경계를 명확히 했습니다.

![하나의 프로젝트에 연결된 개별 저장소 이력](./companion-worktrees.webp)

## 코드 접근에서 작업 격리로

0.11.4는 추가 저장소 읽기·쓰기, 저장소별 검토, 읽기 전용 저장소의 쓰기 제한을 도입했습니다. 0.13.4에서는 각 연관 저장소의 지속적인 작업 트리에서 에이전트가 작업하므로 주 HEAD나 기본 작업 트리를 건드리지 않습니다. [v0.11.4](https://github.com/EMI-Group/genesis/blob/v0.11.4/CHANGELOG.md)

해당 저장소의 경로는 작업 트리를 기준으로 해석합니다. 초기 컨텍스트가 그 위치를 보여 주며 저장소 간 위임도 이를 기준으로 합니다. 저장소의 디렉터리 구조가 다르거나 다른 개발 활동이 진행되어도 변경 위치가 명확합니다. [v0.13.4](https://github.com/EMI-Group/genesis/releases/tag/v0.13.4)

## 통합 결정은 저장소별로 유지됩니다

0.13.0은 개별 병합·거부 버튼, 병합 검사와 처리 상태를 갖춘 검토 카드를 도입했습니다. 전체 병합 기능은 미처리 저장소를 함께 수락하면서도 개별 결과를 보여 줍니다. 연관 저장소만 바뀐 작업의 검토 흐름도 수정했습니다. [v0.13.0](https://github.com/EMI-Group/genesis/releases/tag/v0.13.0)

API 변경은 서비스, 클라이언트와 공유 라이브러리의 각 이력에서 검토합니다. 인터페이스 버전과 통합 순서를 정하고 결합된 결과를 검사하세요.

## 저장소 간 검토 준비하기

위임 전에 저장소별 쓰기 가능한 워크트리를 확인하고, 완료 후에는 검토 카드에서 변경, 병합 검사와 처리 상태를 살펴보세요. 여러 프로젝트의 작업을 구체적인 수용 결정으로 연결할 수 있습니다. [개발 이력 보기](/ko/news/genesis-development-history)에서 관련 커밋을 추적할 수 있습니다.
